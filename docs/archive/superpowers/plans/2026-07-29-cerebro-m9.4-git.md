# Cerebro M9.4 — Git Tracking

> **Status: DRAFT.** Largest M9 milestone. Full port of tolaria's git subsystem, adapted to cerebro's vault model.

**Goal:** The vault is a git repository. Every note has a history, every change has a diff, the assistant's edits are reviewable and revertible, and a remote can be connected, pulled, pushed, and conflict-resolved without leaving the app.

**Why:** Beyond backup — cerebro runs a background distiller ([useLearnRunner](../../../src/agent/useLearnRunner.ts)) that writes to `knowledge/` whether or not the AI panel is open. M8 gave that loop a review surface for *concepts*; git gives it one for *files*. "The base edited 14 notes overnight" becomes a diff you can read and revert.

**Scope decision (user, 2026-07-29):** everything tolaria has. Remotes, push/pull, conflict resolution, provider probing, clone, GitHub file URLs.

### Two pieces worth calling out before writing any code

**`workspace.rs` is not optional.** The vault directory is frequently *not* the git root — a vault inside a larger repo, or a repo whose root is a parent directory. `GitWorkspaceInfo` resolves `{vaultRoot, gitRoot, vaultPathspec, gitRootRelation: 'vault'|'parent'|'none', resolutionFailure}` and every other call scopes its pathspec through it. Skipping this produces an app that works on the developer's machine and silently reports the wrong files on anyone else's. Port it first.

**`credentials.rs` prevents a hang, not an error.** `git pull` against an auth-required remote with no credential helper blocks forever waiting on a terminal prompt that does not exist in a GUI app. Tolaria sets `GIT_TERMINAL_PROMPT=0` and a no-op `GIT_ASKPASS`, then classifies the resulting failure ([`classify_push_error`](../../tolaria-main/src-tauri/src/git/remote.rs)) into `auth_error | network_error | rejected`. Port both halves together — the suppression without the classification turns a hang into an unexplained failure.

## Cerebro adaptations

**Drop the WSL provider.** `provider.rs` probes native git and every WSL distribution because tolaria ships on Windows. Cerebro is macOS-only today (`scripts/mac-package.sh`, a signed `.app` + DMG). Port `provider.rs` as a **native-only probe** that keeps the `GitProviderStatus` shape — `wsl_distributions: []` — so adding Windows later is filling in a branch rather than reshaping the API. Do not port `wsl.rs`-adjacent code paths.

**`dates.rs` feeds the existing scanner.** `Entry.createdAt` / `modifiedAt` currently come from filesystem metadata in `src-tauri/src/vault/`. Filesystem mtime is wrong after a clone or a checkout — every file looks touched at once. `get_all_file_dates` returns real authorship dates from `git log --diff-filter=A` and the latest commit per path. Wire it as an *override* applied during scan when the vault is a repo, falling back to filesystem dates for untracked files.

**`ensure_gitignore` must know cerebro's layout.** Tolaria's default ignores its own sidecar files. Cerebro's equivalent: `.DS_Store`, plus nothing else by default — `views/*.yml`, `types/*.md`, and `knowledge/` are all content the user wants versioned. Explicitly *do not* ignore `knowledge/`; the whole review argument depends on the assistant's writes being tracked.

**Vault switching invalidates everything.** Cerebro's `vaultStore.openVault` swaps the whole corpus. Every git hook must key its cache on `vaultPath` and reset on change, and `git_workspace_info` must be re-resolved — the new vault may not be a repo at all.

## UI surfaces

**History in the detail panel.** Port [`GitHistoryPanel.tsx`](../../tolaria-main/src/components/inspector/GitHistoryPanel.tsx) (43 lines, lifts cleanly) into [DetailPanel](../../../src/detail/DetailPanel.tsx) and [DocPage](../../../src/pages/DocPage.tsx). Commit list, relative dates, click for the diff at that commit.

**Diff viewer.** New `src/components/DiffView.tsx` — unified diff with syntax-neutral +/− gutters. Tolaria renders diffs inline in its inspector; cerebro shows them in a `Dialog` since the detail panel is narrower. Needed by three callers: file history, the changes surface, and M9.5's agent-edit review.

**Changes surface.** A rail entry listing `get_modified_files` with per-file stats, discard, and a commit box. This is the `SidebarFilter: 'changes' | 'pulse'` pattern from tolaria's sidebar, expressed as cerebro rail destinations. Two selections to add to `Selection`: `{kind: 'changes'}` and `{kind: 'pulse'}`.

**Pulse.** `get_vault_pulse` returns commits with per-file add/modify/delete counts — a readable activity log of what changed in the vault and when. This is the surface that makes the assistant's overnight work legible, so it earns its place under the "no non-functional chrome" rule.

**Status bar / topbar badge.** Sync state, ahead/behind counts, last commit short hash linking to GitHub via `git_file_url`. Model on [`StatusBarBadges.tsx`](../../tolaria-main/src/components/status-bar/StatusBarBadges.tsx). Cerebro has no status bar — put it in [Topbar](../../../src/app/Topbar.tsx), right-aligned.

**Settings.** Port [`GitSettingsSection`](../../tolaria-main/src/components/GitSettingsSection.tsx), [`GitProviderSettingsRows`](../../tolaria-main/src/components/GitProviderSettingsRows.tsx), [`GitRepositorySelect`](../../tolaria-main/src/components/GitRepositorySelect.tsx), [`GitRequiredModal`](../../tolaria-main/src/components/GitRequiredModal.tsx) into [SettingsPage](../../../src/pages/SettingsPage.tsx): enable/disable, init, remote URL, author identity, auto-checkpoint thresholds.

**Conflict resolution.** Files in conflict, merge-vs-rebase mode, per-file "keep ours / keep theirs", then the resolution commit. Lowest-frequency surface; build it last but do build it — a half-ported git that can pull into a conflict and not resolve it leaves the user stuck in a state the app created.

## Auto-checkpoint

Port [`useAutoGit.ts`](../../tolaria-main/src/hooks/useAutoGit.ts) — idle and inactive thresholds, `document.visibilityState` + `hasFocus` gating, eligibility on `hasPendingChanges && !hasUnsavedChanges`. Plus [`autoGitWork.ts`](../../tolaria-main/src/utils/autoGitWork.ts) for the commit-message generation.

**One cerebro-specific trigger:** checkpoint after a `vault_changed` UI action from the agent ([types.ts:79](../../../src/agent/types.ts#L79)). An assistant turn that wrote files gets its own commit, separate from the user's edits, with a message naming the turn. That is what makes the agent's work independently revertible rather than tangled into the next idle checkpoint.

## Sequencing within M9.4

1. `workspace.rs` + `mod.rs` + `command.rs` + `credentials.rs` + `author.rs` — the foundation. Nothing works without correct root resolution and prompt suppression.
2. `status.rs` + `history.rs` + `commit.rs` + `dates.rs` — local read/write. Ship the History panel and Changes surface here; this is already a useful app.
3. `pulse.rs` + `file_url.rs` — the activity surface.
4. `remote_status.rs` + `remote.rs` + `upstream.rs` + `remote_url.rs` + `remote_config.rs` — push/pull.
5. `connect.rs` + `clone.rs` + `provider.rs` — setup flows.
6. `conflict.rs` — resolution.
7. `useAutoGit` + agent-turn checkpoints.

Each stage is independently shippable. If M9.4 runs long, stages 1–3 alone deliver the reviewability argument.

## Acceptance criteria

1. Opening a non-repo vault offers "Enable history"; accepting runs `init_repo` + `ensure_gitignore` and produces an initial commit.
2. A vault nested inside a larger repo reports `gitRootRelation: 'parent'` and scopes every operation to the vault pathspec.
3. A note's detail panel lists its commits; clicking one shows the diff at that commit.
4. The Changes surface lists modified files with stats, discards individual files, and commits with a message.
5. Pulse lists commits with per-file add/modify/delete counts.
6. Connecting a remote, pushing, and pulling all work; an auth failure reports `auth_error` rather than hanging.
7. Pulling into a conflict lists the conflicted files, offers ours/theirs, and commits the resolution.
8. Idle for the configured threshold with pending changes produces a checkpoint commit.
9. An assistant turn that writes files produces its own commit naming the turn.
10. `git_enabled: false` builds and runs with every git surface hidden and no command errors.
11. `mockIpc` covers every new command; the vitest suite passes without a real repo.
