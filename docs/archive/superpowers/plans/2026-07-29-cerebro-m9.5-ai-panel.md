# Cerebro M9.5 — AI Panel

> **Status: DRAFT.** Independent of the view work. Wants M9.4's diff plumbing for the review flow; degrades without it.

**Goal:** The assistant panel shows what it did in enough detail to trust or reject, remembers conversations, lets you point it at specific notes, and knows more about where you are than a single line of prose.

**Why:** The current panel ([AiPanel.tsx](../../../src/agent/AiPanel.tsx), 327 lines) is a single ephemeral thread with a plain textarea, a one-line context hint, and a 20px chip per tool call. The agent has write access to the vault; the panel's job is to make that legible, and a chip that says `create note · knowledge/x.md` does not.

## 1. Action cards

Replace `ToolChip` with `AiActionCard`. Port the structure from the reference; substitute cerebro's tool vocabulary.

```ts
interface ActionCardProps {
  tool: string;          // 'mcp__cerebro__write_concept' → stripped for display
  status: 'pending' | 'done' | 'error';
  input: string | null;
  output: string | null;
  expanded: boolean;
  onToggle: () => void;
  onOpenPath: (path: string) => void;
}
```

Icon map covers both vocabularies — the native CLI tools (`Bash`, `Read`, `Write`, `Edit`, `Glob`, `Grep`) and cerebro's MCP tools from [mcp.rs:360-371](../../../src-tauri/src/mcp.rs#L360-L371): `get_vault_context`, `search_notes`, `get_note`, `list_inbox`, `create_note`, `update_frontmatter`, `append_to_note`, `write_concept`, `cache_source`, `propose_organize`, `open_note`, `navigate`.

**Write tools render differently from read tools.** A `search_notes` card collapsed to one line is fine. A `write_concept` or `update_frontmatter` card should show the affected path unexpanded, because that is the thing you might want to undo. `isWriteTool` already exists in [useAgentChat.ts](../../../src/agent/useAgentChat.ts) — reuse it rather than duplicating the list.

**With M9.4:** write cards get a "View diff" action calling `get_file_diff_at_commit` against the turn's checkpoint commit, and a "Revert this file" action. This is the payoff for doing git first — the assistant's edits become reviewable at the granularity it made them.

**Requires an event-model change.** Tool *output* is not currently plumbed: [types.ts:12](../../../src/agent/types.ts#L12) has `ToolDone { tool_id }` with no result payload. Add `ToolDone { tool_id, output?: string | null, error?: string | null }` in `src-tauri/src/agent.rs` and thread it into `ToolCall`. Without this the cards expand to nothing.

## 2. Conversations

```ts
interface Conversation {
  id: string;
  title: string;
  usesDefaultTitle: boolean;   // false once the user renames it
  sessionId: string | null;    // the CLI session to resume
  messages: ChatMessage[];
  createdAt: string;
  archived: boolean;
}
```

Persisted in `app_config` (which already stores vault path and agent settings via [app_config.rs](../../../src-tauri/src/app_config.rs)), **not** in the vault. A conversation is a tool transcript, not a note; writing it into the vault would put it in the corpus the base distills from, which is exactly the feedback loop M8 was designed to avoid.

Auto-title after the first exchange from the first user message, truncated — port [`aiConversationTitle.ts`](../../tolaria-main/src/utils/aiConversationTitle.ts)'s approach but generate locally rather than spending an agent turn on it. `usesDefaultTitle` flips to `false` on manual rename so auto-titling never overwrites a user's name.

Panel header gains a conversation switcher. `chat.reset` becomes "New conversation" and archives rather than destroys. `sessionRef` in [useAgentChat](../../../src/agent/useAgentChat.ts) moves into the conversation record — the resume-session guard at lines 55-59 already reasons about session ownership carefully and must keep doing so per conversation.

## 3. Wikilink input

Replace the textarea with a contenteditable supporting `[[` autocomplete over `useVaultStore().entries`. Cerebro already has this component — the editor's [chips.tsx](../../../src/editor/chips.tsx) and the BlockNote wikilink handling. Extract the completion menu rather than porting tolaria's `InlineWikilinkInput`.

Referenced notes are collected on send and passed as explicit context, so `[[LNC-14]]` in a prompt means the agent receives that note's content, not just its name.

## 4. Structured context

Replace the one-line hint with a JSON snapshot appended to the system prompt, following [`buildContextSnapshot`](../../tolaria-main/src/utils/ai-context.ts):

```jsonc
{
  "selection":     { "kind": "view", "id": "at-risk-work", "name": "At risk" },
  "activeNote":    { "path": "...", "title": "...", "type": "...", "properties": {}, "body": "…" },
  "linkedNotes":   [ { "path": "...", "title": "...", "type": "..." } ],
  "visibleRecords":[ { "path": "...", "title": "...", "status": "..." } ],   // capped
  "vault":         { "types": [...], "projectCount": n, "noteCount": n },
  "referencedNotes": [ … ]   // from [[wikilinks]] in the prompt
}
```

`visibleRecords` is the cerebro-specific addition and the most valuable one: when you ask "what is at risk", the agent should see the rows you are looking at rather than re-deriving the query. Cap it (tolaria caps its note list at a constant and emits a `truncated` marker — do the same) and include the view's filters alongside, so the agent knows the list is a filtered subset rather than the whole type.

Keep the existing prose rules from [`buildSystemPrompt`](../../../src/agent/AiPanel.tsx#L272) — the OKF instructions, the `verified`-is-the-user's-stamp rule, the `propose_organize` rule. Those encode M8 decisions and are not up for renegotiation; the snapshot goes *after* them.

## Acceptance criteria

1. A turn that writes files shows an expandable card per write with the path visible collapsed.
2. Expanding a card shows the tool's input and output.
3. With M9.4 present, a write card offers "View diff" and "Revert".
4. Starting a new conversation preserves the previous one in the switcher, auto-titled.
5. Renaming a conversation survives an app restart.
6. `[[` in the input completes against vault notes; the referenced note's content reaches the agent.
7. Asking "what is at risk" from the At risk view returns an answer grounded in the visible rows.
8. Reasoning is still not rendered as prose.
9. `mockAgent` covers tool output; existing agent tests pass.
