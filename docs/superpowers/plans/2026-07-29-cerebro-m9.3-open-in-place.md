# Cerebro M9.3 — Open In Place

> **Status: DRAFT.** Small, contained, no dependencies. Lands first.

**Goal:** Clicking a record inside a collection opens it without moving you off the collection. Navigating to the record's project becomes an explicit action in the detail panel.

**Why:** Opening a row in the "At risk" view throws you onto a project page. The view you were reading is gone and getting back costs a Back press.

---

## Root cause

[TableView.tsx:127](../../../src/views/TableView.tsx#L127) routes row clicks through `useOpenPath`. [useOpenPath.ts:22-32](../../../src/app/useOpenPath.ts#L22-L32) contains:

```ts
if (entry?.type === 'Work item') {
  const onProject = entry.project !== null
    && selection.kind === 'project'
    && selection.path === entry.project;
  if (entry.project !== null && !onProject) {
    navigate({ kind: 'project', path: entry.project });
  }
  openDetail(path);
  return;
}
```

The guard only suppresses navigation when you are *already on that record's project page*. Standing in a saved view is not "on the project", so every row click navigates. `at-risk-work.yml` is `type: table` over `Work item`, so this fires on every row.

The behavior is also inconsistent between layouts of the same view: [ListView.tsx:124](../../../src/views/ListView.tsx#L124) and [BoardView.tsx:88](../../../src/views/BoardView.tsx#L88) call `openDetail` directly and stay put. [TreeView.tsx:216](../../../src/views/TreeView.tsx#L216) uses `useOpenPath` and jumps. Switching a view from Table to List silently changes what clicking a row does.

## Why the rule existed

`useOpenPath` is documented as "the one open-by-kind rule" for trees, recents, and QuickOpen — surfaces with **no surrounding context**. Opening a work item from QuickOpen with no canvas behind it left the detail panel floating over whatever you happened to be looking at, so it navigated to give the panel a backdrop.

That reasoning is correct for context-free surfaces and wrong for collections. A collection *is* the backdrop.

## Change

**Split the two intents.**

```ts
// app/useOpenPath.ts
export type OpenMode = 'navigate' | 'in-place';

export function useOpenPath(mode: OpenMode = 'navigate'): (path: string) => void
```

- `'navigate'` — today's behavior, unchanged. Default, so no caller changes meaning by accident.
- `'in-place'` — `Project` records still navigate (a project *is* a page, there is nothing to show in a panel); everything else calls `openDetail` only.

Callers that switch to `'in-place'`: [TableView](../../../src/views/TableView.tsx), [TreeView](../../../src/views/TreeView.tsx). Callers that stay `'navigate'`: [Sidebar](../../../src/app/Sidebar.tsx), [HomePage](../../../src/pages/HomePage.tsx), [DocsPage](../../../src/pages/DocsPage.tsx), [QuickOpen](../../../src/app/QuickOpen.tsx), [editor/chips](../../../src/editor/chips.tsx), [AgentActions](../../../src/agent/AgentActions.tsx), [AiPanel](../../../src/agent/AiPanel.tsx), [EntityDossier](../../../src/knowledge/EntityDossier.tsx), [DocSidePanel](../../../src/detail/DocSidePanel.tsx), [KnowledgePage](../../../src/pages/KnowledgePage.tsx).

ListView and BoardView already behave as `'in-place'` by calling `openDetail`; route them through the hook too so all four layouts share one implementation and cannot drift again.

**Add the explicit escape hatch to the detail panel.** [DetailPanel.tsx](../../../src/detail/DetailPanel.tsx) header gains a breadcrumb when `entry.project !== null` and the current selection is not that project: the project's icon and title, clickable, navigating to `{kind: 'project', path}`. This is the affordance the implicit navigation was standing in for — now it is a thing you press rather than a thing that happens to you.

**Deep-link case.** `AgentActions`' `open_note` and `navigate` UI actions keep `'navigate'`: when the assistant says "look at LNC-14", there may be no relevant canvas behind it.

## Acceptance criteria

1. Opening the "At risk" view and clicking any row opens the detail panel and leaves the view on screen.
2. The same is true in every layout — table, list, board, hierarchy.
3. The detail panel shows a clickable project breadcrumb for records that belong to one.
4. QuickOpen, Home recents, and the file tree still navigate to the project as they do today.
5. Clicking a `Project` record in any layout still opens its page.
6. New test in `TableView.test.tsx`: clicking a row from a view selection does not call `navigate`.
