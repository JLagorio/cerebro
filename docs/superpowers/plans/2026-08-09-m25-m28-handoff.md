## What M25.1 and M25.2 built (do not re-derive)

### M25.1 — `c76f677`

- `src-tauri/src/runtime/schema.rs` — the whole `user_version = 3` DDL as an
  executable contract: closed enums are `CHECK`s, counts are `>= 0`, hashes
  are shape-checked, times are checked for the `…Z` spelling. Two constraints
  are behaviour: an ambient run must name a vault, and a `claimed` item must
  carry a lease.
- `runtime/mod.rs` — migrations are a numbered list, each one `BEGIN
  IMMEDIATE` → DDL → **validation inside the transaction** → version stamp →
  commit. Failure rolls back, names the version, pauses ambient. Corruption is
  quarantined to `runtime.db.corrupt-<stamp>`, never overwritten; an
  `runtime.db.open` marker file distinguishes clean from unclean shutdown
  (`quick_check` vs `integrity_check`). `open_existing()` is the hot-path
  connect that refuses to migrate.
- `runtime/scope.rs` — **`vault_id` is derived from the canonicalized path AND
  recorded** in `vault_registry`. Derived so a deleted database re-derives the
  same ids and rebuilt rows rejoin their vault. Moving a vault folder mints a
  new `vault_id`; that is correct for the local questions it answers, and
  `store_uuid` carries portable identity.
- `runtime/normalize.rs` — the normalized snapshot. **No timestamp is in it,
  by construction**; that is the whole point (a `git checkout` rewrites every
  mtime and changes no content). `NORMALIZER_VERSION = "vault-entry-v1"`.
- `runtime/scheduler.rs` — row storage + the seven states. `put`,
  `counts_by_state`, `keys_in_state`, `get`, `move_state`.
- `runtime/import.rs` — the one-shot upgrade. Imports the three ledgers that
  were actually durable (`cerebro.learnAttempts` / `.skillRuns` /
  `.triggerRuns`) and HOLDS everything it cannot prove as `baseline_held`.
  Consults mtime exactly once, deliberately, in the one place the legacy
  evidence is keyed on it. Rows and the completion marker commit together.
- `runtime/recovery.rs` — the conservative recovery planner.
  `receipts_in_ledger()` is the **M25.3 seam** and returns empty; the planner
  it drives is complete and tested against injected receipts.
- `runtime/status.rs` — process-level `Ready | MigrationFailed | Recovering`.
  Has a `test_lock()` because it is global; any test that asserts on it must
  take the lock or it will pass alone and fail in the suite.

### M25.2 — `7f1dfea`

- `agent/usage.rs` — parses the four disjoint counts off recorded fixtures in
  `src-tauri/fixtures/cli-stream/`. Unknown wire fields → one
  `operational_log` row per run. `KNOWN_UNCOUNTED` is the deliberately-ignored
  list, kept separate so the log does not fill with the same two lines.
- `agent/meter.rs` — the reader thread tallies and writes straight to the
  runtime DB. **Usage never travels on the UI event channel.** Also holds the
  elapsed watchdog.
- `shared/runtime/budget-defaults.v1.json` + `.sha256` — compiled in,
  digest-pinned. Regenerate with
  `cargo test --lib runtime::budget::tests::write_defaults_digest -- --ignored`.
- `runtime/budget.rs` — immutable settings versions (every edit appends, even
  a revert), local-day windows via `chrono-tz` (honest 23/25-hour DST days, a
  skipped midnight starts at the first minute that exists), `budget_days` rows
  that COPY their ceilings, and the gate. **Degradation is one formula**: each
  lane's shed threshold is interpolated from its registry priority (lowest
  sheds at `warning_ppm`, highest at the ceiling), and the refusal names the
  dimension that is filling rather than an opaque "degraded".
- `runtime/dispatch.rs` — `claim()` is gate + reservation + scheduler claim +
  run row + singleton lease in ONE `BEGIN IMMEDIATE`; spawn after commit.
  `finalize()` is the second transaction. Missing usage is `unknown`, never
  zero, and pauses ambient. `recover_expired_leases()` is the crash path.
  Kill-point tests cover every boundary.

## Working rules for a fresh context

- **Verify before you claim.** Run the gate; quote the counts. The last known
  green numbers are recorded in each phase's commit message.
- **The schema is the tripwire.** Two real ordering bugs in M25 were caught by
  foreign keys and CHECK constraints, not by tests. If SQLite refuses
  something, read it as a design answer before reaching for `PRAGMA`.
- **Never mirror a rule.** If a rule needs to exist in Rust and TS, it belongs
  in a shared artifact with a digest, or in the conformance vectors.
- **Held is a real answer.** Whenever the honest options are "assume consumed"
  or "assume pending", the third answer — hold it and ask the owner once — is
  the one this milestone keeps choosing. Follow it.
