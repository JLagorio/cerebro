probe agents' findings against the verifiers' records **in different orders**.

those sections wrong**. The full corrected mapping is now at the top of the

## 2. What is fixed, by mechanism

Nine commits, each one mechanism. The commit messages carry the measurements;
this is the index.

**`7fa27fe` — the keys and the chrome a diagram surface owns.** Eleven
findings, two mechanisms. Nothing inside a mermaid surface ever holds focus, so
every React `onKeyDown` carrying a gesture was on an element the keystroke
never passed through: Escape never exited the block's visual editor, Backspace
reached ProseMirror and took the whole diagram out of the document, and ⌘Z
after `+ Node` was a no-op because focus sat on the button that made the edit.
The editor claims Delete/Backspace/Escape at the **window**, in capture, so it
can stop the key before a host answers it — moving focus around could not have
done that, and measurement said so. Plus: the block routes ⌘Z to the document's
history explicitly, flushes an uncommitted source draft on unmount, both source
boxes stop only what the surrounding editor claims (a blanket stop killed the
app's own ⌘K), and double-click opens the editor.

The second mechanism: M29.51 made the overlays counter-scale but baked their
screen constants into the stored coordinate, which fixes them to the scale in
force at that instant. The drift is exactly `k·(s − s₀)`. The constants ride in
the transform now. Three affordances M29.51 never reached — the selection ring,
the connect handle, the editor's own focus ring — and the background click and
connect drop moved to the **viewport**, which is what a user reads as "the
canvas" (the editor's own box is 25.1% of it at rest, 6.7% at 39% zoom).

**`d28fc13` — a canvas that says what is wrong.** Every parse-error banner
printed the line number twice and dropped the clause that says what broke;
`summarizeRenderError` keeps it, condenses a 670-character grammar dump to the
token that failed, and answers an empty file with a sentence about the file.
A syntax error made in **visual** mode reported nothing at all. The code panel
buried the zoom cluster. Fit centred a quarter of the diagram under that panel.
The percentage chip threw the pan away. Auto-update OFF was reading as a
shredder.

**`72f2b58` — an export that carries the picture.** PNG export failed for
every diagram type mermaid draws with HTML labels, flowcharts included, because
a `<foreignObject>` taints the canvas: labels become real SVG `<text>` for the
raster path. Exports carry the app's own background now (73.4% of a dark-theme
PNG was transparent). Export falls back to the last-good svg instead of
refusing while a valid picture is on screen. And a copy crossing a mermaid
block carries the fence rather than the block's button labels.

**`95d5a1e` — a viewer that fits, stays put, and does not eat the document.**
One keystroke in the lightbox deleted the whole block. The readout lied and
there was no Fit. Wheel zoom ran away from the pointer; the pan was unclamped.
And a latent one it uncovered: the injected svg took an inline innerHTML prop
object, which React re-applies on **identity** — one pan frame would have
restored every stripped link target.

**`2f57da1` — a drag that moves the node, not the diagram.** The whiteboard's
primary gesture. `growViewBox` reports the screen-pixel shift its origin move
causes and the canvas cancels it with a pan; the geometry was never wrong.
Also: a viewport that changes size keeps its centre (opening a record panel left
0 of 2 nodes on screen), Escape closes the panel a record chip opened, and the
delete-view dialog stops claiming to remove a drawing it leaves on disk.

**`c058d4d` — chrome that fits its window, files with no debris, ELK
subgraphs.** Toolbars scroll instead of running off the page. The block's own
chrome wraps instead of painting 147px outside its card at the app's minimum
window. Appends keep the file's trailing newline; removing the layout override
takes the mapping it emptied. Under ELK a subgraph could never be opened at all
— the renderer names the cluster group `"[object Object]"` — so the binding
falls back to document order. Plus one text size per document, focus rings on
the hand-rolled buttons, and a selection ring with its own token.

**`5261647` — the visual editor is reachable without a mouse.** The full tab
ring of the diagram page was 29 stops and not one was inside the drawing. Nodes
are named buttons under a roving tabindex; focus selects, the arrows walk,
Enter renames, Delete works because there is finally a selection to read.

**`5c3ba95`** — two regressions the e2e suite caught from the two commits
before it. **`69bdbfa`** — Quick Open closing two layers on one Escape, the
code panel answering Escape with its own dismissal, the rename box and group
title no longer eating ⌘K, and full screen reachable from a block being edited.

## 3. What is left — one finding, and it is not ours

The eight that survived the first sweep were driven again after being fixed.
Seven are closed with a measurement on each side of the change; the eighth is
the document's markdown round-trip, which M29 triggers but does not own.

| Fixed after the sweep | Before → after, measured in Chromium |
|---|---|
| A popover stays put while its node moves | node moved (−358, −214) and the palette (0, +2.4) → the palette tracks to the pixel, −357.97 against −357.97, and is still free to flip sides and clamp to the viewport |
| The record picker marks nothing | 25 options / 0 marked / no aria-activedescendant → one marked row, an aria-activedescendant, wrap-around arrows. The real cause was a layer down: `autoFocus` fires when React inserts the element, and a Popover is `visibility: hidden` until it has measured itself, so the search box never had focus at all. jsdom ignores visibility when deciding what is focusable, which is why three unit tests said otherwise |
| Focus lands in the document body on close | activeElement was the ProseMirror root → the trigger button, from both the X and Escape |
| Exports name a font they do not carry | 0 `@font-face` in 14,890 chars → 1, with a live data URI, 274,162 chars |
| The link badge destroys the dialog | dialog 1 → 0 with no close → the dialog closes deliberately, then navigates to the same place |
| The toolbar owns the next node's centre at 39% | elementFromPoint returned `mermaid-node-toolbar` → the node itself, through its own label |
| A chip repeats the label and swallows a drag | chip "Rack layout sign-offDone" vs node "Rack layout sign-off", drag moved 0px → chip "Done", drag moves the node 320px, and the click still opens the record |

## 4. Conventions this wave held to

- Commits are `type(scope): sentence (M29.53)`. Next number is **M29.54**.
- Every fix carries its measurement in a comment at the site, in the tense the
  rest of this codebase uses: what was measured, what it was, what it is now.
- Every geometry fix has a test that can fail. jsdom reports 0×0 for every
  rect, so the new `with measurable rects` describes stub
  `getBoundingClientRect` — and the counter-scale, fit, clamp and pan-cancel
  cases were each run against the unfixed code first to watch them fail.
- `keys.ts` is the one place that decides which keystrokes the surrounding
  editor claims. It is expressed as what the EDITOR takes, not as a copy of
  App.tsx's shortcut list, so a new global shortcut works inside a source box
  the day it is added.
- The e2e suite caught two regressions this wave that 3100 unit tests did not.
  Run it (`PORT=5273 pnpm e2e` — check the port is free first).
