# M34.1 "Make agents real" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the three remaining gaps that keep a second agent from genuinely being a second agent: the bearer grant ignores the record's `allowed-tools:`, every agent's system prompt claims it maintains `knowledge/`, and unattended instructions ride the user message.

**Architecture:** Four phases, one commit each, on a branch off `m33a-knowledge-tab` (green at `1e97866`, includes M33b). No new MCP tool, no schema migration, no demo-vault edit, no rail/Docs/Selection change — zero e2e impact by construction. M34.1.5 (chat with a named agent) was delivered by M33b.6 (`d841901`); Task 5 verifies the grant composes with it.

**Tech Stack:** Rust (Tauri 2) + React 19/TS. Gate per commit: `pnpm lint && pnpm typecheck && pnpm test:run`; Rust tasks add `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` (run from `src-tauri/`).

### Task 1: The grant stops lying (M34.1.1)

The renderer already sends `allowed_tools` on every run request (`src/agent/agentIpc.ts:164`), and Rust already narrows **argv** with it (`agent/mod.rs` `narrow`) and enforces grant-level tool allowlists (`mcp.rs:1279` via `ungranted_tool_refusal:1188`). But `run_agent` mints every grant with `tools: None` — unrestricted — so the enforcement never sees the record's list. `mcp.rs`'s own doc says "argv is advice, the grant is the boundary." Make that true.

**Files:**
- Modify: `src-tauri/src/lib.rs:1078-1087`
- Test: same file, `#[cfg(test)]` module (add one near the bottom of `lib.rs` if none exists at module scope; `grep -n "mod tests" src-tauri/src/lib.rs` first and reuse it if present)

- [ ] **Step 1: Write the failing test**

Extract the passthrough as a tiny pure fn so it is testable without Tauri. In `lib.rs`, add near `run_agent`:

```rust
/// M34.1.1: the tools half of the grant, taken from the REQUEST like the
/// scope half always was. `None` is unrestricted (the panel's own turns: a
/// person is watching them and no record narrowed them); `Some([])` is
/// narrowed to nothing (the editor popovers say exactly that). The CLI never
/// sees this and therefore cannot argue with it.
fn grant_tools(request: &agent::AgentRequest) -> Option<Vec<String>> {
    request.allowed_tools.clone()
}
```

And the test (in the existing `#[cfg(test)]` module, or a new one):

```rust

    let mut req = agent::AgentRequest::default();
    assert_eq!(grant_tools(&req), None, "absent stays unrestricted");

    assert_eq!(grant_tools(&req), Some(vec![]), "narrowed-to-nothing stays nothing");
    req.allowed_tools = Some(vec!["get_note".into()]);
    assert_eq!(grant_tools(&req), Some(vec!["get_note".into()]));
}
```

If `AgentRequest` does not derive `Default`, construct it the way the neighboring tests in `agent/mod.rs` do (check `grep -n "AgentRequest {" src-tauri/src/agent/mod.rs` for a test constructor) — do not add a `Default` derive just for the test if one is not already there.

### Task 3: The knowledge paragraph becomes a capability (M34.1.3)

### Task 4: Unattended instructions ride the system prompt (M34.1.4)
