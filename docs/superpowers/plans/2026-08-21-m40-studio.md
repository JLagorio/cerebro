**Branch:** `m34-agent-platform`. Written after recon on 2026-08-21.

## The shape, corrected by recon

The design sketch is "chat rail + live preview, builds into a vault folder".
Two recon facts bound v1:

1. **The vault writes markdown.** `save_note` only overwrites files that
   exist, creation goes through `create_item` (`.md`, deduped slugs), and the
   non-`.md` write path is the guarded attachment writer. There is no path
   that CREATES an `index.html`, for the app or for the agent's tools — so a
   v1 prototype is a folder of PAGES, previewed rendered, not an iframe of
   HTML. That is also the files-first answer: the artifact Studio builds is
   the artifact the vault can hold.
2. **The chat rail already exists.** The Assistant panel is a companion on
   every surface with a seeding seam (`uiStore.askAgent` — the template-fill
   precedent). A second transcript surface inside StudioPage would be the
   two-chromes defect. Studio's "chat rail" IS the panel, aimed at the
   prototype's folder.

## v1 shape

- `studio/` is the workshop: one prototype = one folder `studio/<slug>/`
  with an `index.md` main page. Loose files directly in `studio/` belong to
  no prototype and are ignored (a prototype is a FOLDER — the same rule that
  makes a Collection a folder).
- `engine/studio.ts` — `studioProjects(entries)`: pure derivation, main page
  is `index.md` (title from it, else the humanized slug), pages sorted main
  first.
- Selection kind `studio` (`{ project?: string }`) — the open prototype is a
  SUBJECT (Back returns to it); the previewed page within it is a lens and
  stays local state, per the place doctrine. `placeOf`/`placeKey`/
  `placeLabel`/`isPlace` learn the kind.
- Sidebar: the **Studio** destination row (after Work — it is a making
  surface). The contract returns to nine.
- `StudioPage`: no project → the prototype list + **New prototype**
  (createFolder + createItem `index.md`); project open → pages list, a
  rendered live preview (`ConceptBody`, the read-only renderer — the body
  re-reads when the scanner sees a write, which is what makes an agent's
  edit LIVE), and **Build with the assistant** → `askAgent` seeded with the
  folder, panel opens.
- The `navigate` MCP tool does NOT learn `studio` in v1 — unknown surfaces
  already go Home, and the agent reaches the folder by path, not by surface.
