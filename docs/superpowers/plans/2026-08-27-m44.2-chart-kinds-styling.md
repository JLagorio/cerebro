# M44.2 — Chart kinds + styling pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend `ChartSpec`/`ChartView` with a `number` big-stat kind, horizontal bars, band sorting, cumulative totals, height presets, a single-hue palette with value shading, seven style toggles, and a subtitle summary line — WITHOUT touching the X-axis/Group coupling (that reversal is M44.3).

**Architecture:** All new settings are flat primitive members of `ChartSpec` (so `clonePresentation`'s shallow `{ ...p.chart }` stays correct), persisted only off-default by `ChartPage.patch`, allowlisted in `parseChart`, computed in `computeChart` (sort/cumulative/number), and rendered by `ChartView` in tokens only — the no-literal-hex test is a hard wall. The spec sequence per feature is: type → parse arm → round-trip test → engine → render → panel control.

**Tech Stack:** React 19 + hand-written SVG (no chart library — `ChartView.tsx:7-20` header comment forbids one), Vitest + Testing Library, YAML view specs via `src/engine/views.ts`.

**Plan-level decisions (spec §4 questions this slice touches):**
- **Q4 (measure model):** the richer existing any-numeric-field sum/avg model stays; the design's hardcoded Count/Sum-of-points pair is NOT adopted, not even as a preset. Nothing to build.
- **Q7 (horizontal orientation):** the standalone chart view type gets it, as `ChartSpec.horizontal?: boolean` on the existing `bar` kind — NOT the design's `column`/`bar` kind split. Reason: existing vaults store `kind: bar` meaning vertical; re-meaning the string `bar` to "horizontal" would silently repaint every saved chart, and a parse-time migration cannot distinguish old `bar` (vertical) from new `bar` (horizontal). An orientation flag has no such ambiguity.
- **M16.27 stays true in this slice.** The three verbatim statements of "the X axis IS the view's grouping" (`chart.ts:7-19` + `chart.ts:119-120`, `types.ts` ChartSpec docstring, `ViewSettingsPanel.tsx` ChartPage docstring + footnote) remain accurate and MUST NOT be edited here — M44.3 retires them. The one nuance this slice adds: a `number` chart has no axis at all, and the ChartPage footnote gains a branch saying so.

**The trap this plan exists to avoid** (from recon): `serializePresentation` passes `chart` through whole, but `parseChart` (`src/engine/views.ts:309-318`) is an allowlist — a new `ChartSpec` key without a parse arm SAVES fine and then silently VANISHES on the next vault load. Every task that adds a key adds its parse arm and a round-trip test in the same commit.

const HPAD = { top: 16, right: 44, bottom: 16, left: 120 };

function HBarChart({ data, chart, h }: { data: ChartData; chart: ChartSpec | undefined; h: number }) {
  const plotW = W - HPAD.left - HPAD.right;
  const plotH = h - HPAD.top - HPAD.bottom;
  const top = niceCeiling(data.max);
  const band = plotH / data.slices.length;
  const barH = Math.min(28, band * 0.62);
  return (
    <>
      {data.slices.map((s, i) => {
        const w = top === 0 ? 0 : (s.value / top) * plotW;
        const y = HPAD.top + band * i + (band - barH) / 2;
        return (
          <g key={s.key}>
            <text
              x={HPAD.left - 8}
              y={y + barH / 2}
              textAnchor="end"
              dominantBaseline="central"
              fontSize={11}
              fill="var(--n-500)"
            >
              {clip(s.label, HPAD.left)}
            </text>
            <rect
              data-testid="chart-bar"
              data-label={s.label}
              data-value={s.value}
              x={HPAD.left}
              y={y}
              width={s.value > 0 ? Math.max(1, w) : w}
              height={barH}
              rx={3}
              fill={sliceColor(s, i)}
            >
              <title>{`${s.label}: ${s.display}`}</title>
            </rect>
            {chart?.hideLabels !== true && (
              <text
                x={HPAD.left + w + 6}
                y={y + barH / 2}
                dominantBaseline="central"
                fontSize={11}
                fill="var(--n-500)"
              >
                {s.display}
              </text>
            )}
          </g>
        );
      })}

export function sliceColor(
  slice: ChartSlice,
  index: number,
  opts?: { palette?: string; share?: number },
): string {
  if (opts?.palette !== undefined) {
    const swatch = resolveOptionColor(opts.palette);
    const base = swatch.name !== 'default' ? swatch.solid : `var(--opt-${PICKABLE_OPTION_COLORS[0]})`;
    if (opts.share === undefined) return base;
    // 35%–100% of the hue against the app surface: the smallest band stays visible.

  }

function linePath(pts: { x: number; y: number }[], smooth: boolean): string {
  if (pts.length === 0) return '';
  if (!smooth || pts.length < 3)
    return `M${pts[0].x},${pts[0].y}` + pts.slice(1).map((p) => ` L${p.x},${p.y}`).join('');
  let d = `M${pts[0].x},${pts[0].y}`;
  for (let i = 0; i < pts.length - 1; i++) {
    const p0 = pts[Math.max(0, i - 1)];
    const p1 = pts[i];
    const p2 = pts[i + 1];
    const p3 = pts[Math.min(pts.length - 1, i + 2)];
    d += ` C${p1.x + (p2.x - p0.x) / 6},${p1.y + (p2.y - p0.y) / 6} ${p2.x - (p3.x - p1.x) / 6},${p2.y - (p3.y - p1.y) / 6} ${p2.x},${p2.y}`;
  }
  return d;
}

function captionNotes(chart: ChartSpec | undefined): string[] {
