# M44.3 — Chart interaction + the M16.27 reversal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Decouple the chart's X axis from the view's Group control (`ChartSpec.xField` + `ChartSpec.groupBy`, stacked bars / multi-series lines), make the legend interactive (`hidden`/`hiddenG`, persisted), add a hover tooltip, click-to-drilldown with "Save as view", and PNG/SVG export — and retire every M16.27 "the X axis IS the grouping" statement the reversal falsifies.

**Architecture:** The reversal is ADDITIVE: `xField` absent → the axis still derives from `presentation.group`'s first band, so every existing saved chart renders identically with zero migration; `xField` present overrides. `groupBy` splits each band into `ChartSlice.parts` (stacked/series rendering); `hidden`/`hiddenG` filter INSIDE `computeChart` so totals, max, and the donut ring reflect the visible set, while `ChartData.bands`/`series` carry the full roster (with hidden flags and STABLE hue indices) for the legend. Chart writes flow through a new `onChartChange` that `ViewCanvas` derives from its existing `onPresentationChange` — dashboards omit it and stay read-only. Export serializes the live SVG element and inlines the CSS-variable fills via `getComputedStyle` (a new `chartExport.ts` — the mermaid pipeline is string-in/string-out and its fills are already literal; ours are tokens).

**Tech Stack:** React 19, hand-written SVG, the existing `mermaid/export.ts` copy/save plumbing + `export_png` Tauri command (M29.4), one new `export_svg` command.

**Plan-level decisions (spec §4 questions this slice resolves):**
- **Q2 (export in scope?): yes.** M29.4 already built the hard parts — `export_png` (Rust dialog+write), base64 IPC, clipboard via plain web APIs, the svg→png rasterizer with font embedding. New work: element→string serialization with token inlining, and a ~20-line `export_svg` sibling command for "Save SVG". All four affordances ship: Copy SVG, Copy PNG, Save PNG, Save SVG.
- **Q3 (Save-as-view path): reuse.** Drilldown's "Save as view" mints through the SAME `seedView`/`nextViewId` chain the tab bar uses, appended via a host-supplied callback — no chart-specific creation path.
- **Interactive affordances are host-gated.** `onChartChange` (legend persistence) and `onSaveView` (drilldown) are optional props; embedded dashboard charts render static legends and no drilldown this slice.
- **Series hue stability:** the engine stamps each band/series with its PRE-filter index (`hue`); renderers color by `s.hue`, never by array position — hiding a band must not repaint its neighbours.
- **The M16.27 retirement checklist** (every site, from the re-survey + the M44.2 final review — a comment the reversal falsifies dies in the same commit that falsifies it):
  - `src/engine/chart.ts:8-19` header (rewrite: axis = `xField`, else the grouping carry-over as DEFAULT) and `:155-156` inline "One band level only … not this commit" (now it IS this commit)
  - `src/engine/types.ts:460-467` ChartSpec docstring ("Its X AXIS IS NOT HERE")
  - `src/views/ChartView.tsx:15` module doc clause

  - `src/views/viewKinds.test.ts:132-139` ("only lets a charted kind exist if it can group" — the invariant dissolves; replace with what stays true: a chart REMAINS groupable because group is still the default axis source)

  Grep `M16.27` at the end of Task 8 — zero hits may remain that still claim the coupling.
