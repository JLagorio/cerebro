# M44.5 — In-page record tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user-configurable tab mechanism on the full-page record view (`DocPage`) — add/rename/reorder/remove tabs persisted per TYPE under a `tabs:` frontmatter key, a tab bar cloned from `ViewTabs`' patterns, the tab riding on the selection so the back button returns to it, and three content types: Overview (today's layout), Properties, and free-text Sections.

**Architecture:** `tabs:` joins `views:`/`display:` as a reserved Type-doc key: tolerant `parseTabList` into `TypeDef.tabs`, a `typeTabs()` default-synthesizer beside `typeViews()` (every type has at least an Overview tab; nothing is written until a user makes tabs their own), and a `setTypeTabs` action cloned from `setTypeViews`. The tab bar mounts in `DocPage` as a `flex-none` sibling ABOVE the `scrollRef` scroll container (so it survives `diffOpen` and stays out of the 820px measure). The active tab lives on the selection — `{ kind: 'doc'; path; tab? }` — per the union's own doctrine ("a place the back button returns to"). Section content is per-record structured data under the app-managed `_sections` frontmatter key (hidden from property surfaces by the existing `_` namespace rule).

**Tech Stack:** React 19, Zustand, existing `patchFrontmatter` IPC (key-agnostic both backends — zero Rust).

**Plan-level decisions (spec §4 questions this slice resolves):**
- **Q13 (where tab management lives):** inline — a trailing "+" popover on the tab bar (the `NewViewForm` shape) and a per-tab menu on the active tab (the `ViewTabs` press-active-to-open-menu pattern). No settings-surface detour: `ViewTabs` proves the inline idiom works and gives us the exact popover/menu/rename/delete components to clone.
- **Q14 (section content storage):** structured data in the record's OWN frontmatter under `_sections` — NOT markdown-H2 surgery on the body. The repo has a heading LISTER (`buildOutline`, live blocks only), no section model, no ranges, no per-section write; building H2 splitting over an uncontrolled whole-file editor is a subsystem this slice doesn't need. `_sections` keeps the file as the one store (frontmatter IS the file), rides the existing `_`-namespace hiding (`visibleProperties`, `src/engine/properties.ts:44`), and writes through the key-agnostic `patchFrontmatter`. Shape: `_sections: { <tabId>: [{ heading, text }] }`.
- **Q15 (activity/comments):** out, per the spec. No Activity content type ships; the content-type vocabulary is `overview | properties | sections`, extensible later.
- **Tab state is selection state, not local state:** `{ kind: 'doc'; path: string; tab?: string }`. `remapSelection` spreads extra keys so renames keep the tab; `sameSelection` compares structurally. Absent `tab` = the type's first tab, same contract as `list.view`.
- **Interplay with M44.1:** `DisplayConfig.showBody`/`showFile` are peek-panel-only by M44.1's own decision, so DocPage tabs never fight it. The Overview tab IS today's DocPage record layout (properties + body + git history), unchanged.
- **Untyped docs get no tab bar** — tabs are per-type; a plain doc renders exactly as today.

```ts
const TAB_CONTENT_SET = new Set<string>(TAB_CONTENTS);

/**
 * Tabs persisted on a Type doc (M44.5): an array under `tabs:`, one entry per
 * record-page tab. Tolerant like every Type-doc block — absent or malformed
 * means "no saved tabs yet" and the page renders its Overview default.
 */
export function parseTabList(raw: unknown): TabDef[] {
  if (!Array.isArray(raw) || raw.length === 0) return [];
  const taken = new Set<string>();
  return raw.map((r, i) => {
    const obj = asRecord(r);
    const declared = typeof obj.id === 'string' && obj.id.trim() !== '' ? obj.id.trim() : '';
    const id = declared !== '' && !taken.has(declared) ? declared : `tab-${i + 1}`;
    taken.add(id);
    return {
      id,
      name: typeof obj.name === 'string' && obj.name.trim() !== '' ? obj.name.trim() : `Tab ${i + 1}`,
      icon: typeof obj.icon === 'string' && obj.icon.trim() !== '' ? obj.icon.trim() : null,
      content:
        typeof obj.content === 'string' && TAB_CONTENT_SET.has(obj.content)
          ? (obj.content as TabContent)
          : 'sections',
    };
  });
}

/** TabDef[] → the plain objects stored under `tabs:`. Inverse of parseTabList. */
export function serializeTabList(tabs: TabDef[]): unknown[] {
  return tabs.map((t) => ({ id: t.id, name: t.name, icon: t.icon, content: t.content }));
}
```

```ts
/**
 * Persist a type's record-page tabs onto its Type doc (M44.5). The whole
 * array is written each time, same contract as `setTypeViews`; an empty
 * list deletes the key so the synthesized Overview default returns.
 */
export async function setTypeTabs(
  listing: { name: string; docPath: string | null },
  tabs: TabDef[],
): Promise<boolean> {
  const { entries, patchFrontmatter } = useVaultStore.getState();
  const toast = useUiStore.getState().toast;
  const doc = findTypeDoc(entries, listing.name);
  if (!guardEditable(doc, listing.name)) return false;
  const serialized = tabs.length === 0 ? null : serializeTabList(tabs);
  try {
    if (doc === null) {
      if (serialized === null) return true;
      await ensureTypeDoc({ name: listing.name, docPath: null }, { tabs: serialized });
    } else {
      await patchFrontmatter(doc.path, { tabs: serialized });
    }
  } catch {
    toast(`Couldn't update ${listing.name} tabs`);
    return false;
  }
  return true;
}
```

```tsx
export interface TabSection {

/** `_sections` is app-managed frontmatter (the `_` namespace): a map of tab
 * id → sections. Tolerant like every frontmatter read — garbage means []. */
export function parseSections(raw: unknown, tabId: string): TabSection[] {
  if (raw === null || typeof raw !== 'object') return [];
  const list = (raw as Record<string, unknown>)[tabId];
  if (!Array.isArray(list)) return [];
  return list.flatMap((s) => {
    if (s === null || typeof s !== 'object') return [];
    const obj = s as Record<string, unknown>;
    return [
      {
        heading: typeof obj.heading === 'string' ? obj.heading : '',
        text: typeof obj.text === 'string' ? obj.text : '',
      },
    ];
  });
}

export function TabSections({ entry, tabId }: { entry: Entry; tabId: string }) {
  const patchFrontmatter = useVaultStore((s) => s.patchFrontmatter);
  const raw = (entry.properties as Record<string, unknown>)._sections;
  const sections = parseSections(raw, tabId);

  const write = (next: TabSection[]) => {
    const all =
      raw !== null && typeof raw === 'object' ? { ...(raw as Record<string, unknown>) } : {};
    if (next.length === 0) delete all[tabId];
    else all[tabId] = next;
    // The last section of the last tab deletes the key — a record with no
    // section content carries no _sections at all.
    void patchFrontmatter(entry.path, { _sections: Object.keys(all).length === 0 ? null : all });
  };

  const patchAt = (i: number, patch: Partial<TabSection>) =>
    write(sections.map((s, j) => (j === i ? { ...s, ...patch } : s)));

  return (
    <div data-testid="tab-sections" className="flex flex-col gap-4">
      {sections.length === 0 && (
        <p data-testid="sections-empty" className="m-0 text-sm text-n-400">
          Nothing here yet — add a section to start writing.
        </p>
      )}
      {sections.map((s, i) => (
        <div key={i} className="group flex flex-col gap-1">
          <div className="flex items-center gap-1">
            <input
              value={s.heading}
              placeholder="Heading"
              onChange={(e) => patchAt(i, { heading: e.target.value })}
              className="w-full border-0 bg-transparent p-0 text-base font-semibold text-n-900 outline-none placeholder:text-n-300"
            />
            <IconButton
              icon="trash-2"
              label="Delete section"
              size="sm"
              onClick={() => write(sections.filter((_, j) => j !== i))}
            />
          </div>
          <textarea
            value={s.text}
            placeholder="Write…"
            aria-label={`Section ${i + 1} text`}
            onChange={(e) => patchAt(i, { text: e.target.value })}
            rows={Math.max(3, s.text.split('\n').length)}
            className="w-full resize-y rounded-md border border-transparent bg-transparent p-0 text-sm leading-6 text-n-800 outline-none hover:border-n-100 focus:border-n-200"
          />
        </div>
      ))}
      <button
        type="button"
        data-testid="add-section"
        onClick={() => write([...sections, { heading: '', text: '' }])}
        className="flex items-center gap-1 self-start rounded-md border-0 bg-transparent px-1 py-0.5 text-xs text-n-400 hover:bg-n-50 hover:text-n-700"
      >
        <Icon name="plus" size={12} /> Add section
      </button>
    </div>
  );
}
```

Refinement while implementing: writing frontmatter on every keystroke is too chatty — debounce the text writes the way the codebase debounces (local draft state committed on blur is the simplest honest version: `value` from local state seeded by props, `onBlur` → `patchAt`). Pick blur-commit and adjust the tests to `fireEvent.blur` after `change` — the add/delete tests stay as-is since those are click-driven. Verify `_sections` stays hidden from property surfaces (the `_` prefix rule in `visibleProperties`) with a quick check in `RecordProperties.test.tsx` if not already generic.
