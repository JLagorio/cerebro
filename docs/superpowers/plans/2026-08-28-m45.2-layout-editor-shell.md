# M45.2 — Layout editor shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Customize-layout SCREEN: fullscreen editor with a real-record preview rendered from a staged draft, the Page settings rail (Structure + Options), and Cancel / Apply-to-all — replacing the M44.1 Customize-display drill-in.

**Architecture:** One global `LayoutEditorDialog` mounted at App level, opened via a uiStore signal from three menus. Draft state (`TypeLayoutDraft`) seeded from the RESOLVED layout (pointer pruning happens at seed, lands on Apply); every control edits the draft; the inert preview canvas re-renders from it; `applyTypeLayout` (M45.1) is the only write, and the dialog closes only on `true` (M14.8 idiom).

**Tech Stack:** existing only — `Dialog fullscreen` (M29.27), `Switch`, `Select`, Menu primitives, `resolveLayout`/`stripCells`/`applyTypeLayout`, RecordTabs/HeadingProperties/RecordProperties as preview renderers.

**Spec:** `docs/superpowers/specs/2026-08-28-cerebro-m45-layout-editor-design.md` §3.1–3.2, §3.5 (structure only), §5(M45.2), §6.

## Decisions this plan locks

- **One mount, one signal.** The editor is `LayoutEditorDialog` rendered once in `App.tsx` beside the other global overlays, driven by `uiStore.layoutEditor: { type: string } | null` (`openLayoutEditor(type)` / `closeLayoutEditor()`). Menus fire the signal; nothing threads callbacks through PropertyRow. Device-local ephemera — uiStore's charter.
- **The preview is INERT.** It renders the real components (HeadingProperties, grouped RecordProperties, RecordTabs) from the draft, wrapped in a container with the `inert` attribute (React 19 supports it). A live FieldEditor in the preview would write REAL records from inside a staged editor — forbidden. `data-testid="layout-preview"` carries `inert`; a test asserts it.
- **Preview edits nothing; the rail edits the draft.** M45.2 draft-editable surface: `display` (three switches), `tabs` (Structure tiles). `layout` changes only by seed-pruning; `visibility`/`added` stay empty (M45.3's group editor owns them). The draft still carries all five members so M45.3 plugs in without reshaping state.
- **Structure is derived, both ways**: Tabbed tile active ⟺ `draft.tabs.length > 0`. Switching to Simple sets `tabs: []`; switching to Tabbed with an empty draft seeds `[{ id: 'overview', name: 'Overview', icon: null, content: 'overview' }]` — the synthesized default made explicit. No structure flag anywhere.
- **Simple means NO strip** (spec §3.5): DocPage renders `RecordTabs` only when the type has SAVED tabs (`typeDef.tabs.length > 0`), not for the synthesized Overview. This deliberately amends M44.5 behavior (today every typed record shows a one-tab strip); the M44.5 tests that assert the synthesized strip are updated IN the task that changes it, with a comment naming this plan.
- **Customize display RETIRES.** The drill-in step in DetailHeaderActions (menuStep 'display', the three switches, MenuBack, the reset button) is deleted; the ⋯ item becomes `Customize layout` opening the editor. Every comment the deletion falsifies (the drill-in rationale at :69-70, :195-197, :265-267) dies with it. The M44.1 drill-in tests retire in the same commit — their COVERAGE (the three display bits round-tripping) already lives in typeActions tests and gains an editor-path e2e in Task 6.
- **Dirty means a confirm, not a block**: Cancel/Escape with an untouched draft closes immediately; with edits, a small confirm Dialog ("Discard layout changes?"). Apply disables while busy; a failed Apply keeps the editor open with everything the user built (M14.8).
- **Seed prunes**: draft.layout is rebuilt from `resolveLayout(typeDef.layout, typeDef.fields)` — surviving names only (heading + groups; group ids/names verbatim; empty groups kept). Dead pointers thus vanish on the next Apply, honoring spec §4's hygiene without a special pass.
- **Preview roster**: records of the type via the surface.ts:204 filter (`e.type === name && !isTemplate(e)`), sorted by title; first is default. Zero records → a synthetic in-memory Entry (path `''`, empty properties) rendered inert — never written, never in the store.
