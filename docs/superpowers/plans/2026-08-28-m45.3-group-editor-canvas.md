# M45.3 — Group editor + canvas interaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The canvas becomes the editor: block chrome, the property-group popover (eye toggles, search, Add a property, Add section), and drag between containers — everything staging into the M45.2 draft.

**Architecture:** The inert boundary moves inward — interactive BLOCK SHELLS (heading, each group, rest, content) own hover chrome, click-to-edit, and drag grips, while each block's CONTENT stays inert. All edits flow through the existing `update(patch)` door into `TypeLayoutDraft` (`layout`, `visibility`, `added`); Apply is untouched. Pure editors over `LayoutConfig` (a new `src/engine/layoutEdit.ts`, dashboard.ts's pure-editor shape) do every structural move so drag/menu handlers stay thin and testable.

**Tech Stack:** existing only — dnd-kit core (DashboardView's slot idiom), Popover/MenuSurface, AddPropertyPanel, splitByVisibility.

**Spec:** `docs/superpowers/specs/2026-08-28-cerebro-m45-layout-editor-design.md` §3.3, §3.4 (Move to page), §5(M45.3). **Mandatory carries:** the M45.2 plan's "Slice write-back" section (657d40c) — items 1–4 are all budgeted below.

## Decisions this plan locks

- **Eye toggle cycles show ↔ hide**; the row's overflow (⋯) offers the full three-state vocabulary (Always show / Hide when empty / Always hide — PropertyMenu's VISIBILITIES verbatim). The eye WRITES `draft.visibility[name]` (`'hide'` or `null`), never the vault.
- **Canvas rows fold like the real page** — `splitByVisibility` with the DRAFT's visibility overlaid on each FieldDef and the DRAFT's showEmpty (M45.2 write-back item 1 + fold fidelity). Folded rows show nothing in the canvas (the page's collapsed default); the group EDITOR's rows always list every field with its eye state — the editor is where hidden things stay visible.
- **Pure editors, dashboard-style**: `layoutEdit.ts` exports `moveField(layout, name, to: {container, index})`, `addGroup(layout, takenIds)`, `renameGroup`, `removeGroup` (fields fall to rest by OMISSION — rest is derived, so removal just deletes the group), `moveGroup(layout, id, to)` — each returns the SAME reference on a no-op (the identity-guard idiom) and a fresh config otherwise. Container address: `'heading' | 'rest' | groupId`. Moving to `rest` = removing the name from every container.
- **`added` fields live in the draft roster**: preview + group editor resolve against `[...typeDef.fields, ...draftAddedDefs]` (the write-back's one-liner). A staged added field can be placed, eyed, and dragged like any other; deleting it before Apply = removing it from `added` (offered in its row's ⋯ as "Discard new property").
- **Add a property (existing)** lists fields NOT in the clicked group (rest + other containers), pulling one IN via `moveField`; **create new** drives AddPropertyPanel's catalog and stages `{name, kind, config}` with **FieldDef-shaped config** (the typeActions.ts:620-629 contract — relation configs built as FieldDef members, options as FieldOption[]).
- **Add section** appends an empty group named "New group", id minted against ALL draft group ids with the two-pass-safe `group-${n}` walk (a pure `mintGroupId(taken)` exported from layoutEdit.ts — do NOT duplicate schema.ts's private one; export from ONE place and note the origin).
- **Block chrome is the shell's**: hover ring + name label + grip render on the shell (non-inert); the content div carries `inert`. Both existing inert assertions re-aim at the content divs (`layout-preview-content` per block or one shared testid — implementer picks, test asserts EVERY block's content is inert).
- **Hoists land here** (write-back item 3): the fold predicate into `src/engine/properties.ts` (`foldsWhenUnset(entry, schema, showEmpty)` returning the isEmpty lambda — consumed by stripCells, RecordProperties, DocProperties, canvas), and deep-equal into `src/lib/deepEqual.ts` (consumed by draftDirty, navStore.sameSelection, trigger/evaluation.ts) — both behavior-neutral, both test-first, each killing the twin-copy rationale comments it obsoletes.
- **Polish carries land in Task 1**: duplicate type-name span trimmed (one-header anatomy), dead icon-span classes, the `key={signal.type}` reseed component test.

## Tasks (each = TDD: failing test → red → implement → green → commit)

### Task 1: Canvas honesty + polish (write-back items 1, 3-fidelity, 4)
Fold canvas rows via `splitByVisibility` with draft visibility/showEmpty overlay; extract the caps label as `GroupLabel` (one component, canvas + panels); trim the duplicate name span + dead classes; add the reseed test. Commit: `fix(detail): the canvas folds what the page folds (M45.3)`.

### Task 2: The hoists (write-back item 3)
`deepEqual` + `foldsWhenUnset` extracted with all consumers switched and twin-rationale comments killed; behavior-neutral (all existing suites untouched and green). Commits: `refactor(lib): one deep-equal, three former copies (M45.3)`, `refactor(engine): one fold predicate for every property surface (M45.3)`.

### Task 3: `layoutEdit.ts` pure editors
All six editors + `mintGroupId`, identity-guard no-ops, frozen-input purity tests, container-address edge cases (move to own position; unknown name; unknown group; heading↔group↔rest all directions). Commit: `feat(engine): pure editors move fields and groups through the layout (M45.3)`.

### Task 4: Block shells + inert boundary reshape (write-back item 2)
Shells with hover ring/label/grip; content-only inert; re-aim BOTH inert assertions (unit: every `layout-preview-content` inert AND shells not; e2e: the coordinate click targets the content). Canvas roster gains `added` defs. Commit: `feat(detail): the canvas grows block shells around inert content (M45.3)`.

### Task 5: GroupEditorPopover
Click a group/heading/rest shell → Popover (PropertyMenu drill-in idioms, `autoFocus={false}`): search input; one row per resolved field of that container (kind icon, name, eye button cycling show↔hide via `update({visibility})`, ⋯ MenuSurface with the three-state vocabulary + "Discard new property" for added-only); rename (groups only, blur-commit/Escape-abandon); Delete section (groups only, fields fall to rest); Add a property → existing-list (pull in via `moveField`) / Create new → AddPropertyPanel catalog staging FieldDef-shaped `added`; + Add section on the rest/heading editor footer. Commit: `feat(detail): the group editor stages eyes, names, and new properties (M45.3)`.

### Task 6: Drag
dnd-kit droppable slots per container (DashboardView's `slot:` id grammar + WidgetSlot idiom), draggable grips on rows AND group shells; pure `handleLayoutDragEnd(event, {layout, commit})` exported (DashboardView's exported-handler pattern) routing to `moveField`/`moveGroup`; keyboard sensors as BoardView's. Commit: `feat(detail): fields drag between containers, groups reorder (M45.3)`.

### Task 7: Gate + e2e
e2e extends the journey: open editor → click the Planning group shell → eye off `estimate` → Apply → real page folds it behind the expander → bytes assert `visibility: hide` on the field. Full gate (coverage ratchet, e2e on a FREE port). Commit as needed.
