### M59.2 search_notes reports what it found and missed

- **What:**
  - The description promises frontmatter, but only title, type and body rank, so a Skill's `description:` and an `owner: [[maya-chen]]` link are invisible.
  - The excerpt keeps the first 180 chars of the best line, so a late match is cut off.
  - The phrase bonus matches the raw query, quote marks included, so a quoted phrase never earns it.
  - `hits.truncate` drops the rest with no count, and no word caps exist.
  - A miscased or unknown `type`, and `limit: 0`, both answer "No notes matched".
  - `searchEntries` matches nested values as `[object Object]`.
- **Files:** `src-tauri/src/{search.rs, mcp.rs, knowledge.rs}`, `shared/policy/{tools.v1.json, tools.v1.sha256}`, `src-tauri/fixtures/searchable-values.json` (new), `src/engine/searchable{,.test}.ts` (new), `src/engine/{viewFilters,viewFilters.test,tools.test}.ts`.
- **Approach:**
  - **Tokens and queries** (search.rs).
    - `token_spans(text)` sits beside `tokenize()`: each maximal `is_alphanumeric` run, lowercased, with its byte range. `tokenize()` itself, retrieval and RETRIEVER_VERSION don't change.
    - `parse_query(raw)`: `"`, `\u{201C}` and `\u{201D}` quote a phrase of 2+ tokens; an unclosed mark quotes nothing. Terms come from `tokenize`, each cut to `MAX_TERM_CHARS` (80 chars), deduped, with the first `MAX_TERMS` (50) kept; `dropped` and `cut` are counted. `implicit` is the whole query when nothing is quoted and it holds 2+ tokens.
  - **Frontmatter text** (D3). `searchable_fields(title, type, properties, relationships)`:
    - properties in frontmatter order, then relationship keys sorted;
    - a string trimmed (blank gives nothing), an integer as digits, a float by f64 Display (1.0 reads 1), a boolean as written; an array item by item; an object or null gives nothing; texts join with `, `;
    - dropped: `_` keys, `icon` and `cover` (M55.11's PAGE_CHROME_KEYS), a `title` equal to the note's, and, on an `Agent` record (a reserved name, CV-08), `recent`, `memory` and `preferences`.

    `searchable-values.json` holds the cases (A2). TS `searchableFields` replays it, and `searchEntries` builds its haystack from the title, type, path and fields.
  - **Ranking.**
    - `Doc` gains `meta`, and `META_WEIGHT` is 1.5: tf = body + 3·title + 2·type + 1.5·meta. df, the gate and the length read all four fields.
    - A phrase matches inside one field. Sort: holds every quoted phrase, then score, then path. The implicit phrase keeps its ×1.5, and nothing gates.
    - `rank_query(query, docs, limit)` returns `Ranked {hits, widened, total}`, with `Hit {index, score, excerpt: Option<Excerpt>, matched, phrase}`. `rank(&str…)` stays as a wrapper, and `contains_phrase` goes.
  - **The excerpt,** in two steps (.4 reuses the second).
    - Choose: meta fields in order, then body lines numbered from 1. That body is the one get_note prints, so the numbers are the ones edit_note lists. The most distinct terms wins, ties go to the earlier, and none gives None.
    - Window: whole when 240 chars or fewer (`EXCERPT_CHARS`). Otherwise take the 238-char window, starting 60 chars before a match, that holds the most distinct terms; snap it to whitespace within 20 chars; drop invisible chars, written only as escapes (`\u{00AD}`, `\u{034F}`, `\u{061C}`, `\u{200B}`–`\u{200F}`, `\u{2028}`–`\u{202E}`, `\u{2060}`–`\u{206F}`, `\u{FEFF}`, `\u{2800}`); collapse spaces; remap the ranges; add `\u{2026}` at each cut end. Ranges are byte offsets on token boundaries.
  - **Labels and the tool.**
    - knowledge.rs lifts `about()`'s walk into `ConceptGraph::build` and adds `concept_status` (trust, lifecycle, superseded_by, contested, stale). `about()` reads both, with no behaviour change.
    - mcp.rs helpers, shared with .5: `readable_entries` (with the vault-wide withheld count), `type_filtered` (ASCII case-insensitive; an unknown type is refused naming only readable types), `arg_limit(default, max)` and `HitLabels`, built lazily and only when a shown hit is a concept.
    - `tool_search`: a blank query is refused; `arg_limit(20, 100)`; unparsed frontmatter and unreadable notes are counted, never dropped. The answer text is exact (A2). No new code and no operational row.
  - **Manifest.** The search_notes row's description, summary and three property descriptions change (A2). Its shape, title, hint, `always_load`, fold and `confirmable` stay.
- **Comments to delete:** search.rs's `Hit.excerpt` doc, `excerpt()`'s doc and `rank`'s phrase comment; the weights doc gains 1.5; the old manifest description and summary; `searchEntries`' "Every term must match somewhere…"; `about()`'s "walked ONCE", moved to `ConceptGraph::build` and reworded. Left for .4: the module doc's cost paragraph. tokenize's no-stemmer doc stays true.

- **What:** no find exists: nothing handles ⌘F, and WKWebView has no find bar (EDITOR-5). Macro's behaviour, mirrored: literal, case-insensitive, non-overlapping, never across blocks, and Replace all as one edit.
- **Files:** `src/editor/{findMatches,findMatches.test,chipLabels,chipLabels.test,findHighlights,findHighlights.test}.ts` (new), `src/editor/FindBar{,.test}.tsx` (new), `src/editor/{chips,MarkdownEditor}.tsx`, `src/editor/{editor.css, citationInput.ts, sectionLinks.ts}`, `e2e/find-replace.spec.ts` (new). `package.json` and `pnpm-lock.yaml` only to add a missing ProseMirror dependency.
- **Approach:**
  - **Precondition.** prosemirror-history (M55.6), prosemirror-state and prosemirror-view (M70.1) are direct dependencies with one lockfile copy each, and MarkdownEditor passes `extensions: [CommentHighlights()]`. A missing one is added at BlockNote's range, and `pnpm why` shows one version. sectionLinks.ts changes only to export M55.8's reveal step, if it is private.
  - **Matching** (`findMatches.ts`, pure, no React or DOM; the doc type by a type-only import, as citationInput.ts does).
    - `findHits(doc, query, labelOf)`: an empty query gives []. The pattern is `new RegExp(escapeRegExp(query), 'giu')`.
    - Each textblock (paragraph, heading, list item, code block, table paragraph) is scanned alone, so no hit spans blocks. Text nodes add their text (positions are UTF-16). An inline atom adds `FIND_SEPARATOR` (`￼`, an escape in source, CV-13) around its label; a match touching a label becomes one `inLink` hit over the whole chip.
    - Hits come in document order, 1-based, never overlapping, each with its block id. Also `nextIndex` (wraps), `firstAtOrAfter`, `replacementPlan` (text hits not already equal, last first, links counted) and `escapeRegExp`.
    - The docblock says why it is neither M55.5's finder nor M70.1's reader text: find is case-insensitive and non-overlapping, includes code, and spells chips by their visible label.
    - `chipLabels.ts`: `wikilinkLabel` and `assigneeLabel`, exactly what the chips render (alias first, `Title › Heading`, the raw target when dangling). chips.tsx calls them, so nothing changes on screen, and `chipText` serialization is untouched (trap 10).
  - **Highlights** (`findHighlights.ts`, M70.1's pattern). `FindHighlights` via `createExtension`, plugin key `cerebro-find`, holds a DecorationSet: a meta replaces it and a doc change maps it. Text hits get inline decorations and link hits node decorations, all with `cb-find-hit` and `data-find`, the current one also `cb-find-current`. `showFindHits` and `clearFindHits` dispatch a step-less transaction with `addToHistory: false`: no onChange, no undo entry, no save. Nothing is written onto ProseMirror's DOM (trap 2).
  - **The bar** (`FindBar.tsx`, props editor, host, readOnly).
    - A module registry holds the mounted bars. The target is the bar whose host holds focus, else the last focused host (tracked by focusin), else the first connected one.
    - Keys use App.tsx's `metaKey || ctrlKey` rule. ⌘F opens the bar, or refocuses it and selects the query. ⌥⌘F (`code === 'KeyF'` with altKey) opens it with Replace, on editable pages only. ⌘G and ⇧⌘G step while it is open.
    - With focus outside every host, or inside `[role=dialog]`, `[role=menu]`, `[role=listbox]` or `[aria-modal=true]`, it does nothing and doesn't call preventDefault. Not `hasLayers()`: the record peek is a surface layer.
    - Opening seeds the query from a one-line selection of 1–200 chars, else the last query, and starts at `firstAtOrAfter(selection.from)`. It recomputes once per frame on input, on `editor.onChange` (subscribed only while open) and on entries, never while composing.
    - Moving to a hit runs M55.8's reveal step for its block (opening closed toggles), then `scrollIntoView` on `[data-find="i"]` the next frame.
  - **Replace.**
    - Replace changes the current hit and moves on; it is disabled on a link hit.
    - Replace all re-runs `findHits` and applies `replacementPlan` in one `editor.transact`, with `closeHistory` before and after, so it is one undo step that never merges with typing on either side. It refuses when read-only, composing or empty.
    - The edit reaches MarkdownEditor's `scheduleEmit` like any edit, so the normal debounced save writes it (D2). The bar itself never writes.
  - **Close and look.** Escape inside the bar closes it through `useEscapeLayer(close, {kind:'surface'})`, mounted only while focus is in the bar, so Escape in the page keeps its editor meanings (Q15). Closing clears the highlights, keeps the query and refocuses the editor. Layout, copy and testids: A5. CSS uses tokens only: `--warn-50` for hits, `--warn-300` for the current one, and link hits outlined through `.cb-find-hit [data-chip]`, safe under trap 1. MarkdownEditor changes only `extensions` and mounts `{loaded && <FindBar …/>}` as the host's first child.
- **Comments to delete:** citationInput.ts's "`prosemirror-state` is not a dependency of the app…" (keep the view-prop choice), unless M70.1 already did; any MarkdownEditor comment saying CommentHighlights is the editor's only extension.
- **Tests:**

### M59.7 Hover previews for page and concept links

- **What:** links show only a native title tooltip, and no preview card exists (SHELL-8). Macro's HoverCard behaviour, adapted: open delays, one open card per group, ancestors held open, and Escape that walks back through the layers.
- **Files:** `src/components/ui/HoverCard{,.test}.tsx` (new), `src/components/PagePreview{,.test}.tsx` (new), `src/editor/chips.tsx`, `src/editor/chips.test.tsx` (new), `src/editor/sectionLinks.test.tsx`, `src/agent/MessageMarkdown{,.test}.tsx`, `e2e/hover-preview.spec.ts` (new).
- **Approach:**
  - **`HoverCard`,** a render-prop primitive: `children({ref, describedBy})`, `content`, `label`, `group`, `openDelay` (`HOVER_OPEN_MS`, 300), `closeDelay` (`HOVER_CLOSE_MS`, 150), `openOnFocus` and `disabled`. It renders children plus a portal while open, and adds no wrapper node (Tooltip's rule).
    - Listeners bind natively on the ref's element, because React pointer handlers inside ProseMirror don't fire (trap 9).
    - Opening: a pointermove that really moved (its screen position differs from a module-level window tracker's last), with buttons 0 and not touch; or, with `openOnFocus`, focusin on a `:focus-visible` trigger.
    - pointerleave and focusout schedule a close; pointerdown cancels and closes. After a close by Escape or a press, the trigger stays quiet until the pointer leaves it.
  - **Groups and holds.** `openByGroup` maps a group to its open cards. Opening closes the group's other cards except its ancestors and takes a hold on its parent card through context. A card with holds (a nested card, or a portaled child calling `useHoldParentHoverCard`) never schedules its close; when the holds drop to zero with the pointer outside, it does. Macro's "deepest nested trigger wins" is left out: no Cerebro trigger nests.
  - **Surface and dismissal.**
    - role group, aria-label, and an id the trigger gets as aria-describedby while open; `hover-card`. Fixed below-start with a 6 px gap, flipped above when it would leave the viewport and fits there, clamped 8 px from the edges, re-measured on resize and by its own ResizeObserver. Classes: rounded-lg, border-n-200, bg-n-0, `shadow-[var(--shadow-lg)]`, `z-[1100]`, `w-[320px]`, `max-w-[calc(100vw-16px)]`.
    - Pointer entering the card cancels the close, and leaving schedules it. Click, pointer, mouse and key events stop at its root, so nothing bubbles into the chip or the editor host's ⌘K handler.
    - A child component, mounted while open, holds `useEscapeLayer(close, {kind:'tooltip', contains})` (non-modal: it owns its Escape but is never the innermost surface), an outside pointerdown capture (unless `isInsideLayerAbove`), a scroll capture armed one frame late (Popover's M18.4 reason), and a keydown capture that closes on any key from outside but Escape, Tab and bare modifiers.

  - `pnpm format:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test:run`;
  - Rust parts (.1, .2, .4, .5) add `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and the skip-listed `cargo test`;
  - e2e parts add `PORT=<free> pnpm e2e <spec>` once `lsof -iTCP:<port> -sTCP:LISTEN` shows the port free: .1 `destinations` plus the specs that click destination rows or doors (`smoke`, `studio`, `agents`, `workspace`, `knowledge`, `inbox`, `agent`, `pipeline`, `shell-layout`, `ai-block`); .3 `quick-open-recent`; .4 `quick-open-content`; .5 `agent` and `agents`; .6 `find-replace`; .7 `hover-preview`;
  - UI parts (.1, .3, .4, .6, .7) run `verify-ui` on a free port.
- **Each wave tip:** the same gate on the branch, with the full e2e suite.
- **M59 closes when:**
  - the full gate passes on the tip, with `pnpm test:coverage` holding or raising every floor;
  - CI is green on the push;
  - every roadmap M59 acceptance bullet holds;
  - the owner has run the packaged checks (.1, .4, .6, .7) on a `./scripts/mac-build.sh` build, optionally .2's live check, and has looked at the built app;
  - .4's commit body records the per-query time on the owner's vault;
  - the roadmap's M59 status is updated, and its M59.6 cell says decorations (Q14).

cargo test --manifest-path src-tauri/Cargo.toml -- --skip crash --skip killed_ \
  --skip kill_and_restart --skip a_kill_ --skip kill_point --skip interrupted_overwrite

### A2. search_notes (.2; .4 and .5 add as marked)

- **Description:** "Keyword search over the notes this run may read: titles, types, frontmatter values (description, status, tags and other properties, and the pages a property links to) and body text. It is not semantic search: it matches whole words, ignoring case, with no stemming (risk and risks differ), so search for words the note itself would contain, and search for a person and a topic separately rather than in one long question. A note must contain every informative word somewhere; when none contains them all, the answer says so and returns the closest matches. Put a phrase in double quotes, as in "release checklist", and notes containing that exact phrase rank first. At most 50 distinct words are searched and each is cut to 80 characters; the answer says when either cap applied. Results come best first, up to limit, and the answer says how many more matched but are not shown. Each hit gives the path, title, type and labels (a knowledge concept's review state, lifecycle and replacement; a template; an Inbox capture; a note past its stale_after date), then the matching line, cut to about 240 characters, with its line number in the note's body, or the frontmatter field that matched. Notes outside this run's read scope are never searched, and the answer counts them."
  - .5 inserts after "…rather than in one long question.": "Pass in: name to match titles only, or in: content to match everything except titles."
- **Summary:** "Keyword search over titles, properties and text".
- **Properties:**
  - `query`: "Words to find. Put a phrase in double quotes to rank notes holding it first."
  - `type`: "Only notes of this type, ignoring case. An unknown type is refused with the types in use."
  - `limit`: "Max results (default 20, at most 100)."
  - `in` (.5), a string enum of name, content and all: "Where to match: name (titles only), content (everything except titles) or all (the default)."
- **Answer** (exact; singular forms when a count is 1):
  - Strict header: `{n} of {total} notes{ of type T} match "{query}", best first{scope}:`
  - Widened header: `No note{ of type T} contains every word of "{query}". {n} of {total} closest matches, best first{scope}:`
  - No hits: `No notes{ of type T} matched "{query}".{scope}`
  - `{scope}` keeps M34.4's words: ` ({w} notes outside this run's read scope were not searched)`.
  - .5: after the quoted query, ` (titles only)` for name and ` (titles not searched)` for content.
  - .4: when a searched note was capped, the header gains ` (N notes longer than 100 KB were searched in their first 100 KB)`.
  - Each hit: `- {path} — {title}{ [Type]}{ · labels}`, then `  L{n}: {excerpt}`, `  {key}: {excerpt}` or `  {snippet}` (omitted when empty). A widened answer adds `  matched: {terms}`.
  - Labels, in order: `concept, {trust}`, plus `, {lifecycle}` when not stable, `, replaced by {path}` per readable replacement, `, contested` and `, stale`; then `knowledge log` or `knowledge index`; `template` (under templates/); `Inbox capture`; `stale` (a non-concept whose `stale_after` is past or malformed); `unparsed frontmatter`; `unreadable`.
  - Footers, in order, each only when it applies:
    - `{more} more not shown; raise limit (at most 100) or narrow the query.`
    - `The limit is at most 100.`
    - `Only the first 50 of {k} distinct words were searched.`
    - `{c} words longer than 80 characters were cut to 80.`
    - `{p} notes have frontmatter that could not be parsed, so only their title and text were searched.` With a type filter: `{p} notes have frontmatter that could not be parsed, so their type is unknown and they were not searched.`
    - `{u} notes could not be read, so their text was not searched.`
- **Refusals:** `search_notes needs a query` · `limit counts from 1 (default {d}, at most {m})` · `No note this run can read has type "{T}". Types in use: {the sorted types of the readable notes, or none}.` · (.5) `in must be name, content or all`.
- **`searchable-values.json`,** in `source-slugs.json`'s shape: `format` 1, an `about` that states the rule and names both replayers, then `values` and `entries` cases, each with a `why`. Non-ASCII and invisible chars are `\u` escapes (CV-13).
  - Values: a string, a blank string, an integer, a negative, a decimal, a boolean, null, a flat array, a nested array, an object, an array holding an object.
  - Entries: a Skill's description; a relationship target; an Agent's three memory keys; `recent` on a non-Agent record (kept); `_organized`, `icon` and `cover` (dropped); a duplicate `title` (dropped) and a different one (kept); tags joined; relationship keys sorted; an object-only property (no field); a `_`-prefixed relationship (dropped).

### A3. list_notes and the read toolset (.5)

- **Row,** after search_notes, in search_notes's row shape: surface base · title `List notes` · summary `Browse notes by type, folder or date` · toolset read · kind read_only · idempotent true · door none · axis read · no target, no exempt · renderer step · icon `list-filter` · always_load false · search_hint `list notes by type folder or date` · fold one `listed notes`, many `listed notes {n} times` · confirmable false.
- **Description:** "Browse the notes this run may read without a search term: filter by type, by folder (subfolders included) or by when a note's file last changed, and sort the result. Use it for questions like "what changed this week", "list the Risk records" or "what is in this folder"; to find notes by the words they contain, use keyword search instead. Each line gives the path, title, type, labels (a knowledge concept's review state and replacement, a template, an Inbox capture, a note past its stale_after date) and a time. modified is when the file last changed on this disk, which any save, sync or checkout moves; created is when the file first appeared on this disk, which a copy or clone resets. modified_since takes a date such as 2026-10-01, read as 00:00 UTC, or an RFC 3339 time. sort is modified (the default) or created, newest first, or title or path, A to Z. Up to limit notes are listed (default 50, at most 200), and the answer says how many more matched. An unknown type is refused with the types in use. Notes outside this run's read scope are never listed, and the answer counts them. A note whose time was not recorded is listed last and counted, never treated as new."
- **Properties** (none required):
  - `type`: "Only notes of this type, ignoring case. An unknown type is refused with the types in use."
  - `folder`: "Only notes in this vault-relative folder and its subfolders, such as records/risks."
  - `modified_since`: "Only notes whose file changed at or after this time: a date such as 2026-10-01 (00:00 UTC) or an RFC 3339 time."
  - `sort`, a string enum of modified, created, title and path: "modified (default) or created, newest first; title or path, A to Z."
  - `limit`, a number: "Max notes (default 50, at most 200)."
- **Answer** (exact; singular forms when a count is 1):
  - Header: `{n} of {total} notes{ of type T}{ in folder/}{ modified since {instant}}, {order}{scope}:`. `{order}` is `newest modified first`, `newest created first`, `by title` or `by path`; the instant is RFC 3339 UTC; `{scope}` is ` ({w} notes outside this run's read scope were not listed)`.
  - Each line: `- {path} — {title}{ [Type]}{ · labels} · {modified|created} {time}`. created appears only under sort created, and an unrecorded time reads `not recorded`.
  - Empty: `No notes{ of type T}{ in folder/}{ modified since {instant}}.{scope}`
  - Footers, in order: `{more} more not listed; narrow the filter or raise limit (at most 200).` · `The limit is at most 200.` · `{k} notes have no recorded {modified|created} time and are listed last.` · `{k} notes have no recorded modified time, so modified_since could not include them.` · with a type filter, `{p} notes have frontmatter that could not be parsed, so their type is unknown and they were not listed.`
- **Refusals:** `folder must be a folder inside the vault, such as records/risks` · `modified_since must be a date such as 2026-10-01 or an RFC 3339 time such as 2026-10-01T09:00:00Z` · `sort must be modified, created, title or path` · and .2's type and limit refusals.
- **The read toolset:** get_vault_context, search_notes, list_notes, get_note, knowledge_about, list_inbox.
- **Skills index overflow,** after `{n} more skill(s) is/are defined but not listed here`:
  - the run holds list_notes: ` — call list_notes with type Skill to see them all.`
  - it holds only search_notes: ` — search_notes for type Skill to find them.` (today's)
  - it holds neither: `.`
