### M66.2 Bytes into the webview: the cerebro-file scheme, two CSP sources, probe_file, raw IPC for PDFs, a mock bytes lane

- **What:** the webview can't draw a vault or repo image, play audio or hand a PDF to a viewer. The CSP is `img-src 'self' data:`, and tauri's features are `[]` (M16.13c deferred this). FileViewer reads only text under 2 MB, and read.rs checks size before the sniff, so a 5 MB photo reads tooLarge. Tauri's asset protocol is not containment: it resolves relative symlinks against the cwd and checks one path while opening another (17-files §8).
- **Files:** `shared/files/{bytes.v1.json (new), README.md}`, `shared/policy/{links.v1.json, README.md}`, `src-tauri/src/files/{mod.rs, bytes.rs (new), scheme.rs (new)}`, `src-tauri/src/roots/{tree,read}.rs`, `src-tauri/src/{roots_commands.rs, lib.rs}`, `src-tauri/{tauri.conf.json, Cargo.toml, Cargo.lock}`, `src/engine/fileBytes{,.test}.ts` (new), `src/lib/{rootsIpc, rootsIpc.test, mockBytes, mockBytes.test, mockIpc, mockRoots, mockRoots.test, ipc, ipcContract.test}.ts` (mockBytes new; mockRoots.test added for root `0`'s text read), `e2e/boot.ts`, `src/detail/FilesField.tsx`, `src/views/{GalleryView, GalleryView.test, ViewSettingsPanel}.tsx`, `src/components/PageIcon.tsx`, `SECURITY.md`, `AGENTS.md`.
- **Approach:**
  - **Spike first** (roadmap risk): root resolution, the scheme for root `0`, its registration and the CSP line. Then stop until the owner runs packaged checks 1–4. Build the rest on a pass; on a fail, ask Q2 and wait.
  - **Addressing.** `cerebro-file://localhost/<root>/<rel>`, each segment percent-encoded. The adapter adds `?v=<opaque revision>` to invalidate WebKit decoded media across vault changes; only the shared bounded revision syntax is accepted, and it never selects a root. One helper, `bytes::root_dir(id)`, resolves every root: `0` is config.json's `lastVault`, read per request; any other id goes through `roots::find`. `locate` and roots_commands.rs' `root_path` both call it, so `read_file_text` and `list_dir` take root `0` too (.4b's FilePage reads vault text through them). No URL or command names a vault path. `roots/tree.rs` splits a typed `locate_within` (pub(crate); `Missing`, `Outside`, `RootUnavailable`) out of `resolve_within`, which keeps its signature and words. `roots/read.rs` exports `sniff`.
  - **`files/bytes.rs`:** `locate` (rel refusals, then `locate_within`; a folder or anything not a regular file refuses); `probe` (any size, from the first sniff bytes: size, MIME, kind, door, sniff and `open_policy`); `read_for_ipc` (only `bytes: ipc` rows, i.e. PDFs, at most 64 MiB). Refusal codes `no_such_root`, `bad_address`, `not_found`, `folder`, `outside`, `wrong_door` and `too_large`, with words from `bytes.v1.json`.
  - **`files/scheme.rs`:** a pure `serve(request, resolve)`. GET and HEAD only (else 405). A wrong scheme, host or address is 403, and so is outside. Missing or a folder is 404. It serves only `bytes: scheme` rows (images, audio, video); other rows get 403. One `bytes=` range answers 206 with an exact Content-Range, at most 1 MiB per answer.
