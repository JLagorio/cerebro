### M68.1 Scene core: JSON Canvas boards, pure commands, one-step gestures, per-item history, fragments, durable colours

- **What:** CANVAS-2. Under D14 (b) the scene IS JSON Canvas 1.0 (text, file, link and group cards; whole-number axis-aligned boxes; edges naming two cards) plus Cerebro extras (card shapes, ink): one geometry authority, no affine model. M53.20's no-DOM typecheck already covers `src/engine`; this part proves it.
- **Files:** `src/engine/scene/{model,limits}.ts`, `src/engine/scene/{colors,order,ink,board,commands,fragments,history,editor}{,.test}.ts`, `src/engine/scene/boundary.test.ts` (all new), `package.json`, `pnpm-lock.yaml`, `THIRD_PARTY_NOTICES.md`, `eslint.config.js`, `scripts/lint-rails.test.ts`, `AGENTS.md`.
- **Approach:**
  - **Deps (D0, Q3).** `pnpm add --save-exact perfect-freehand@1.2.3 fractional-indexing@4.0.0`. Notices take name, version, licence and text from each installed LICENSE and name the one file that loads it. `ENGINE_IMPORTS` admits both bare names, with a reason.
  - **Model and leaves.** Cards `text {text, shape}` (rectangle, ellipse, diamond), `file {file, subpath?}`, `link {url}`, `group {label?, background?, backgroundStyle?}`, each with id, z, box, color? and opaque `facts` (unknown keys and key order: carried, never read). Edges `{id, z, fromNode, toNode, fromSide?, toSide?, fromEnd?, toEnd?, color?, label?}`. Ink strokes `{id, z, box, points, size, simulated, color?}`, points as flat whole-number triples (x, y in tenths; pressure in thousandths). Maps by id, ItemKey `n:`/`e:`/`i:`; absent stays undefined. Durable colours are preset `1`–`6` or hex, written lower-case `#rrggbb`; never `var(--…)`. `order.ts` alone loads fractional-indexing (keys derive on read, never saved); `ink.ts` alone loads perfect-freehand (`strokeOutline` cached in a WeakMap, `inkContains`, `scaleStroke`). Limits: A1's values plus history 100, paste offset 24 and the fragment caps.
  - **Board and commands.** `paintOrder` (cards, edges, ink); `membersOf` (wholly inside a group, nested); `boardBounds`; `problemsOf` (dangling-edge, undrawable-color); `checkSet(before, after)`, strict only on what a change sets (new ids, whole-number boxes in limits, durable colours, existing ends for added or re-pointed edges, vocab). Commands `(board, payload, {createId})` give `{ok, board, label, …}` or a refusal in words: add and update cards, edges and ink; move (a group carries `membersOf`); resize (strokes scale); delete (a card's edges go in the same result, Q1); reorder; duplicate; paste. A no-op returns the same board; nothing throws or reads a clock or randomness.
  - **Fragments, history, editor.** A copy keeps edges with both ends (the rest counted); paste remaps every id (kind `cerebro-board-fragment` v1, ≤2,000,000 chars, ≤5,000 items). A history step holds changed items only; undo applies an item only while it still holds the side it leaves and names the keys it skipped; cap 100. `createSceneEditor(board, {createId})`: `execute`; `begin`/`preview`/`commit`/`cancel` (previews never touch the board; commit rounds, checks, drops removed cards' edges and records ONE step); `undo`/`redo`; `applyExternal` (one undoable step; cancels a gesture); selection as view state; `subscribe` (commit, undo, redo, external, cancel).
  - **Rails.** `boundary.test.ts` (TS compiler API): scene files import only `./` siblings and each library from its one file; no `Date`, `Math.random` or `crypto`; every file in tsconfig.engine.json's program. AGENTS.md: repo map; the next free CV (Appendix D).
- **Comments to delete:** the engine rail's message gains the two libraries.
- **Tests:** a table per module (colour classes; order inserts; ink dot vs polygon and caps; `membersOf` nested, half-overlap out; `problemsOf`; a moved card keeps a loaded `var(--x)` while setting one refuses; commands with a counter factory, no-op identity, refusals in words; fragment caps; history skips). editor.test: "one drag is one undo step"; cancel leaves no step; `applyExternal` is one step; deleting a card and its edges is one step that one undo restores. boundary: `the scene core imports only itself and its two upstream libraries`. lint-rails: `engine imports admit the two scene libraries and no subpath`.

## Appendix A — the board format (M68.2)

**A1. `format.v1.json`.** Two-space JSON, LF, one trailing newline, no BOM. Keys in order:

- `format` 1, `artifact_version` 1, `json_canvas` "1.0", `cerebro_versions` [1];
- `vocab`: node_types file, group, link, text; sides top, right, bottom, left; ends none, arrow; background_styles cover, ratio, repeat; color_presets "1"–"6"; shapes diamond, ellipse;
- `limits`: max_bytes 8388608, max_depth 32, max_id_chars 128, max_coord 1000000000, max_nodes 5000, max_edges 10000, max_strokes 2000, max_ink_points 16384, max_ink_size 64;
- `key_order`: board nodes, edges, cerebro · text id, type, text, x, y, width, height, color · file id, type, file, subpath, x, y, width, height, color · link id, type, url, x, y, width, height, color · group id, type, x, y, width, height, color, label, background, backgroundStyle · edge id, fromNode, fromSide, fromEnd, toNode, toSide, toEnd, color, label · cerebro version, cards, ink · card shape · stroke id, x, y, width, height, color, size, simulated, points;
- `layout`: indent "\t", trailing_newline false.

Both loaders refuse, in the same words: a format other than 1; an unknown or missing key; an empty vocab; a limit that isn't a positive integer; a key_order missing a type.

**A2. Reading,** the same order in both languages:

1. Over max_bytes is too_large; bytes that aren't UTF-8 are not_text.
2. A leading BOM is dropped and never written back; empty or whitespace-only is an empty board.
3. Strict RFC 8259: JSON whitespace only, depth ≤ 32, else not_json.
4. The top level is an object; `nodes` and `edges` are absent or arrays of objects, else not_board.
5. `cerebro` is absent, or an object whose `version` is a whole number in cerebro_versions; else `version` or not_board.
6. Cards: id 1–128 characters, unique among cards; type in vocab; x and y whole-number literals (no `.` or exponent) within ±max_coord; width and height 1..max_coord; text needs `text`, file a non-empty `file` (optional `subpath`), link `url`; group fields in vocab; color a string. Else invalid, worded "card {id}: …".
7. Edges: unique id; fromNode and toNode strings; sides and ends in vocab; color and label strings.
8. `cerebro.cards`: an object of objects whose `shape`, if present, is ellipse or diamond. `cerebro.ink`: strokes with a unique id, a card-like box, M68.1's point triples (within box × 10, pressure 0–1000, at most max_ink_points), size 1–64, `simulated` a boolean, color a string.
9. More cards, edges or strokes than the limits is too_large.

Non-fatal problems: a dangling edge is kept; a colour neither preset nor hex is kept; a card extra for a missing card is dropped and counted. Unknown keys anywhere are kept as minified raw JSON. A repeated key keeps first place and last value. A lone surrogate escape is refused in a known string and kept in an unknown value.

**A3. Writer layout** (TS from .2, Rust from .7): `{`, then one top-level member per line at one tab; `nodes` and `edges` hold one compact object per line at two tabs, or `[]`; `cerebro` holds one member per line at two tabs, each card extra and stroke on its own line at three tabs; `}`, no trailing newline. Keys keep their read order, then gained keys follow key_order; removed keys go. Known strings as JSON.stringify writes them; whole numbers plainly (-0 as 0); unknown values as minified raw text. A board gains `cerebro` only once it has extras, `version` first; orphan card extras aren't written.

**A4. `cases.json` and goldens.** A case is `{name, input}` (a string or a golden name). Readable cases give ok, counts, problems, texts, links, snippet, search and `canonical` (a string, a golden name or "same"); unreadable ones a reason and a refused fragment. Inline cases: truncated JSON, a top-level array, version 2, a duplicate card id, a fractional x, width 0, a text card without text, an unknown type, lone surrogates in text and in an unknown value, depth 33, a repeated key, a BOM, CRLF, an empty file, too many cards, control characters in text, -0 (.7 adds raw numbers, escapes and nested unknown keys). Goldens: `obsidian-layout` (all four card types, a coloured labelled edge), `extras-kept` (unknown keys at every level), `cerebro-v1` (shapes and ink), `dangling`, `pretty` (writes obsidian-layout bytes), `empty` (`EMPTY_BOARD`). Every golden opens in Obsidian. Twin row: Rust `src-tauri/src/canvas/read.rs::replays_the_shared_canvas_cases` (plus `write.rs::replays_the_shared_canvas_goldens` from .7), TS `src/engine/scene/jsonCanvas.test.ts`, held by `shared/canvas/cases.json`.

A card's `target` says whether its file exists: exists, missing, unchecked (outside what this run may read, so not looked up) or outside (not a path inside the vault). Then `edges`, the connections that touch the listed nodes: `id`, `fromNode`, `toNode`, optional `fromSide` and `toSide` (top, right, bottom or left), `fromEnd` and `toEnd` (none or arrow), `color` and `label`; an edge whose node is not on the board says `dangling`. - edit_canvas: "Change a whiteboard (a `.canvas` file) in one checked batch. `ops` holds 1 to 25 operations, applied in order to a copy of the board. `add_node` takes `type` (text, file, link or group), whole-number `x`, `y`, `width` and `height`, and its content: `text` (markdown), `file` (a vault path such as notes/plan.md, with an optional `subpath` starting with #), `url` (an http or https address) or a group's optional `label`; plus an optional `color` (a preset 1 to 6, or #rrggbb) and an optional new `id`, else one is made and reported. `update_node` takes an `id` and the fields to change; an empty string clears `color`, `subpath` or `label`, and a node never changes type. `add_edge` takes `fromNode` and `toNode`, ids of nodes on the board or added earlier in this call, with optional `fromSide` and `toSide` (top, right, bottom or left), `fromEnd` and `toEnd` (none or arrow), `color`, `label` and `id`. `update_edge` takes an `id` and the fields to change.
