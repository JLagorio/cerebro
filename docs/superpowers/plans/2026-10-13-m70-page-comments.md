# M70 — Page comments

**Goal.** Select text on a page and comment. Threads live in a sidecar beside the page, survive edits and never change its bytes. Agents comment by quote, and an @agent in a thread runs once and answers there.

## Parts

### M70.1 Spike: quote-and-occurrence anchors drawn as decorations, proven never to touch the page

- **What:** BlockNote's extension keeps comments in the document as marks. `createThread` calls `setMark`, resolving flips `orphan` in a doc-changing transaction, neither skips history, and the mark's `parseHTML` comes back on paste. The spike measures that route against hand-built ProseMirror decorations, lands the winner's editor half, and settles the sidecar location and the anchor space.
- **From Macro:** an anchor is an exact quote plus a 1-based occurrence; overlapping matches count; ambiguity is refused with a listing. Cerebro differs on purpose: marks never enter the page, and anchors re-resolve by context after every change.
- **Files:** `package.json`, `pnpm-lock.yaml`, `src/engine/commentAnchor{,.test}.ts` (new), `src/engine/quote{,.test}.ts`, `src/editor/{readerText,commentHighlights}{,.test}.ts` (new), `src/editor/commentSpike.test.ts` (new), `src/editor/{MarkdownEditor.tsx, MarkdownEditor.test.tsx, markdown.ts, editor.css}`, `e2e/{comment-anchors.spec.ts (new), boot.ts}`, `docs/superpowers/specs/2026-10-13-cerebro-m70-comments-spike-record.md` (new). `playwright.config.ts` only if M55.4 added the WebKit project (its Q6); the spec then joins it.
- **Approach:**
  - **The rule, fixed before measuring:** adopt `CommentsExtension` only if F2, F3 and F4 are all false. Read against 0.46.2's source, all three are true, so the expected outcome is hand-built decorations and no production import of `@blocknote/core/comments`. `commentSpike.test.ts` mounts the extension on an in-memory `ThreadStore` (no Yjs) and titles each fact F1–F5 (Appendix A).
  - **Pure anchors** (`engine/commentAnchor.ts`, inside M53.20's rails). `CommentAnchor {quote, occurrence, before, after}`, with limits of 1000 and 40 code points. `validMatches` keeps finder matches inside one block that don't split an atom. `anchorAt` trims, refuses empty and `spans_blocks`, cuts the quote, numbers the occurrence and takes context. `resolveAnchor`, in order: no valid match is gone; the stored occurrence with identical context; the unique best context score (common suffix with `before` plus common prefix with `after`); the stored occurrence among the best; otherwise ambiguous, with the count. Matching is M55.5's finder, exported as `occurrencesOf` with no behaviour change: no second matcher.
  - **Reader text** (`editor/readerText.ts`): every textblock in document order except code, joined by `\n`; a hardBreak is `\n`; a chip is an atom spelled by `chipText` (exported from markdown.ts unchanged); atom blocks add nothing. `posAt` and `offsetsOf` map both ways and refuse `outside_text`.
  - **Highlights** (`editor/commentHighlights.ts`, `createExtension`). One plugin whose state is a DecorationSet mapped through each transaction: classes `cb-comment`, `cb-comment-active` and `cb-comment-pending`, plus `data-thread`. The API .2b wires: `setThreads`, `setActive`, `setPending`, `anchorSelection`, `reveal`, `onSelect`, `resolveNow`, and a store of resolutions keyed by thread id (a missing id is unknown, never detached). Every dispatch is a step-less meta transaction: no onChange, no history entry, no save. It re-resolves 200 ms after a doc change, never while composing. MarkdownEditor passes `extensions: [CommentHighlights()]` and nothing else; editor.css uses tokens only.
  - **Dependencies:** `prosemirror-state ^1.4.4` and `prosemirror-view ^1.41.4`, BlockNote's own ranges (M55.6's prosemirror-history precedent). The lockfile keeps one copy of each, or our DecorationSet is foreign to BlockNote's view and highlights vanish with no error.
  - **Probe and record.** In browser mode only, `window.__cerebroCommentProbe {anchor(), show(threads), resolutions()}` (M55.6's seam precedent, typed in e2e/boot.ts). The record holds the fact table (claim → test); the measurements (chunk greps before and after `pnpm build`; `resolveNow` on 2,000 paragraphs with 50 anchors); the decision; the sidecar location, `<vault>/.comments/<page path>.json`, tracked (rejected: `.cerebro/` is gitignored for credentials, app-data leaves the vault, sibling files clutter the tree); the anchor space (Q2); the resolution rule; and the API.
- **Comments to delete:** markdown.ts's M52.1 reason "but it needs `prosemirror-view`, which is BlockNote's dependency and not the app's" (the decision stays); quote.ts's "internal" note on the finder, if exported.
- **Tests:**
  - commentAnchor: trims; refuses empty and cross-block; cuts at 1000 code points, an emoji counted once; numbers occurrences. Resolves an exact match, occurrence 2, a copy inserted before (moved), a deleted quote (gone), a deleted quote with a copy left that shares under half its context (gone), two copies tied on enough context (ambiguous, 2); skips a match ending inside an atom; `aa` in `aaa`; ties break the same way on every run.
  - readerText (headless): joins; code excluded; `[[kickoff]]` an atom spelled as written; table cells and toggle children in order; `posAt` round-trips; a selection across bold and a link in `Ship **the new** [pricing page](https://example.com) today.` reads `new pricing page today`; cross-block and code refused; an emoji keeps offsets right.
  - commentHighlights: one decoration per attached thread; set, active and pending keep `state.doc` and undoDepth; typing maps; deleting the quote detaches; an unset id is absent; the narrowest decoration wins a click; markdown is unchanged; a re-parse resolves the same span.
  - MarkdownEditor, "comment highlights stay out of the save (M70.1)": no onChange or onDirty past the debounce; undo keeps text and highlight; the unmount flush writes nothing; a `.cb-comment` span renders (one prosemirror-view copy); an `applyExternal` (M55.6) that rewrites the quote detaches after the delay, and one elsewhere keeps it.
  - commentSpike F1–F5. quote.test, only if exported: overlapping matches, and `quote-cases.json` replays unchanged.
  - e2e `comment-anchors.spec.ts`, on `delivery/how-we-schedule.md` seeded with "Owner: TBD.", "Deadline: TBD." and "We ship on Thursdays, after the freeze.": one `.cb-comment` holds "after the freeze" inside its paragraph; the bytes equal the seed 800 ms later; ⌘Z changes neither; the second TBD anchors as occurrence 2; Home and back keeps every highlight; typing "Also TBD." above keeps it on "Deadline: TBD."; deleting the quote reads gone within 1 s.
- **Acceptance:**
  - Roadmap risk (yjs and y-prosemirror) answered by measurement: both already ship, and the hand-built route adds neither.
  - Highlights never change the document, its undo history, its dirty state or its saved bytes, in jsdom and in Chromium.
  - An anchor survives a re-parse, picks the right copy of a repeated phrase by context, and detaches when its quote goes: the editor half of roadmap acceptance 1 and 2.
  - Every fact cites a passing test. The rule, its outcome, the sidecar location and the anchor space are written down.
  - No production file imports `@blocknote/core/comments`, and matching reuses M55.5's finder.

### M70.2 Comment sidecars: a Rust store mirrored in the mock, carried on rename and delete, with a watcher event

- **What:** nothing stores comments. `.cerebro/` is gitignored for credentials (`IGNORE_ENTRIES`, git/commit.rs). Scan, folder listing, note writers, the watcher and `clean_orphan_temps` all skip dot-folders. Roadmap M70.2 as one commit is XL, so it splits by its own bullets (M57.4's precedent): .2 is the data half, .2b the surfaces. No schema step, no refusal code (human IPC errors are plain strings, CV-03), no MCP tool.
- **From Macro:** a thread hangs off its entity, its id is its first message's, and deletes are soft, so a thread keeps its shape. Cerebro: one file per page, no accounts.
- **Files:** `src-tauri/src/vault/{comments.rs (new), mod.rs, write.rs, watcher.rs}`, `src-tauri/src/{lib.rs, runtime/vault_writes.rs}`, `src-tauri/fixtures/comment-cases.json` (new), `src/engine/comments{,.test}.ts` (new), `src/lib/{ipc,ipc.test,mockIpc,mockIpc.test,ipcContract.test}.ts`, `src/stores/commentsStore{,.test}.ts` (new), `src/detail/PropertyMenu.tsx`, `AGENTS.md`, `SECURITY.md`.
- **Approach:**
  - **Format v1**, the one format every later part writes. `<vault>/.comments/<page path>.json`, two-space JSON plus a final newline. Keys in order: file `{format, threads}`; thread `{anchor?, resolved?, deleted?, comments}`; comment `{id, author, created, body, deleted?, run_id?, state?, answers?}`; anchor `{quote, occurrence, before, after}`; stamp `{at, by}`. A thread's id is its first comment's. Ids are 16 lowercase hex, times RFC 3339 UTC to the second. `run_id`, `state` (pending, answered, failed) and `answers` (the comment a reply answers) are parsed, checked and kept here; .3 and .4 write them. Limits: body 10000, quote 1000, context 40 code points; file 1 MiB.
  - **Pure core**, twinned in `engine/comments.ts` and held by `comment-cases.json` (limits, paths, parse, ops, bytes; non-ASCII as `\u` escapes, CV-13). `parse_comments` checks conflict markers, then JSON, then format, then shape; the JSON pointer goes to the log (M53.24), never the message. `apply_op(file, op, ctx)` returns the new file, or None when nothing changes. Ops: Start `{anchor?, body}`, Reply, SetResolved `{resolved, closing?}`, DeleteComment, DeleteThread; ctx `{ids, now, by, run_id?, page}`. A reply reopens; resolving twice changes nothing; a delete empties and stamps; deleting the last live comment stamps the thread; a deleted thread takes no ops.
  - **Disk.** `comment_page` (`note_join` plus `is_file`, else "no note at {page}"). `read_comments`: absent is zero threads, unreadable is its reason, and no lock. `write_comment(vault, page, op, by, run_id)` runs a pub(crate) `rewrite(vault, page, f)`: `lock_paths [page, sidecar]` (M55.1), the page exists, parse (an unreadable sidecar refuses and is never overwritten), apply, write nothing if unchanged, check the size cap, `write_file`, then a `vault.write` row in vault_writes: the sidecar's vault-relative path (`.comments/<page>.json`), its sha256 and the actor. Not a new kind: v17's CHECK admits only write, rename and delete, and `record` drops a refused insert silently. Containment runs through `resolve`, so a `.comments` linked out of the vault is refused.
  - **Carry.** `rename_note_with(vault, from, to, remove)` locks both pages and both sidecars (the folder form for a folder), hands an orphan at the target to `remove`, moves the sidecar, renames the page, and moves the sidecar back if that fails. `delete_note_with` trashes the page, then its sidecar or mirrored folder; a failed sidecar step logs, and the delete stands. The public functions pass `trash::delete`. Empty `.comments` folders are pruned, and `clean_orphan_temps` walks `.comments/`.
  - **Events and IPC.** The watcher emits `comments-changed {pages | null}` (null: the OS dropped events, so every loaded page reloads) and never raises vault-changed for a sidecar; own writes stay silent. Six async commands, with `by` always `human:owner` (the webview never names an author): `list_comments`, `start_comment_thread`, `reply_to_comment_thread`, `set_comment_thread_resolved`, `delete_comment`, `delete_comment_thread`. ipc.ts adapters sit behind `inTauri()`, plus `listenCommentsChanged`. mockIpc mirrors Rust's order and words, keeps sidecars in the mock files Map, and carries them on rename and delete.
  - **Store and docs.** `commentsStore` keeps one slot per page: loading, ready, or unavailable with its sentence (CV-05). A reload keeps a ready slot on screen. `startThread` and `reply` return the new comment id; every action toasts once, reloads and returns null or false on failure (CV-03). A vault switch clears slots and drops late answers; one lazy listener reloads the named pages. AGENTS.md takes CV-31 and names comments.rs in the repo map; SECURITY.md gains its line; PropertyMenu's falsified sentence is rewritten (Appendix A).
- **Comments to delete:** write.rs's `clean_orphan_temps` "(skipping dot-directories, where `write_file` never writes)" and the test note that delete_note's happy path is "exercised manually … rather than polluting the developer's Trash"; the `rename_note` and `delete_note` docs gain the carry; watcher.rs's "emits `vault-changed` (unit payload)" and "emit one `vault-changed`" gain comments-changed; vault_writes.rs's module doc gains comment writes (as `vault.write`); ipc.ts's "listenVaultChanged is the one event here", if left; mockIpc's "'vault-changed' has no equivalent here" and deleteNote's doc; PropertyMenu's "**Comment** has no subsystem anywhere in this app…".
- **Tests:**
  - comments.rs: `replays_the_shared_comment_cases`, `the_limits_match_the_fixture`, `a_comment_never_touches_the_page_bytes` (bytes and mtime after every op), `the_scan_search_and_folder_list_never_see_a_sidecar`, `an_unreadable_sidecar_is_never_overwritten` (conflict markers, bad JSON, format 2), `a_comment_needs_a_markdown_note_that_exists`, `a_comments_folder_linked_out_of_the_vault_is_refused`, `two_comment_writes_on_one_page_both_land`, `a_comment_write_is_recorded_as_a_vault_write` (one `vault.write` row: the sidecar's path, its sha256, the actor), `a_file_past_one_mebibyte_is_refused`, `fresh_ids_never_repeat_in_a_file`.
  - write.rs, with a recording `remove`, so the OS Trash is never touched: a page and a folder carry their comments; a refused rename moves nothing; a failed rename puts the sidecar back; an orphan at the target goes first; deletes remove sidecars; no empty folder is left; orphan temps under `.comments/` are reaped. The escape and bundle-door tests pass unchanged.
  - watcher.rs: `a_sidecar_change_names_its_page`, `a_sidecar_is_not_a_vault_change`, `only_markdown_page_sidecars_count`.
  - vitest: comments (the cases; the limits; path round-trips; `visibleThreads`; `openThreadCount`; 1 MiB); mockIpc (Rust's words; no op touches the page; carry; never overwrites an unreadable sidecar; scan and folder list skip `.comments/`); ipc (six invokes with literal payloads; the listener binds only in Tauri); ipcContract (clean); commentsStore (absent is ready and empty; conflicted is unavailable with its sentence; new ids; one toast and a reload; a switch clears; late answers dropped; the listener reloads named pages, or all on null).
- **Acceptance:**
  - Every op leaves the page's bytes and mtime alone, and a re-read returns the same threads: the data half of roadmap acceptance 1.
  - Renames carry sidecars, of a page or a folder. Deletes send them to the Trash (Q4). A refused or failed rename moves nothing.
  - An outside change raises comments-changed naming its page. Own writes raise nothing, and a sidecar never raises vault-changed.

### M70.2b Comments tab and the page's Discussion: comment, reply, resolve, reopen, delete, deep links

- **What:** nothing renders threads. The side panel holds Outline, Info, Links and Knowledge (Details, Outline and Links on a concept). The doc Selection has no thread, and the toolbar has no Comment button. No Rust or IPC change.
- **Files:** `src/editor/{PageCommentsContext.ts (new), SelectionToolbar.tsx, SelectionToolbar.test.tsx}`, `src/detail/{usePageComments.ts, usePageComments.test.tsx, commentSections.ts, commentSections.test.ts, CommentsTab.tsx, CommentsTab.test.tsx, CommentThread.tsx, CommentComposer.tsx, DocSidePanel.test.tsx}` (new), `src/detail/DocSidePanel.tsx`, `src/stores/{uiStore,uiStore.test,navStore.test}.ts`, `src/pages/{DocPage,DocPage.test}.tsx`, `src/engine/{types,place,place.test}.ts`, `src/app/{useOpenPath.ts, useOpenPath.test.tsx}`, `e2e/comments.spec.ts` (new), `docs/superpowers/specs/2026-08-30-cerebro-m47-everything-is-a-page-design.md`.
- **Approach:**
  - **A thread is a Place.** The doc Selection gains `thread?`, a lens: placeOf drops it, placeKey and isPlace don't change, remapSelection keeps it through renames, and moving to another thread is a history step. DocPanelTab and ConceptPanelTab gain `comments`.
  - **Comment button.** `PageCommentsContext {start}`, provided only by DocPage. SelectionToolbar shows Comment after the AI group (`selection-comment`, message-square-plus), with mousedown prevented so the selection survives. The record peek (Q6) and read-only pages get none.
  - **`usePageComments(path, editor, {openPanel, deepLink})`** reads .2's slot and drives .1's API. Open anchored threads go to `setThreads` only when that set changes (by id and anchor); resolutions are null without an editor. `start` runs `anchorSelection`: a refusal toasts; otherwise it sets a draft and `setPending`, and opens the panel on Comments. `submitDraft`, `startDiscussion` and `reply` are the only posting paths, and each returns the new comment id (the seam .4 uses). ## Risks

- **Repeated phrases** (roadmap risk). Anchors re-resolve by context; a tie, a deleted quote, or a copy left elsewhere that shares under half the stored context moves the thread to Discussion, which quotes it and says why. One case context cannot see: a deleted quote whose block followed another copy hands that copy its context after, and when that side is half the stored context the thread attaches there, flagged moved (the spike record's Limit). An agent's occurrence counts in the body as get_note prints it, filtered as .3 says, so only an exact context tie with a copy hidden in markup the filter doesn't know (an HTML comment, say) can land differently.
- **yjs and y-prosemirror** (roadmap risk). Both already ship; the hand-built route adds neither. A BlockNote bump that splits the prosemirror-view or prosemirror-state copies stops highlights with no error, and MarkdownEditor's rendered-span test fails first. A bump that flips F1–F4 fails commentSpike, and the record says what to revisit.
- **Git merges** (roadmap risk). A conflicted sidecar reads unavailable and is never overwritten; Changes' keep ours or theirs resolves it. A pushed vault shares its comments (Q1).
- **Amends M47 §9 and M33b D8** (roadmap risk). .2b and .4 annotate both, dated, and delete neither.
- **Outside moves.** Finder or `git mv` leaves a sidecar behind, and a page later made at that path inherits its threads, usually in Discussion. A folder move can race a comment write into it (M55.1's open case).
