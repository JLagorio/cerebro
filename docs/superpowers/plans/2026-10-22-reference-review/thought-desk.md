# Thought Desk reference review

Date: 2026-10-22. Scope: the supplied `docs/examples/thought-desk-main` snapshot compared with the current Cerebro working tree, including the staged M84–M90 implementation. This is a source review: neither application was run, and no reference code was installed, edited, linted, or tested. Existing tests cited below were inspected, not rerun.

The reference identifies itself as Thought Desk `0.1.0`, Svelte 5/Tauri 2, and `AGPL-3.0-or-later` (`docs/examples/thought-desk-main/package.json:2–18`; `docs/examples/thought-desk-main/LICENSE:1–4`). No upstream commit identifier was established from this vendored snapshot. Recommendations describe behaviors and independently implementable designs; this plan does not propose copying its source.

Thought Desk's best contribution is a coherent personal-workspace journey tested against a deliberately large corpus: capture something, find it, place it on a calendar, open its page, and return without loading everything again. It is not evidence that Cerebro needs a different framework, storage model, or agent architecture. Thought Desk persists editor JSON in SQLite and a text copy in FTS5 (`docs/examples/thought-desk-main/src-tauri/src/db.rs:1–9`). Cerebro's Markdown files, pure engine, Rust write guards, shared vocabulary, provenance, and owned Claude CLI remain the design constraints.

No model-backed assistant, agent runner, MCP server, or knowledge-verification implementation was found in the reviewed reference entry points, dependencies, and feature modules. Its database automations are deterministic UI-driven rules. Its flashcards train a person's recall; they do not verify claims. Those distinctions matter when judging the requested agent and knowledge topics.

The reference has substantive Rust tests, including schema edits, trash/restore, synchronization and lean listings (`docs/examples/thought-desk-main/src-tauri/src/databases.rs:1328–1437,1449–1533,1598–1628`). Its package scripts expose Svelte checking/building but no frontend unit/E2E test command (`docs/examples/thought-desk-main/package.json:12–18`). The reviewed bench scripts are diagnostics, not a replacement for Cerebro's shared goldens, pure-engine tests, component tests and cross-browser journeys. Keep those stronger boundaries while adopting the workload discipline.

## Ranked findings and implementation plan

Sizes are engineering estimates, not calendar commitments: S = a contained seam, M = several coordinated modules, L = a cross-layer behavior or new persistent contract. Validation effort is included; native access and product decisions can dominate elapsed time.

### 1. Make mixed-workspace performance a repeatable release artifact

**Evidence.** Thought Desk's deterministic stress generator mixes a deep page tree, thousands of pages and files, assignments/events, trash, and unusually large pages containing tasks and flashcards (`docs/examples/thought-desk-main/src-tauri/src/stress.rs:24–50,116–191`). Browser scenarios measure table scrolling, page opening and post-navigation heap/DOM behavior (`docs/examples/thought-desk-main/bench/database.js:1–17`; `docs/examples/thought-desk-main/bench/pages.js:1–42`). `bench/helpers.js:12–30` records Long Tasks and action-to-render completion.

**Cerebro status.** Performance evidence already exists and must be the starting baseline. `docs/superpowers/plans/2026-10-17-m84-m90-implementation-record.md:101–118` records production p95 key-to-two-frame times of 398.8 ms for 1,000×12 and 1,376.2 ms for 1,000×24; 5,000×12 navigation timed out. The proposed input budget remains unmet. These are headless Chromium diagnostics, not native input-to-photon measurements. This is not an absence of testing; the missing depth is a durable, mixed-workspace workload that can protect later optimization.

**Plan and journey.** Build a Cerebro-owned deterministic generator outside `demo-vault`, with manifest, seed, scale and distribution parameters. Include 100/1,000/5,000 records, 12/24 fields, nested folders, malformed frontmatter, relations, formulas, comments, attachments, long prose and simultaneous open panes. Drive actual navigation: cold open → database → filter → edit/reject/retry → last row → open page beside → search → Back. Separate storage scan/read, query, React work, DOM/layout, and save time before selecting an optimization.

**Acceptance.** Store build hash, fixture hash, machine/browser/native details, warmup, every sample, p50/p95 and timeouts. Check row/cursor correctness and unexpected writes alongside timing. Record unavailable metrics explicitly. Do not copy the reference's best-of-N Rust timer (`stress.rs:194–202`), its `longestMs: 0` for no observed Long Tasks (`bench/helpers.js:17–19`), or a generic `.view` completion selector (`bench/views.js:3–4`). Require destination-specific readiness and keep native measurements separate. **Dependencies:** isolated fixture directory and reproducible production launch. **Size:** M; unlocks ranks 2 and 4.

### 2. Bound mounted table work without sacrificing navigation or drafts

**Evidence.** Thought Desk mounts an initial prefix then grows it near the scroll edge (`docs/examples/thought-desk-main/src/lib/progressive.svelte.ts:7–50`; `docs/examples/thought-desk-main/src/lib/db/TableView.svelte:89–110,735–753`). This reduces initial work but is progressive mounting, not bounded virtualization: visited rows remain mounted. Its selection implementation deliberately limits a jump to `lazy.limit + 500` to avoid freezing (`docs/examples/thought-desk-main/src/lib/db/TableView.svelte:138–149`). That tradeoff is not acceptable as Cerebro's final behavior.

**Cerebro status.** Cells and row bodies are memoized (`src/views/TableView.tsx:160–168,752`), column widths use CSS variables, and computed values are cached per schema (`src/engine/schema.ts:444–499`). Nevertheless, the table maps the full render-row list (`src/views/TableView.tsx:3178–3185`), and the recorded timings show the practical limit. Adding another memo wrapper is not an evidenced solution.

**Plan and journey.** Introduce a viewport row model that retains logical rows independently of mounted rows. Keep group bands, nested rows, wrapped heights, frozen columns, calculations and empty-group scaffolding explicit. Start with flat tables and a measurement spike for variable-height/grouped tables. Pin any row with an active editing lease; preserve its exact draft and validation status while it leaves the visible range. Keyboard End must target the actual final logical row, mount it, and reveal it; browser find and assistive navigation need a deliberate supported behavior.

**Acceptance.** At 5,000×24, verify bounded mounted DOM after repeated end-to-end scrolling, correct logical row counts/indices, stable selection after sorting/filtering, active-descendant targets that exist, and no draft loss. Reuse `src/views/TableView.test.tsx`, `src/views/TableCellChrome.test.tsx`, `e2e/grouped-table-polish.spec.ts`, and the rank-1 workload. The existing <100 ms input proposal is a target to prove, not a promise. **Dependencies:** rank 1; coordinate `src/views/useRowKeyboard.ts:292–363` and visit scroll restoration. **Size:** L.

### 3. Close native accessibility and save-lifecycle acceptance

**Evidence.** Thought Desk has extensive keyboard handlers, but the table focuses the grid while its selected cells are untabbable and its grid declaration provides no active-descendant binding (`docs/examples/thought-desk-main/src/lib/db/TableView.svelte:179–191,610–625,723–734`). The inspected modal declares `aria-modal` and handles Escape but contains no focus trapping/restoration (`docs/examples/thought-desk-main/src/lib/components/Modal.svelte:14–44`). These are source-level risks, not claims of a performed assistive-technology audit.

**Cerebro status.** Cerebro is stronger here: the grid binds active descendants and treats row/cell navigation explicitly (`src/views/useRowKeyboard.ts:284–363`); its shared dialog owns focus restoration and focus trapping (`src/components/ui/Dialog.tsx:67–105`). M84–M90 added persistent field status and passive corrections. Native WKWebView input/IME, VoiceOver, clipboard/drop, dialogs and pending/failed-save quit remain explicitly unaccepted (`docs/superpowers/plans/2026-10-17-m84-m90-implementation-record.md:125–132`). The gap is evidence, not a need to replace the component system.

**Plan and journey.** Complete the isolated packaged-app matrix before broadening UI scope: keyboard into a database → edit a frozen-column-adjacent cell → trigger validation → open/close a picker → switch pane → resume a draft → quit with pending and failed saves. Include VoiceOver reading order and announcements, 200% zoom, light/dark contrast, reduced motion, IME composition, and focus across assistant presentation changes. Add the virtualized variants when rank 2 lands.

**Acceptance.** Record versioned native evidence with expected/actual results and unresolved defects. Ensure every reported correction is available without hover, one Escape closes one owning layer, and save failure leaves recoverable content. Browser success must not close native acceptance. **Dependencies:** functioning access to the isolated native audit build; rank 2 for its new behavior only. **Size:** M with external validation uncertainty.

### 4. Reuse local search projections across keystrokes

**Evidence.** Thought Desk separates raw row values from reactive database versions (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:90–137`). Search builds normalized value text once per database/schema stamp, retaining it across query keystrokes while reading titles fresh (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:539–573,595–609`). This is a useful invalidation boundary; the large store's coupling to navigation, planner and UI (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:10–23`) is not an architectural model to transplant.

**Cerebro status.** Rust already keeps a stat-keyed corpus and rereads changed files (`src-tauri/src/vault/corpus.rs:143–188`). Frontend computed-field memoization already exists. The narrower opportunity is view search: `src/engine/viewFilters.ts:539–551` builds and lowercases each entry's title/type/path/searchable metadata haystack for each query. `src/pages/TypePage.tsx:232` and `src/pages/ListPage.tsx:93` memoize a result, but changing search naturally recomputes that work.

**Plan and journey.** Profile a user refining a filter one character at a time while another pane saves a record. If normalization is material, derive an immutable searchable projection per entry snapshot, using the existing `searchableFields` contract. Keep cache ownership outside pure selection algorithms or explicitly bound to immutable schema/snapshot lifetime. Invalidate on rename, metadata changes and vault switch; do not preserve a projection after permission/scope changes. Keep values and errors typed rather than replacing unknown values with empty strings for convenience.

**Acceptance.** Show reduced normalization work and input time under rank 1, with identical match/order results. Add mutation, deletion, relation, Unicode, malformed-field and vault-switch cases to existing `src/engine/searchable.test.ts`/filter suites. Confirm bounded cache lifetime. **Dependencies:** profiling evidence and stable entry identity; coordinate with the snapshot store rather than inventing a second content index. **Size:** M, reduced to S if identity already provides sufficient invalidation.

### 5. Add saved intake configurations on the existing composer

**Evidence.** Thought Desk's form view selects, orders and optionally requires properties, retains drafts on failure, and clears only after successful creation (`docs/examples/thought-desk-main/src/lib/db/FormView.svelte:23–87,89–115`). Its capture dispatch names the destination and offers an Open/Show action (`docs/examples/thought-desk-main/src/lib/capture.ts:87–122`). This connects capture to the eventual place without forcing navigation immediately.

**Cerebro status.** Generic capture, destination explanations and structured composition are present. Capture intentionally creates an untyped Inbox note (`src/lib/capture.ts:5–9,25–38`). The New launcher shows where each choice lands (`src/app/CreateLauncher.tsx:137–150`). `src/app/RecordComposer.tsx:23–59,94–124` already has typed drafts, defaults, similar-record search, validation, duplicate-submit protection and create-more behavior. A claim that Cerebro lacks a record form would be wrong. What is not represented in the view vocabulary is a reusable, explicitly configured intake view (`shared/schema/views.v1.json:5–15`).

**Plan and journey.** Add saved configurations for recurrent intake—e.g. “Log a customer interview” asks for three fields, applies chosen defaults and files under its host—using the existing composer and create-target logic. Keep Capture unstructured; offer the saved intake as another explicit New choice or host action. Start with local personal forms, not public web forms or inferred type routing. Show the saved destination before submit and an Open action afterward.

**Acceptance.** Create nothing on cancellation; create once on repeated Enter; retain all draft values on validation/I/O failure; preserve host relation, item key and inherited agents in the same write. Persist field order/defaults in a documented Markdown-compatible carrier, handle renamed/deleted fields explicitly, and test advisory schema versus form-only required fields. **Dependencies:** product agreement on persistence and form semantics; shared vocabulary changes only if promoted to a real view. **Size:** M.

### 6. Offer explicit date overlays across databases

**Evidence.** Thought Desk marks individual date properties for calendar inclusion and emits row+property identity (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:1849–1868`). Its day model combines events, assignment deadlines and those row dates (`docs/examples/thought-desk-main/src/lib/calendar.svelte.ts:97–143`); dragging a row routes through the property that placed it (`docs/examples/thought-desk-main/src/lib/calendar.svelte.ts:55–66`).

**Cerebro status.** Calendar month/week placement, scheduling gestures, recurrence, ICS import and My Work already exist. `src/views/CalendarView.tsx:94–109,147–161` resolves one date field for a presentation. My Work groups active records by declared deadline (`src/engine/myWork.ts:64–95`). The agent agenda already reads declared date fields across readable databases and explicitly declines to infer free time (`src-tauri/src/vault/agenda.rs:242–281,401–406`). Thus the opportunity is a human overlay view, not a new calendar backend.

**Plan and journey.** Let a saved calendar select explicit `(database, date field)` sources. A person can see an interview's scheduled time, a project's milestone and a work item's deadline together, with field labels distinguishing meanings. A record with two selected dates produces two identifiable placements. Begin read-only; enable drag only when the selected placement maps to one writable field and a supported recurrence operation.

**Acceptance.** Test two dates on one record, duplicate sources, hidden/unreadable fields, malformed dates, cross-midnight ranges, DST, recurring exceptions and navigation back to the original page. An unavailable source must say unavailable; “no events” must never imply availability. Preserve the shared TS/Rust date cases. **Dependencies:** a persisted source-selection contract, rank-1 measurement for dense weeks; preserve pull-only Home. **Size:** L.

### 7. Evaluate retrieval with realistic heterogeneous queries

**Evidence.** Thought Desk's palette finds database rows by values and names the matching property (`docs/examples/thought-desk-main/src/lib/components/SearchPalette.svelte:205–220`). Rust tests cover title prefix, body prefix, substring fallback, malformed query syntax and trash exclusion (`docs/examples/thought-desk-main/src-tauri/src/db.rs:1405–1428`). These are useful user intentions to test.

**Cerebro status.** This is mostly parity or a Cerebro advantage. Search includes metadata and relationships, excludes private agent-memory fields (`src-tauri/src/search.rs:355–402`; `src/engine/searchable.ts:21–67`), selects meaningful excerpts, and prefixes field matches with their key (`src-tauri/src/search.rs:676–701,1045–1071`). Quick Open renders safely highlighted text and reports capped search coverage (`src/app/QuickOpen.tsx:346–389,654–691`). It also shares ranking with agent search. Replacing this with FTS5 is unsupported by this review.

**Plan and acceptance.** Add a small reviewed query set over the mixed corpus: find a book by author, a task by relation target, an imported source by provenance, a phrase in a long page, and an ambiguous name. Record desired top results and excerpts, observed latency, and scope/cap explanations for human and agent calls. Include denied-scope documents, Trash and agent memory as negative cases. Extend existing search goldens and `e2e/quick-open-content.spec.ts`; do not introduce embeddings solely because another product has a search palette. **Dependencies:** rank-1 corpus and representative owner workflows. **Size:** S–M.

### 8. Explore deterministic record rules separately from agents

**Evidence.** Thought Desk exposes “when a row is added / property changes → set values” (`docs/examples/thought-desk-main/src/lib/db/AutomationsPanel.svelte:81–124`). Immediate field effects join the user's undo step (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:690–709`); change matching prevents unchanged values from firing (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:1156–1165`). However, URL/open/create effects are deferred callbacks (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:1112–1141`), and inspected Rust tests prove storage/sync of rule definitions, not frontend execution correctness (`docs/examples/thought-desk-main/src-tauri/src/databases.rs:1535–1595`).

**Cerebro status and plan.** Durable agent wakes, claims, leases and terminal outcomes are already substantially stronger (`src-tauri/src/runtime/wakes.rs:1–31`). Trigger editors already publish only on Done (`src/library/AgentProperties.tsx:941–993`). The optional gap is cheap, explicit record arithmetic such as “on completion, set completed date,” without a model turn. First establish repeated user demand. If justified, start with bounded same-record field actions, a pure preview and one guarded human batch with one undo step. Define whether API, editor, import and agent writes trigger rules before adding cross-record effects; do not silently inherit the reference's UI-only execution model.

**Acceptance.** Prove source edit and effects are atomic, no-op writes do not retrigger, cycles are bounded, preview equals committed changes, failure rolls back, and receipts distinguish the human action from derived changes. Never add a path around knowledge/provenance guards or map missing numbers to zero as the reference's `add` action does (`docs/examples/thought-desk-main/src/lib/databases.svelte.ts:1094–1096`). **Dependencies:** authority/persistence design, shared cases if Rust and TS both evaluate. **Size:** L; not a prerequisite for useful agents.

### 9. Keep personal recall distinct from knowledge verification

**Evidence.** Thought Desk has a small pure spaced-repetition scheduler (`docs/examples/thought-desk-main/src/lib/srs.ts:10–50`) and a study queue that limits new cards to 30 while keeping due reviews first (`docs/examples/thought-desk-main/src/lib/cards.svelte.ts:13–20,57–84`). This gives stored notes a deliberate reuse loop.

**Cerebro status and plan.** Cerebro's Review queue asks whether a claim is verified/current, not whether the person remembers it (`src/engine/okf.ts:941–960`). Verify binds the reviewed bytes and does not move agent-owned staleness dates (`src/knowledge/ConceptReviewBar.tsx:98–120`). No comparable flashcard scheduler was found in the reviewed app/engine modules. Treat recall as a separate optional capability, initially a small user-invoked study journey from selected pages. Keep question/answer material in documented Markdown carriers; decide explicitly whether personal scheduling metadata belongs in a sidecar or existing personal runtime state. An agent may draft cards through existing grants, but the person chooses to study and grades their recall.

**Acceptance.** A successful answer must never Verify a concept, alter support, or hide a stale claim. Bind cards to a source version; changed/deleted/superseded material must be surfaced before further study. Preserve drafts on save failure—the reference's `answer()` returns its calculated review even after save failure (`docs/examples/thought-desk-main/src/lib/cards.svelte.ts:87–96`), which should not become Cerebro's success contract. Test deterministic dates, undo and source changes before UI polish. **Dependencies:** validated learning use case and source-version identity. **Size:** L; defer behind reliability/performance work.

## Delivery sequence and exclusions

First publish the repeatable performance corpus and finish existing native acceptance. Next implement measured table/search optimizations, preserving editor leases and navigation contracts. Then trial saved intake on one real workflow. Evaluate overlays, deterministic rules and recall independently; each needs a product decision and its own scoped specification, not a single expansion milestone.

Do not transplant the student-specific Course/Assignment taxonomy, SQLite content authority, direct opener calls, large reactive database singleton, best-case benchmark claims, or progressive-list keyboard limit. Do not recreate the shell, title projection, record-as-page model, search excerpts, calendar basics, templates, or agent runtime already present. The highest return from this reference is dependable behavior under a realistic workload, followed by fewer steps between capture and an intentionally chosen destination.
