# Tolaria reference review against Cerebro

Review date: 2026-10-22. Scope: the local `docs/examples/tolaria-main` reference snapshot and the current Cerebro working tree, including staged M84–M90 work. This is a source review, not a fresh runtime benchmark or native acceptance pass. No reference or application code was changed, built, linted, or tested for this review.

Tolaria's most useful lessons are operational: make large documents and lists responsive, explain external CLI readiness before the first failed request, and ship usable product guidance alongside the assistant. Cerebro already has substantially deeper guarded knowledge, durable automation, source provenance, file policy, and write reconciliation. Adopting Tolaria's more permissive model would weaken those strengths.

## Provenance and comparison limits

The snapshot's [package manifest](../../../examples/tolaria-main/package.json) declares version `0.1.0` and `AGPL-3.0-or-later` at lines 2–5; its [LICENSE](../../../examples/tolaria-main/LICENSE) contains the AGPL v3 text. There is no `.git` directory in this snapshot, so this review does not assign it an upstream revision. Paths and line ranges below refer to the reviewed local bytes. Recommendations describe independently implemented behavior within Cerebro's architecture; provenance is recorded factually, not made into an additional approval gate.

**Classification:** “missing” means no corresponding implementation was found in the inspected production path; “depth” means an existing capability needs stronger behavior; “validation” means the implementation may already work but lacks comparable evidence; “parity/retain” means no new feature is justified by this comparison.

## Findings

### T1. Make performance budgets a repeatable engineering surface

**Classification: depth; priority P0; practices and architecture.** Tolaria records individual startup phases, including shell, snapshot, usable vault, restored note, editor module, editor interactivity, and background reconciliation in [`startupPerformance.ts`](../../../examples/tolaria-main/src/lib/startupPerformance.ts), lines 8–34 and 54–109. Its [editor benchmark](../../../examples/tolaria-main/scripts/editor-performance-benchmark.mjs), lines 23–49, 125–173 and 225–248, generates small/large documents, measures distinct stages, and can launch its own server. [Committed thresholds](../../../examples/tolaria-main/.editor-performance-thresholds.json), lines 1–82, separately budget parse/apply, first content, full application, edit frame, and note opening. The inspected CI and hook files did not establish that this benchmark is a mandatory gate; executable tooling is evidence, mandatory enforcement is not.

Cerebro already has unusually honest evidence: the [M84–M90 implementation record](../2026-10-17-m84-m90-implementation-record.md), lines 93–123, distinguishes production diagnostics from development timings and records unmet targets. At 1,000 records, p95 key-to-two-frame time is 398.8 ms for 12 fields and 1,376.2 ms for 24; 5,000×12 navigation timed out. These are headless Chromium measurements, not native input-to-photon results. The gap is turning this one acceptance exercise into a maintained budget with phase attribution.

**Plan:** retain the existing fixtures and methodology, add marks at scan, data derivation, render, first visible row, editor parse, editor mount, and ready-to-edit boundaries. Store machine/build/sample metadata and missing measurements explicitly. Run an isolated production benchmark lane for changes touching these paths. Track both p50 and p95, repeated samples, long-task counts, and retained DOM/memory; do not compare Tolaria's absolute numbers to Cerebro's. Gate on Cerebro's existing proposed budgets and ratchet improvements. Native acceptance remains its own requirement.

### T2. Reduce rendered list size while preserving navigation and accessibility

**Classification: missing bounded rendering in inspected paths; P0; architecture and UX.** Tolaria's [`NoteListViews.tsx`](../../../examples/tolaria-main/src/components/note-list/NoteListViews.tsx), lines 62–110, renders its ordinary list through Virtuoso with overscan. [`useNoteListKeyboard.ts`](../../../examples/tolaria-main/src/hooks/useNoteListKeyboard.ts), lines 18–44 and 181–218, caches item lookup maps and coalesces repeated opens to the next frame. This shows coordinated data, keyboard, and rendering decisions rather than a CSS-only optimization. It does not establish that Tolaria's grouped entity view is virtualized: lines 31–47 still map groups normally.

Cerebro's [`PagesPage.tsx`](../../../../src/pages/PagesPage.tsx), lines 252–285, maps every shown page; [`TableView.tsx`](../../../../src/views/TableView.tsx), lines 3178 onward, maps every built row. Its implementation record explicitly says ordinary DOM was retained after `content-visibility:auto` omitted an offscreen record from Chromium's accessibility tree. That finding must constrain the next attempt.

**Plan:** first address inexpensive selectors, derived-field evaluation, and changed-row subscriptions, using T1 to identify actual costs. Then prototype bounded rendering against the same 1,000/5,000 fixtures. Treat logical row index, offscreen keyboard targets, selection, frozen columns, group headers, variable-height wrapping, active draft retention, error anchoring, and browser find as acceptance requirements. If a virtual list cannot preserve the established accessibility/find contract, use explicit pagination or another reviewed alternative instead of silently dropping it. A library adoption alone is not completion. Keep four-pane visit state and scroll restoration intact.

### T3. Add bounded warm editor reads only where repeated opens justify them

**Classification: missing in inspected editor-open path; P1; architecture.** Tolaria separates file content and parsed-block caches. [`noteContentCache.ts`](../../../examples/tolaria-main/src/hooks/noteContentCache.ts), lines 11–55, 118–174 and 310–352, caps the cache at 24 entries/8 MiB, limits each retained file to 1 MiB, limits background requests to four, removes failed entries, and starts foreground requests ahead of queued prefetch. [`editorParsedBlockCache.ts`](../../../examples/tolaria-main/src/hooks/editorParsedBlockCache.ts), lines 12–80, caps six parsed documents/3 MiB of source and checks exact source equality before reuse. These are different retention budgets for different costs.

Cerebro's [`NoteBodyEditor.tsx`](../../../../src/editor/NoteBodyEditor.tsx), lines 238–276, reads the note for each path/generation load, while [`MarkdownEditor.tsx`](../../../../src/editor/MarkdownEditor.tsx), lines 781–804, reparses and serializes the initial value. Cerebro's Rust search corpus cache is already present; that does not make editor parsing warm. Conversely, mounted panes already preserve live editors, so adding a second cache for those instances would waste memory.

**Plan:** benchmark cold open, close/reopen, Back/Forward, and four-pane navigation first. Introduce only a disposable cache for closed clean documents, keyed by vault identity, path, content identity, parser/schema version, and source bytes. Invalidations must cover external writes, renames, undo, imports, vault switches, permission changes, and failed reads. Never retain a rejected promise. Foreground reads bypass speculative queues. Compare warm latency and memory before keeping it; document hashes and conservative invalidation are preferable to copying Tolaria's mtime/length assumptions. Unsaved drafts remain owned by the existing editor lifecycle.

### T4. Large-document rendering needs cancellation and a complete-document readiness boundary

**Classification: missing progressive initial mount; P1; architecture and UX.** Tolaria's [`editorContentSwapApply.ts`](../../../examples/tolaria-main/src/hooks/editorContentSwapApply.ts), lines 15–17, 127–161 and 200–242, applies large documents progressively: 48 initial blocks, then 120 per animation frame after a 320-block threshold. It locks editing and suppresses change emissions until the full commit. Its [tests](../../../examples/tolaria-main/src/hooks/editorContentSwapApply.test.ts), lines 98–190, cover locking, recovery, and aborting without committing the partial document. [`editorFastMarkdownBlocks.ts`](../../../examples/tolaria-main/src/hooks/editorFastMarkdownBlocks.ts), lines 623–650, also has an off-thread parser path and fallback.

Cerebro's initial `markdownToBlocks` → whole `replaceBlocks` → round-trip serialization sequence in `MarkdownEditor.tsx`, lines 781–818, is a clear profiling boundary. It also establishes the lossy-import baseline and protects readiness until listeners exist. Its [`NoteBodyEditor.tsx`](../../../../src/editor/NoteBodyEditor.tsx), lines 207–218, keeps lossy imports read-only until explicit adoption. Those guarantees are more important than an early paint.

**Plan:** separate parse latency from DOM application latency. Prefer moving existing pure transforms off the UI thread or chunking application over inventing a second Markdown grammar. Prototype with tables, custom carriers, sheets, citations, unknown blocks, and projected titles. Cancel by vault/path/generation; a partial document must never become editable, autosave, enter undo history, or report “ready.” Preserve stable metadata portals and external-write reconciliation. Accept only after semantic round-trip equivalence, no unexpected writes on mount, successful quit during load, and measured improvements in both browser engines and packaged WKWebView.

### T5. Profile startup phases before introducing stale startup snapshots

**Classification: architectural difference; validation first; P2.** Tolaria's [`useVaultLoader.ts`](../../../examples/tolaria-main/src/hooks/useVaultLoader.ts), lines 102–166, can present a startup snapshot, then apply background reconciliation while loading chrome independently. Its Rust [`vault/cache.rs`](../../../examples/tolaria-main/src-tauri/src/vault/cache.rs), lines 22–26 and 51–88, versions cached entries and distinguishes missing, invalid, unreadable, and concurrent-update outcomes. This can reduce perceived boot time, but Tolaria's reconciliation failure at loader lines 138–147 is largely a console warning; that presentation is not suitable for Cerebro.

Cerebro's [`vaultStore.ts`](../../../../src/stores/vaultStore.ts), lines 184–194 and 323–375, waits for scan, collections, folders, watcher setup, and recovery handling before declaring ready. [`corpus.rs`](../../../../src-tauri/src/vault/corpus.rs), lines 10–18, explicitly leaves the scanner uncached so stale data cannot hide trigger-relevant changes. It already handles scan tickets, writes during startup, and interrupted-batch rollback.

**Plan:** instrument T1 first and move only independent, nonessential work off the critical path. A provisional browse-only snapshot is a later experiment if actual vault sizes justify it; it must never drive triggers, grant checks, verification, destructive actions, or “ready” claims. Show freshness and failed reconciliation explicitly. Keep the canonical scan and existing write fence authoritative. This is not a recommendation to add a persistent search index or make cached metadata the source of truth.

### T6. Treat Claude Code readiness as one recoverable state shared by Settings and chat

**Classification: depth plus a verified inconsistent failure presentation; P0/P1; agent workflow and onboarding.** Tolaria's [`AiAgentsOnboardingPrompt.tsx`](../../../examples/tolaria-main/src/components/AiAgentsOnboardingPrompt.tsx), lines 37–61, 89–125 and 178–238, explains checking, missing, installed versions, installation links, and deferred setup. [`useAiAgentsStatus.ts`](../../../examples/tolaria-main/src/hooks/useAiAgentsStatus.ts), lines 14–24 and 56–111, defers optional discovery and bounds the frontend wait. However, its timeout and error map to “missing”; do not reproduce that conflation.

Cerebro already discovers the user's CLI through multiple installation locations and login-shell PATH handling. [`agent/mod.rs`](../../../../src-tauri/src/agent/mod.rs), lines 1136–1305, is substantive existing infrastructure. [`ClaudeCodeRow.tsx`](../../../../src/pages/ClaudeCodeRow.tsx), lines 9–38 and 55–79, correctly separates failed checking from missing installation and reports path/version. But [`AiPanel.tsx`](../../../../src/agent/AiPanel.tsx), lines 1010–1014, converts any rejected check into `installed: false`; lines 1534–1554 then tell the user to install and reopen. Both consumers check once on mount, so a successful setup outside the app has no obvious coordinated refresh.

**Plan:** use a shared `checking | available | missing | unavailable` state, bounded native probes, explicit retry, and refresh when returning from setup. Keep installation guidance, detected executable/version, and CLI-owned login guidance together. Do not infer authenticated readiness from `--version`; retain the existing typed runtime failure cards for sign-in/account failures. Offer “set up later” without blocking the vault. Test hung probe, inaccessible executable, PATH change, install while open, and failed check. No multi-provider picker, app-held API keys, or automatic installation is implied.

### T7. Ship task-oriented product documentation the assistant can retrieve on demand

**Classification: depth; P1; agent workflows and knowledge.** Tolaria's [`build-agent-docs.mjs`](../../../examples/tolaria-main/scripts/build-agent-docs.mjs), lines 103–164 and 167–195, generates a local docs map, searchable headings, section bundles, and individual pages from the human documentation source. [`ai-agent.ts`](../../../examples/tolaria-main/src/utils/ai-agent.ts), lines 43–61 and 88–99, tells the assistant where to look for product behavior. This is real wiring, not merely a docs directory. The snapshot's [`agent-instructions.js`](../../../examples/tolaria-main/mcp-server/agent-instructions.js), lines 5–22, separately exposes vault conventions.

Cerebro already centralizes model-facing product descriptions and server instructions in [`shared/prompt/README.md`](../../../../shared/prompt/README.md), lines 10–12, and provides an opt-in starter vault. Agent Instructions/Runs/Memory already exist in [`AgentPage.tsx`](../../../../src/library/AgentPage.tsx), lines 13–24 and 65–79. The missing depth is a discoverable, versioned “how to do this in Cerebro” corpus, rather than more automatic memory or another long system prompt.

**Plan:** write short guides for source capture → cited concept → human verification, task assignment → pending approval → run history, import → edited-copy conflict, schedules → missed/failed runs, and CLI/connector recovery. Generate a bounded help catalog from the same source used by human help. Expose selected content through a read-only capability within existing tool/policy rules; do not grant general filesystem access merely to read help. Version the bundle with the app and test example commands against the shipped manifest. Give the model topic/path provenance and preserve the distinction between product rules and untrusted vault content. Validate usefulness with representative setup and knowledge tasks.

### T8. Extend writing acceptance to IME and bidirectional content

**Classification: validation plus missing explicit bidirectional behavior in inspected styles; P1; UX and practices.** Tolaria's [`imeCompositionKeyGuardExtension.ts`](../../../examples/tolaria-main/src/components/imeCompositionKeyGuardExtension.ts), lines 7–54 and 56–103, accounts for DOM composition flags, key code 229, ProseMirror composition state, and the paragraph event after composition ends. Its [Korean list test](../../../examples/tolaria-main/tests/smoke/korean-list-ime-composition.spec.ts), lines 46–98 and 100–147, checks that composing Enter/Space does not split nested lists. [`EditorTheme.css`](../../../examples/tolaria-main/src/components/EditorTheme.css), lines 29–49, explicitly uses per-block direction and logical spacing; its [RTL test](../../../examples/tolaria-main/tests/smoke/rtl-editor-direction.spec.ts), lines 67–135, covers Arabic/Hebrew paragraphs, lists, tasks, quotes, and table cells.

Cerebro already ignores composition in [`keys/root.ts`](../../../../src/lib/keys/root.ts), line 113, and protects the filename fallback and title projection. That is parity for shell commands, not proof of editor-internal input correctness. The M84–M90 record, lines 125–132, explicitly leaves native IME and VoiceOver acceptance open.

**Plan:** add Arabic/Hebrew mixed-direction and Korean/Japanese/Chinese composition journeys through title, nested list, table, link picker, and save/reopen. Confirm logical selection and caret behavior, not just displayed glyphs. Use logical padding/border/alignment where defects are reproduced. Browser-dispatched composition events are a useful regression harness but cannot close native IME acceptance. Do not copy Tolaria's 500 ms suppression window without a reproduced event sequence on Cerebro's pinned editor; an overbroad workaround can swallow an intentional Enter. Full application translation is a separate product decision.

### T9. Improve name discovery with controlled normalization; retain the stronger corpus search

**Classification: small depth gap in name matching; retain existing full-text architecture; P2.** Tolaria's [`useNoteSearch.ts`](../../../examples/tolaria-main/src/hooks/useNoteSearch.ts), lines 77–114 and 124–151, normalizes diacritics and filename-shaped queries while prioritizing exact title/alias matches. Its [tests](../../../examples/tolaria-main/src/hooks/useNoteSearch.test.ts), lines 50–85, cover filename punctuation, “Cafe” finding “Café,” and punctuation-only queries. Cerebro already has a common name ranker and recent-open weighting in [`nameRank.ts`](../../../../src/lib/nameRank.ts), lines 1–26 and 137–175; [`quickOpenScore.ts`](../../../../src/lib/quickOpenScore.ts), lines 21–34, lowercases but does not strip combining marks.

**Plan:** add a named multilingual retrieval fixture set before changing ranking. Consider accent-insensitive fallback below exact spelling, canonical Unicode equivalence, filename queries, duplicate titles, and mixed-script names across every picker. Keep displayed spelling and identifiers unchanged, and never merge distinct paths because normalized labels coincide. Measure top-result quality and negative cases, including titles whose accents distinguish meaning.

Do not mistake reference design filenames for implementation: Tolaria's current [`search.rs`](../../../examples/tolaria-main/src-tauri/src/search.rs), lines 98–115 and 175–236, reads files and uses substring scoring; its entry point accepts an unused `_mode` at lines 118–130. Cerebro's [`search.rs`](../../../../src-tauri/src/search.rs), lines 15–26 and 38–56, already has field-weighted BM25 over a stat-keyed corpus. This review provides no evidence for replacing it with vectors or a persistent content index. Scale/tokenization measurement is the next justified search investment.

### T10. Preserve Cerebro's source/file and knowledge boundaries; improve workflow evidence

**Classification: parity/retain, with validation work; P1.** Tolaria supports portable attachment paths and rejects traversal in [`vaultAttachments.ts`](../../../examples/tolaria-main/src/utils/vaultAttachments.ts), lines 156–174 and 190–217; editor clicks are routed by [`editorAttachmentActions.ts`](../../../examples/tolaria-main/src/components/editorAttachmentActions.ts), lines 98–124. Cerebro already has shared file-kind policy, bounded import naming, reused-file outcomes, and root-anchored links in [`attachments.ts`](../../../../src/engine/attachments.ts), lines 12–60, plus descriptor-bound native actions in [`file_actions.rs`](../../../../src-tauri/src/shell/file_actions.rs), lines 1–5 and 93–135. There is no missing generic attachment feature here.

Similarly, Tolaria's assistant preamble favors direct file edits (`ai-agent.ts`, lines 77–86); Cerebro's [`knowledge.rs`](../../../../src-tauri/src/knowledge.rs), lines 1–26, enforces human-only verification and closed concept-writing doors. Durable wakes, claims, leases and outcomes are already implemented in [`runtime/wakes.rs`](../../../../src-tauri/src/runtime/wakes.rs), lines 1–31. Do not replace these with prompt-only permissions or a second workflow engine.

**Plan:** adopt the spirit of Tolaria's real-file journey tests: [`vault-workflows.spec.ts`](../../../examples/tolaria-main/tests/integration/vault-workflows.spec.ts), lines 89–155, verifies creation and rename on disk. Its [`fixtureVaultDesktopBridge.ts`](../../../examples/tolaria-main/tests/helpers/fixtureVaultDesktopBridge.ts), lines 13–26, injects mock Tauri globals; therefore this is not native Rust/WebView proof. For Cerebro, add targeted native disposable-vault journeys covering attachment import → reopen → reveal/copy, source refresh → citation review, external editor save → reconciliation, and pending-save quit. Assert disk bytes, receipts/outcomes, and user-visible state. Preserve D2 human-save semantics, no mail send, and scoped extraction throughout.

## Delivery sequence and acceptance

1. **P0: establish the regression baseline and close known misleading states.** T1 creates one reproducible production performance entry point; T6 aligns chat and Settings failure semantics and adds retry. Use existing M84–M90 evidence without declaring outstanding native checks complete. Output: recorded baseline, classified bottlenecks, bounded readiness state and focused tests.
2. **P0/P1: tackle the measured interaction bottleneck.** T2 prototypes bounded rendering only after selector/render attribution. Output: 1,000-row input under the existing proposed 100 ms budget, measured 5,000-row navigation, and all existing AX/find/editing contracts retained. If the contract prevents a candidate optimization, document the result and select another approach.
3. **P1: improve editor opening with independent experiments.** T3 cache and T4 progressive application are separable changes. Keep only measured wins; budget memory and verify cancellation, lossy import, title projection, metadata continuity, save, undo and external reconciliation. Do not bundle a parser rewrite with visual polish.
4. **P1: make complex capabilities learnable and provable.** T7 ships versioned help journeys; T8 and T10 extend native evidence. Acceptance is successful end-to-end work with correct disk state, not additional screenshots or a larger test count.
5. **P2: refine only after measurement.** T5 startup snapshots remain conditional on a demonstrated startup bottleneck. T9 normalization follows retrieval fixtures and preserves exact-match priority. Neither requires changing Cerebro's knowledge format, navigation model, source of truth, or CLI ownership.

The recommended investment is a smaller set of deeper capabilities: responsive scale, reliable readiness/recovery, guided knowledge workflows, and native writing confidence. Tolaria's numerous features do not justify redoing Cerebro's new shell, title system, guarded knowledge architecture, durable scheduler, or file-policy boundary.
