# M99 selected-authority consumer matrix

Inspected 2026-10-23; bounded consumers reconciled 2026-10-26 against the shared implementation branch. The selected
architecture is [SQLite metadata plus visible Markdown](../specs/2026-10-23-m99-workspace-authority-decision.md).
This is a call-site inventory and cutover checklist. A bounded selected adapter now
serves explicitly selected disposable workspaces through actual scan/read, canonical
search/source locations, finite semantic reads, human body editing and bounded
metadata fields. Body edits use the existing paired journal; metadata.patch uses
its own schema4 durable original-request evidence and complete-version CAS;
default unregistered workspace authority remains Markdown/YAML
and the guarded knowledge ledger. No real vault conversion or active registration
is authorized by this document.

## Dispositions and present state

- **Selected adapter required — unimplemented**: replace the named read/write
  with a canonical body/metadata revision operation before activation.
- **Typed refusal required — unimplemented**: until that adapter exists, the
  named legacy entry point must refuse the selected format before reading,
  writing or deriving permission. A format marker helper alone does not do this.
- **Retained codec — dispatch unimplemented**: preserve the existing authority
  and exact bytes; add an explicit selected-format dispatcher rather than run the
  ordinary metadata converter on it.
- **Inactive library only**: callable native staging code exists; no application
  consumer, registration, permission or live mutation is implied.

The verified bounded slice is listed next. The remaining rows retain their
unimplemented or incomplete disposition; passing one reader does not adopt every
Entry consumer. Already released clients remain unsupported after a future deliberate
cutover; an on-disk marker cannot prevent their filesystem access.

## Inactive implementation and remaining gates

`workspace_migration/stage.rs::{prepare_stage, stage_conversion, open_staged,
validate_cutover}` and `selected_sqlite.rs::{create, read}` are inactive libraries.
They validate bounded complete dispositions, originals, private exclusions,
separate SQLite destination, stage markers and stale discovery. The semantic
producer is a native candidate against checked inventory plus consumed identity
planning; its review packet records the exact tests that pass. The bounded adapter described above is separate from these inactive staging libraries;
neither staging publication nor an identity plan grants semantic permission.

Before activation, every row needs a reviewed adopted adapter, retained dispatcher,
or tested typed refusal at the actual call path. Keep the library activation
blockers until their separate acceptance is complete: adopted production semantic
producer, governed codec/ledger semantics, consumer matrix integration,
coordinated crash recovery, complete backup/restore rehearsal and minimum-client
release. Packaged native cutover/reopen/rollback and the shared release gate remain
required. Inactive staging itself supports none of active registration, complete backup
adoption or current-vault migration. Full width and the finite schema4 declared-field
metadata.patch kinds above are implemented; other scalar/structured kinds and
general writers remain open. Selected human body/checklist/TitleCell saves use the
paired journal and acknowledged whole version. Explicit fresh schema4 staging does
not adopt a current schema3 upgrade, activation or historical lease resumption.
