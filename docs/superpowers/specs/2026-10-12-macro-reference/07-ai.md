## 1. What it is

- A Rust tool framework (`crates/ai_toolset`) plus a composition root (`crates/ai_tools`) that builds **one typed
  toolset and one matching prompt per host** (`AiHost`: Chat, AgentSession, ChannelBot, Mcp) from const prompt
  sections (`crates/prompt`).
- DCS (`services/document_cognition_service`) runs chat turns: admission → persist → per-user memory → agent loop
  (rig-core via `crates/agent`) → durable Redis stream (`crates/stream`) → websocket → SolidJS buffered renderer.
- Around it: skills (markdown docs + code-defined system skills), a judge-gated per-user "unified memory", cached AI
  projections, generative UI (DisplayResults), a Cloudflare AI-editing worker, and heavy SaaS metering/billing.
- **Misfiled**: `crates/ai_engine`, `apps/web/src/lib/core/ai-engine`, `apps/web/src/features/block-ai` are an Adobe
  Illustrator (.ai) engine/editor, not AI. Route to files/canvas; excluded here.

## 3. How it's built

### Overview

- Hexagonal Rust crates + Axum services on AWS; SolidJS web app.
- **Tools**: `ai_toolset` is the framework (never edited per tool, `crates/ai_toolset/CLAUDE.md`). Domain crates own
  tools in `crates/<x>/src/inbound/toolset`. `ai_tools::tools_for(AiHost)` assembles toolset + host prompt +
  deferred catalogue; duplicate names panic at assembly.
- **Hosts**: chat in DCS (`services/document_cognition_service/src/server.rs`), channel bot in DSS
  (`services/document_storage_service/src/server.rs`), MCP (`services/mcp_service/src/main.rs`), agent sessions
  in-process.
- **Model execution**: `crates/agent`, rig-core 0.41 router over Anthropic/OpenAI/Google/Cerebras/Fireworks
  (`crates/agent/src/model/router.rs`). Outside this unit set; not mapped. `crates/anthropic` only powers server-tool
  wrappers.
- **Persistence/streaming**: chat in `crates/chat` (Postgres); `crates/stream` (Redis Streams + Postgres
  `active_streams`) delivered by connection_gateway websockets. Memory, projection, usage, MCP and Pipedream routers
  mount into DCS (`services/document_cognition_service/src/api.rs`).
- **Metering**: every AI call records `UsageEvent{feature,user,entity,model,amount}` (`crates/ai_usage`) and passes
  `AiAdmissionService` before work (`crates/ai_billing/src/domain/admission.rs`).
- **AI editing**: separate TS Cloudflare Worker on the Vercel AI SDK (`services/ai-editing-worker`).

### Key flows

**Chat turn** (`services/document_cognition_service/src/api/stream/chat_message.rs`)
1. Composer POSTs `{content, model, speed, chat_id?, attachments, toolset, additional_instructions}`
   (`apps/web/src/lib/core/component/AI/component/input/buildRequest.ts`).
2. Entitlement 403 → speed 400 → edit permission → **admission 402/503 before any durable state**.
3. Create chat if needed; store user message + attachment snapshot; spawn rename.
4. System prompt = host tools prompt + additional instructions + `<user_memory>`; register Redis cancel channel
   (`services/document_cognition_service/src/service/ai_stream_registry.rs`).
5. Return `{stream_id, chat_id}` at once; background AgentLoop → `StreamAccumulator` → Redis Stream (3 min idle,
   30 min cap); first item echoes the user message.
6. Assistant message persisted **only at stream end**; unmatched tool calls closed as `ToolCallErr "cancelled"`.
7. Client subscribes via gateway; `bufferedStream` drips, holds partial `<m-…>` tags; `AssistantMessageParts` renders.

**Define a tool once → every host**
1. Struct with `#[schemars(title, description)]` + `ToolAnnotated` (missing const = compile error) +
   `AsyncTool<Ctx>`, `Ctx: FromRef<ToolServiceContext>` (`crates/ai_toolset/src/toolset/types.rs`).
2. `tools_for(host)` adds it (`crates/ai_tools/src/lib.rs`).
3. Schema pipeline: inline subschemas, oneOf→anyOf, strip provider-rejected keywords into the description, validate
   (no recursion/maps/non-primitive enums) (`crates/ai_toolset/src/schema/generate.rs`).
4. Non-`EAGER_TOOLS` listed by first sentence; LoadTools/SearchTools load for the next turn; Mcp defers nothing
   (`crates/ai_tools/src/deferred.rs`, `.../search_tools.rs`).
5. Dispatch via `ToolSet::try_tool_call` in an execute_tool span; `ToolCallError.description` returned to the model.
6. MCP maps annotations to hints (`services/mcp_service/src/tool_service.rs`).
7. `gen_tool_schemas` → `tools.json` → `apps/web/scripts/generate-dcs-tools.ts` → TS/Zod → exhaustive
   `ToolHandlerMap` forces a renderer per tool.

**Memory** (`crates/memory/src/domain/service.rs`)
1. `get_or_generate_memory` returns the latest row immediately.
2. Missing or >24h (env ≠ Local) → spawn generation.
3. AgentLoop (Smart model, full Chat toolset) with `<user_id>`, `<datetime>`, `<previous_memory>` baseline.
4. Keep only the last `<memory>…</memory>`; empty → NoGeneration.
5. Judge returns `{accepted, reason}`; rejects thin/speculative/narrated profiles.
6. Upsert; usage booked to exempt `AiFeature::Memory`.

**Projection**
1. Client POSTs definition (`apps/web/src/lib/queries/ai/projection.ts`); `prompt_hash = sha256(prompt\0model\0schema)`.
2. Version change resets instance to cold.
3. Cold/regenerate → inline (await) or SQS; status refreshing keeps the stale result visible.
4. Worker skips stale-version messages, claims lease, runs agent loop, optional structured phase
   (`crates/ai_projections/src/outbound/agent_generator.rs`); sets `stale_at`; pushes `ai_projection_updated`.
5. EventBridge per cadence (6 h / 1 d / 3 d): delete unrequested past expiry; claim stale/errored, 15-min reclaim
   (`services/ai_projections_refresh_handler/src/refresh.rs`).

**AI edit** (`services/ai-editing-worker/src/run-edit.ts`)
1. `/edit {documentToken, documentId, prompt, models per role (fallback chains), mode, editor name, propagate}`.
2. Worker joins as a Loro peer in the reserved AI peer-id range.
3. Doc rendered as line-numbered XML with node ids.
4. Supervised: interpreter → supervisor → parallel coders by disjoint region; fast: one model, `runCode` loop.
5. Coders write JS against `DocumentEditor` in QuickJS → `DocumentOp[]` + effect report.
6. Ops animated and applied, or returned unapplied (`propagate=false`); usage + trace to D1.

## 4. Ideas worth stealing (ranked)

1. **Eager core set vs deferred tools.** Why: the CLI already defers every cerebro tool; an `alwaysLoad` core set is
   Cerebro's `EAGER_TOOLS` and saves a ToolSearch step per run. Path: `crates/ai_tools/src/lib.rs` (`EAGER_TOOLS`),
   `crates/ai_tools/src/deferred.rs`.
2. **One tool definition feeds model, MCP listing and TS.** Schema + mandatory annotations + narrowed context. Why:
   Cerebro has 17 hand-written `json!` tools and 5 drifting write inventories; the CLI acts on annotations. Path:
   `crates/ai_toolset/src/annotations.rs`, `crates/ai_toolset/src/toolset/types.rs`,
   `services/mcp_service/src/tool_service.rs`.
3. **Host matrix: toolset and prompt assembled together.** Why: Cerebro's base prompt names `open_note` /
   `propose_organize` to runs without them. Path: `crates/ai_tools/src/lib.rs`, `crates/ai_tools/src/test.rs`.
4. **User tools with a schema-projected review form** (flat primitives + whole-draft JSON; result written back).
   Why: every tool reviewable without per-tool UI; analogue of proposal channels. Path:
   `crates/ai_tools/src/user_tool_review.rs`, `crates/ai_toolset/src/toolset/tool_object/user_tool.rs`.
5. **Refuse instead of guess, return ops + effect report.** Why: safe, diffable body edits; Cerebro agents cannot
   edit a page in place. Path: `services/ai-editing-worker/AI_EDITING.md`,
   `services/ai-editing-worker/src/ai-editing/tools/im-blocked.ts`, `.../effect-report.ts`.
6. **Provider-strict schema pipeline**, validated at registration. Why: the CLI silently drops API-invalid schemas
   ("Unavailable MCP Tools"). Path: `crates/ai_toolset/src/schema/generate.rs`,
   `crates/ai_toolset/src/schema/transform/strip_unsupported.rs`.
7. **Exhaustive typed renderer registry**, activity groups, standalone tools. Path:
   `apps/web/src/lib/core/component/AI/component/tool/handler.tsx`, `.../message/AssistantMessageParts.tsx`.
8. **Replayable stream per turn + cancelled-call closure.** Why: re-attach mid-turn; valid transcript. Path:
   `crates/stream/src/domain/traits.rs`, `services/document_cognition_service/src/api/stream/chat_message.rs`.
9. **Generative UI from one widget schema**, `--check` generator in CI. Path:
   `apps/web/src/features/dynamic-ui/schema.ts`, `apps/web/scripts/generate-dynamic-ui-schema.ts`.
10. **Typed failure + remedy** (switch provider, remember failed ones). Path:
    `services/document_cognition_service/src/model/stream.rs`, `apps/web/src/lib/core/component/AI/constant/model.ts`.
11. **Prompt sections as const `{title, instructions, intent}`.** Small, ordered, testable; `intent` reads as an eval
    rubric but nothing consumes it. Path: `crates/prompt/src/types.rs`, `crates/prompt/tests/compose.rs`.
12. **AI authorship**: reserved AI peer range, "(AI)" cursors. Why: History can tell agent edits from human ones.
    Path: `services/ai-editing-worker/AI_EDITING.md`.
13. **Metering checklist**: unpriced ≠ free; missing counter = unresolved; disjoint token dimensions; exhaustive
    billable/exempt match; begin/finalize observations; admission before durable state. Path:
    `docs/AI_BILLING_ROLLOUT.md`, `crates/ai_usage/src/domain/counting.rs`, `crates/ai_usage/src/domain/tracking.rs`.
14. **Version-hashed cached AI views**, stale-while-refreshing. Path:
    `crates/ai_projections/src/domain/ai_projection_service.rs`.
15. **Two-phase structured output** (tool loop, then schema distillation; "Interrupted" when writes committed). Path:
    `services/document_cognition_service/src/api/structured_completion.rs`.
