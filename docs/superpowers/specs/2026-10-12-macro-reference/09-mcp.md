## 1. What it is

- **Server:** `services/mcp_service` is an rmcp 1.7 Streamable HTTP server: stateless, JSON responses, POST only, no sessions. It serves 109 tools from `ai_tools::tools_for(AiHost::Mcp)` in one unpaginated `tools/list` with no deferral. `services/mcp_auth_proxy` is an OAuth 2.1 broker in front of FusionAuth (which has no DCR).
- **Client:** two stacks. Native `crates/mcp_client` adds a server by URL and does OAuth (CIMD → DCR → pre-registered), storing AES-256-GCM credentials in Postgres. `crates/pipedream_mcp` runs Pipedream's hosted Connect iframe. `crates/mcp_select` picks one stack per user. Connector tools reach chat only through SearchTools/LoadTools.
- **SDK/API:** `packages/sdk` (`@macro-inc/sdk`) is generated by hey-api from 14 utoipa OpenAPI specs plus a hand-written ORM layer. User API keys (`crates/user_api_key`) serve only the REST SDK. `static_assets/schema.graphql` feeds the web normalized cache; neither SDK nor MCP uses it.

## 3. How it's built

**Server path:** rmcp `StreamableHttpService` (stateless, JSON) → `AuthenticatedToolService` (ServerHandler) → `AsyncToolCollection<ToolServiceContext>` from `tools_for(AiHost::Mcp)` → each domain crate's `inbound/toolset` AsyncTool → its domain service. `/mcp` sits behind `validate_bearer` (JWT → `MacroUserIdStr`), merged with broker routes, mounted at root and under `/mcp`.
**Client path:** DCS mounts `mcp_client` + `pipedream_mcp` routers; `mcp_select` picks a stack; tools mangled `mcp__<server>__<tool>`, routed by prefix through `CombinedToolSet`; connector tools only in the searchable catalog. Agent sandboxes reach the same connectors plus Macro's own MCP through `crates/agent_egress`, which stamps credentials.

### Key flows

**External client connects + calls**
1. POST `/mcp` without token → 401 + `resource_metadata`.
2. Client fetches protected-resource and AS metadata.
3. POST `/register` → redirect policy → Redis 90 d.
4. GET `/authorize` → checks → pending session → 307 to FusionAuth (google_gmail).
5. `/oauth/callback` exchanges upstream code, stores single-use broker code, redirects with code+state.
6. POST `/token` → code consumed, client/redirect/PKCE verified, refresh digest bound → FusionAuth tokens.
7. POST `/mcp` Bearer → JWT → user id → stateless rmcp builds toolset → initialize / tools/list / tools/call.
8. Tool checks entity access in its body → `structuredContent` + images, or `CallToolResult::error`.

**Add native server** — Settings → POST `/mcp/servers` (no creds) → Connect reserves popup → POST `/mcp/servers/auth/start` → discovery → pre-registered / CIMD / DCR → PKCE URL, Redis → provider → `/mcp/servers/auth/callback` → encrypted upsert → onboarding hook → frontend polls until `authenticated`.

**Pipedream connect** — POST `/pipedream/mcp/token` → Connect token → iframe → postMessage success → POST `/pipedream/mcp/complete` → backend verifies account owner == caller → upsert.

**Chat uses connectors** — `mcp_selector.user_toolset` → connect each enabled server → mangle → static schemas only sent → model calls SearchTools (term-count rank, auto-load top 8) → mangled call routed by prefix → original name dispatched.

**Sandbox** — session snapshot → harness advertises slugs + custom servers + Macro → sandbox calls egress with session token → egress stamps Pipedream bearer / refreshed OAuth bearer / minted MacroApiToken.

**Add an MCP tool** — AsyncTool in `crates/<domain>/src/inbound/toolset` with title/description + `ToolAnnotated` → crate toolset fn → `tools_for` branch → FromRef context → wire in each host incl. `services/mcp_service/src/context.rs` → regen tools + docs. ## 4. Ideas worth stealing (ranked)

1. **Annotations as a three-way kind, enforced, plus a served-catalog test** — readOnly/destructive can't disagree; unannotated won't compile; `every_exposed_tool_meets_directory_requirements` checks what is actually served. Claude Code acts on these (concurrency, read-only, display). `crates/ai_toolset/src/annotations.rs:18-44`, `services/mcp_service/src/tool_service.rs:19-25`, `services/mcp_service/src/tool_service/test.rs`.
2. **Per-host composition; never expose a tool the host can't finish** — maps onto Cerebro's grant. `crates/ai_tools/src/lib.rs:234-306`.
3. **Descriptions as routing prompts + filters over pagination with honest caps** — ContentSearch vs NameSearch vs ListEntities each say when not to use them. `crates/ai_tools/src/search/search_service/content.rs`, `crates/soup/src/inbound/toolset/list_entities.rs`, `crates/ai_toolset/TOOL_DESIGN.md`.
4. **Server instructions fixing the citation format** — `crates/prompt/src/lib.rs`. Counter-lesson: Macro's test asserts the phantom `ReadThread` (`services/mcp_service/src/tool_service/test.rs`); derive assertions from the served catalog.
5. **Answer a selected-but-unconnected connector with the fix, not absence** — `crates/agent_harness/src/outbound/egress.rs`.
6. **Out-of-band auth UX: poll while OAuth finishes elsewhere, no false "none connected"** — `apps/web/src/lib/queries/mcp-servers.ts` (design only).
7. **PAT hygiene** — prefix, CSPRNG, hash-only, shown once, cap, redacted Debug, `gcTime 0`. `crates/user_api_key/src/domain/models.rs`, `apps/web/src/lib/queries/user-api-keys/user-api-keys.ts`.
8. **Inline images in results, bounded** — `services/mcp_service/src/markdown_images.rs` (but it drops over-cap images with only a tracing warn, `:133-140`).
9. **Strict-mode schema validation at registration, per-host CI test** — `crates/ai_toolset/src/schema/validate.rs`, `crates/ai_tools/src/test.rs`.
10. **Provider facts** — Slack/GitHub need pre-registered apps, Linear needs explicit scopes, trailing slashes break matching, rotating refresh tokens need write-through. `crates/mcp_client/src/domain/provider_registry.rs:94-113`, `crates/mcp_client/src/domain/service/persisting_credential_store.rs`.
11. **Ownership verification on managed connect; `tools-only` mode** — `crates/pipedream_mcp/src/domain/service/connect.rs`.
12. **SDK coverage ratchet** — every endpoint wrapped or explicitly skipped. `packages/sdk/src/coverage/check.ts`.
