## 1. What it is

- A Gmail-only, server-side mailbox mirror. A Pub/Sub push or a `history.list` cursor fans out idempotent per-message ops (upsert, delete, labels) over SQS into Postgres. Label edits are written locally first, then pushed back to Gmail. Every send is a delayed scheduled send (10 s undo by default).
- On top of it: deterministic Signal/Noise triage, follow-up reminders, calendar-invite cards, attachment auto-import, and a team CRM that projects email traffic into companies (by domain) and contacts (by address).
- The frontend is SolidJS + Lexical. HTML bodies go through a framework-free renderer package (parse5/css-tree scrub, image policy, Shadow DOM, OKLCH color adaptation).

## 3. How it's built

**Architecture.** Hexagonal Rust backend plus a SolidJS frontend.

- `crates/email` is the domain: ports, services, Postgres adapter, axum routers, AI toolset.
- `crates/email_api_client` holds the provider-neutral mailbox ports and a Gmail adapter over `crates/gmail_client` (REST).
- `services/email_service` is the composition root: the axum API plus the SQS workers (inbox_sync, gmail_ops, backfill, link_manager, scheduled, crm_cleanup, sfs). Lambdas on EventBridge handle hourly watch renewal, per-minute due sends and daily cleanup.
- Postgres is the source of truth; Redis caches tokens/certs/counters; Kafka carries `macro.email`.
- `crates/crm` projects email into team CRM records. `crates/contacts` keeps a cross-user correspondent graph for autocomplete.
- Frontend features consume capability contracts; `packages/email-renderer` is framework-free.

**Key flows.**

1. **Push → incremental sync.** Gmail `users.watch` → Pub/Sub → `POST /gmail/webhook` (JWT checked against cached certs, refetched once on rotation) → SQS `GmailMessage{history_id}`. Worker: no-op if inactive or stored cursor ≥ notified id → sync labels → `history.list` from cursor → `map_history_list_response_to_changes` (precedence delete > upsert > labels) → upsert cursor → one op per message. `upsert_message`: fetch + sanitize → insert → calendar parts → event → contacts → `PopulateCrmContact` → realtime refresh → attachment import. `OutdatedCursor`: recovery backfill + cursor repair to the notified id (no loop). Provider 429 → retry queue; local budget refusal → dropped (the next notification covers it). `services/email_service/src/api/gmail/webhook.rs`, `services/email_service/src/pubsub/inbox_sync/operations/gmail_message.rs`, `crates/email_api_client/src/outbound/gmail/convert/history.rs`, `services/email_service/src/pubsub/inbox_sync/email_api_error.rs`
2. **Connect → backfill → upkeep.** OAuth consent → `/email/init` → link row + backfill job → leased Init → labels, contacts → ListThreads: priority pass (200 CATEGORY_PERSONAL threads), then 500-thread batches → thread → message → metadata → attachments → finalize. `SeedSentContact` seeds CRM from the 200 latest sent messages. Hourly Lambda renews the watch in `hashtext(id)%24` buckets; a health probe sets `needs_reauth` and notifies. `services/email_service/src/pubsub/backfill/list_threads.rs`, `services/email_service/src/backfill_init_service.rs`, `services/email_refresh_handler/src/handler.rs`
3. **Compose → send with undo.** Debounced autosave → `saveEmailDraft` (client-minted handles via `email_*_client_ids`) → send readiness (online, saved, attachments uploaded) → `send_message_impl`: send_time = now + 10 s, enqueue with +2 s delay. Undo = `change_schedule(Cancel)`. Delivery: `try_claim` (committed) → `send_claimed` (MIME with In-Reply-To/References) → `complete` or `release`; no DB lock across the provider call. `crates/email/src/domain/service/send.rs`, `crates/email/src/domain/scheduled_delivery.rs`, `apps/web/src/features/email-compose/primitives/send-readiness.ts`
4. **Triage mutation.** Hotkey or tool → resolve owning inbox → atomic local write (label assignments + denormalized flags) → enqueue gmail_ops `ModifyLabels`; on enqueue failure revert only what this op changed → worker calls `messages.modify` → the provider echo finds no DB diff and emits nothing. Sender policy: upsert `email_filters`, recompute `is_signal`, enqueue Unblock/Block. `crates/email/src/domain/service/thread_labels.rs`, `services/email_service/src/pubsub/gmail_ops/process.rs`
5. **Email → CRM.** Sent message → to/cc/bcc; received → from; role addresses dropped → one `PopulateCrmContact` per address → `populate_contact`: killswitch, same-domain skip, generic-domain skip (no contact, no company) → resolver ensures a directory row (negative cache) → one txn upserts company/domain/contact/source: sent may insert a company; received inserts a contact only when the company exists; interactions merge with LEAST/GREATEST. Nightly `crm_cleanup` cascades deletes but keeps manual rows. `crates/crm/src/domain/service.rs`, `crates/crm/src/domain/companies_repo.rs`, `services/email_service/src/pubsub/backfill/populate_crm_contact.rs`
6. **Agent read/send.** ListEntities/ContentSearch → GetThread (`body_parsed`, replyless plaintext with link footnotes) → UpdateThreadLabels/SetSenderPolicy. SendEmail is a UserTool returning `PendingUserExecution`; the host shows a review card, then the undo window applies. In channel/doc threads the model writes the email in prose and calls SendConfirmedEmail with the approval quoted. `crates/email/src/inbound/toolset/get_thread.rs`, `crates/agent/src/hook.rs`

## 4. Ideas worth stealing

1. **CRM as a projection of correspondence, with provenance.** Sent mail creates records; received mail only touches existing ones. Same-domain mail is skipped, generic domains and role addresses are filtered, and first/last interaction merges with LEAST/GREATEST. In Cerebro these facts stay *derived* and are never stored. Machine fields stay separate from human fields (stage, owner, revenue). `crates/crm/src/domain/service.rs`, `crates/crm/src/domain/companies_repo.rs`, `crates/macro_db_client/migrations/20260514120000_crm_contact_sources.up.sql`
2. **Header-only events tagged with origin (UserAction vs ProviderSync).** Mail can trigger agents without bodies leaking into a ledger, and provider syncs don't count as activity (`crates/email/src/domain/activity.rs`). bcc stays out of events and GetThread. This maps to operational records in runtime.db. `crates/email/src/domain/events.rs`, `crates/email/src/inbound/toolset/get_thread.rs`
3. **Agent-facing text is replyless plus `body_parsed`, never raw HTML.** It cuts tokens and noise and doubles as index text. Macro cuts unconditionally at the first splitter and keeps `Fwd:` messages whole. `crates/email_utils/src/body_replyless/plaintext_parser.rs`, `crates/email_utils/src/body_replyless/constants.rs`, `crates/email_utils/src/body_parsed.rs`
4. **The `ReplyBaseline` predicate.** Small and pure: it excludes outgoing, self, draft, replayed and backfilled messages. The return time is ordering metadata, never a message date. It can be tested under a VAULT_TODAY-pinned clock. `crates/email/src/domain/followup.rs`
5. **Sender policy as address XOR domain rules, where an address beats a domain.** The rule store is separate from people records, which matters because newsletters and vendors have no records. Cerebro's version is rule records read in TS. `crates/macro_db_client/migrations/20260325102949_email_filters.sql`, `crates/email_db_client/src/threads/update.rs`
6. **Status derived from persisted facts with fixed precedence, shown as words.** Take the precedence but not the `None → UpToDate` mapping, which breaks absent≠zero. `crates/email/src/domain/models/link.rs`
7. **Display-name normalization.** Strip "via X" and reject names that contain an address. The CRM contact name is the first non-null one. `crates/email_utils/src/normalize_contact.rs`
