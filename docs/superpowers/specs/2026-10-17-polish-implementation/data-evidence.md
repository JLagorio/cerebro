## Retained implementation

- `src/views/TableView.tsx`, `tableAnatomy.tsx`, `displayGeometry.ts`, `src/styles/table-chrome.css`: UI 14/20, metadata 12/18, 36px header, 32px group bands, existing 32/36/48px row presets, 10px cell inset, 28px title Open action. Absent title width is 32% clamped 320–480px in wide hosts; narrow hosts use a bounded 200–320px default. Saved explicit widths remain authoritative. Slack grows unspecified property columns, not explicitly sized ones.
- Title editing retains the exact refused draft, coalesces Enter/blur while pending and after an unchanged refusal, permits explicit retry, handles IME/Escape, avoids no-op writes and avoids stealing focus after delayed failure. A successful keyboard commit returns focus to the grid only when focus was not deliberately moved elsewhere.
- Scalar editing uses root's `FieldEditor` contract. Per-editor `useId` tokens hold table inputs through incoming filter/sort/schema/rescan replacements. Closing one occurrence cannot release another occurrence of the same file/property. The last editor reconciles fresh inputs and names a record that left the view. This is not a result limit or a new store.
- Title feedback consumes root's `AnchoredFieldStatus`: persistent accessible status associated by `aria-describedby`, passive visual bubble in a body portal, viewport/zoom positioning and grid-scrollport visibility. Frozen editing cells retain `position:sticky`; obsolete input z-index/overflow rules were removed. The grid’s inline-start scroll padding equals its resolved frozen prefix, so native input focus/scrollIntoView reveals a nonfrozen editor beside pinned columns, including at200% zoom.
- Retained performance mechanism: a small `TableRow` wrapper forwards stable callbacks through the latest props, while memoized `TableRowBody` receives stable row metadata and a primitive cursor slot. Moving the cursor re-resolves only the old/new row bodies. Tests cover new schema/presentation inputs, changed row ordering/range selection and refusal/edit leases. All supplied rows remain ordinary DOM/layout/paint, with their original indices, grouping, scroll restoration and drag semantics.
- `DatabaseActions.tsx`, `TypePage.tsx`, `ListPage.tsx`, `ViewSettingsPanel.tsx`: entity-level deletion sits in Database/List actions with existing confirmation. View settings says “Display this view”; field management and saved-list settings carry their scope. Delete view remains a view action.
- `ViewTabs.tsx` and `ViewControlIcons.tsx`: controls follow actual container width, move to a second row below 560px, retain active counts and shared vocabulary, and use 32px primary New. `ViewTabEmbed.tsx` and `DatabaseBlockView.tsx` use the same search/control vocabulary. Local search writes nothing. Related creation and Add existing remain separate and host-aware. Shared-view changes write only through the existing explicit Type/List operation; merely opening or measuring a view writes nothing.
- `src/sheet/SheetGrid.tsx` / `SheetView.tsx`: inner toolbar/header/grid presentation aligned with the roles; 32px rows and existing 120px columns retained. Formula source, draft settlement, IronCalc, workbook export and virtualization were not changed.

## Performance: what ships versus discarded experiments

Environment: Apple M1 Pro,10 logical cores,32GiB, Darwin24.6.0, Node26.3.1, Chromium149.0.7827.55; unthrottled headless **Vite development**. Actual table host1340×740 in a1440×900 viewport. This was not an idle machine: process/load artifacts show substantial other load despite agent/browser/build lanes being quiet. Do not present these as production acceptance or statistically robust benchmark results.

Retained safe mechanism was measured at1000×12 with20 samples in `/private/tmp/cerebro-m87-perf/after-1000-12.json`: p95489.3ms, mount553.6ms, max warmed task454ms, all1000 rows retained. The baseline's later five-sample1000×12 p95 was935.9ms; machine load differed, so this is diagnostic evidence, not a controlled speedup claim. Those development results remain separate from the production diagnostic below; no controlled speedup is claimed.

A bounded **production** diagnostic now measured the retained implementation through the real app on a 1146×747 table pane. Four fixtures completed 20 samples each: 100×12 p95 **30.4ms**, 100×24 **47.6ms**, 1000×12 **398.8ms**, and 1000×24 **1376.2ms**. The 1000-row fixtures observed warmed long tasks of **403ms** and **1367ms**; the 100-row fixtures observed no task at or above the Long Tasks API’s 50ms threshold. The proposed <100ms input / <50ms warmed-task targets remain **unmet**. The 5000×12 page navigation timed out before input measurement; 5000×24 was not attempted. No missing result is zero or passing. The production bundle hash stayed unchanged, and completed fixtures retained all rows and wrote nothing. See the [production report](data/performance/production-report.md), [raw matrix](data/performance/production-retained.json), and [reproducible harness](data/performance/production-measure.mjs).
