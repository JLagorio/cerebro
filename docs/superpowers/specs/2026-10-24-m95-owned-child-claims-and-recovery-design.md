# M95 — Owned child claims and recovery

Status: independently reviewed implementation design, 2026-10-24. The accounting and recovery amendments passed scoped source review. Implementation, causal execution and backend isolation acceptance remain outstanding; public supervised execution stays disabled.

This design refines [M95.6](../plans/2026-10-23-m95-chat-and-supervised-agents.md) under the [approved supervised-job limits](2026-10-24-m95-supervised-job-decision.md). It introduces no additional retention choice.

## Decision

Implement one actual launch claim atomically with the child run and native job provenance. Produce a retained opaque owner only after a definite commit and original-source rechecks. Consume that owner once into a fixed closed backend, then settle the pre-launch run. Do not introduce a separate inert pre-run handoff table, a diagnostic policy API, a token or a child process.

This is the smallest complete layer that makes subsequent dispatch legitimate. The existing reservation records intended IDs and concurrency occupancy; the freeze records an immutable contract. Neither records an actual claimed child run/native job provenance, single-consumer execution ownership, or its terminal/restart disposition. Those are the facts the future scoped token mint must consume. A no-op mirror of grant_admission does not supply them.

## Existing source constraints

NativeDelegationCaller is opaque and retains the original NativeActionReadOrigin and intent. with_original_observation authenticates the native window, observes the exact parent publication outside storage locks, and verifies original opening, publication entry, owner/store, native root lineage and attempt in a classified transaction. freeze_native_child retains one Arc<FrozenNativeChild>; V40 stores only digest metadata. The same retained Arc must remain the sole source of its compiled researcher instructions and effective grant.

Native lineage's generic validate_row deliberately rejects source_kind=job and child_job_id. Keep that generic rejection. native_rules explicitly requires actual_m95_job_claim_proof_only. The schema already admits source_kind=job with a nonnull child_job_id and CLI session, but schema acceptance alone is not authority. The new actual claim must supply that missing proof.

The ordinary spawn_run loads connector reach/configuration and uses ordinary CLI launch environment rules. It is not a child isolation adapter and is not called. answer_value handles ask_gate/ask_host before normal call_tool admission; call_tool records tool/refusal activity under a real run ID. No synthetic grant is sent through those paths in this slice.

## API and ownership

Proposed internal APIs, not existing functions:

- claim_native_child_run(app, native_window, &NativeDelegationCaller, &NativeDelegationRequest, &Arc<FrozenNativeChild>) -> OwnedChildRun. Only the fixed native-read-smoke path calls this while public supervised start remains unavailable. No Tauri/MCP/frontend submission door is introduced.
- OwnedChildRun is non-Clone, non-Debug and non-serde. It retains the exact original origin, same frozen Arc, fresh claim identity and private claim/native-run proof. Fields and constructor are private. No arbitrary grant/subject/token constructor or public connection callback exists. Its allocation/run IDs are descriptive, not a reconstruction key.
- consume_native_child_backend(app, native_window, OwnedChildRun) -> ChildBackendOutcome is the sole consuming path. It revalidates the live claim and original owner and delegates only to the fixed ClosedChildBackend, which returns BackendIsolationUnverified. No executable/backend choice is supplied by the caller.
- settle_unstarted_child(...) is a private retained-owner kernel, keyed by the actual held proof; it atomically closes the claim, child run/native lineage and occupancy. Recovery has a separate metadata-only terminalizer and cannot return an OwnedChildRun.

The original caller gets a private serialized launch state: Unclaimed, Claiming/Closed, Owned, Terminal. A replay while the consuming owner is outstanding returns AlreadyClaimed without an owner; a terminal replay returns only a descriptive receipt. Neither path clones/remints the owner or creates another child run. Mark the caller closed before storage work. Definite shape/conflict rollback may restore Unclaimed; uncertain commit, lost acknowledgment, source drift and expired evidence/deadline do not. These Rust ownership states are volatile only: do not add durable claiming/owned/consuming states merely to mirror them.

The future production mint will accept only OwnedChildRun through a consuming method, after checking the actual run/claim is live. It must not accept Allocation, FrozenNativeChildView, IDs, row snapshots or a capability bool. This establishes one launch state machine, not a parallel future-only handoff mechanism.

## Actual rows and narrow lineage proof

Use the next available CHAT migration (V41 at inspected source; root rechecks shared branch before reserving the number) for actual child-job claims. The row uniquely joins the reservation slot, reserved job/run/session, frozen contract digest, parent run/attempt and owner scope, with immutable identity/deadline and constrained lifecycle fields. Avoid redundant values unless needed for SQL foreign keys or integrity validation. Include claim identity and the originating app session. Retain no objective, instruction prose, raw prompt/reasoning, evidence body, credential or result body.

In one retained-owner classified BEGIN IMMEDIATE transaction:

1. Validate the exact original parent, caller intent, reservation, occupies_slot=1, same frozen Arc's digests and source/evidence/deadline. Reuse existing kernels; do not reconstruct the contract from V40.
2. Refuse an existing consumed/abandoned claim, mismatched row or any collision of reserved IDs/session. Existing reservation replay is not permission to start twice.
3. Insert the actual child runs row using reserved_run_id, same vault/store and parent_run_id, recorded reserved CLI session, and a runtime-authored Handoff cause. Use a fixed safe subject/detail such as the compiled researcher role and job identifier; never the user objective. Add the low-level row writer under runtime/dispatch.rs so the repository's single runs-insert convention remains intact.
4. Record the actual child claim and action_native_runs row (source_kind=job, child_job_id, parent, unique authority_id, session, owner/store/vault/app-session and immutable contract link) in that same transaction. The actor is runtime-derived as job:<allocation.job_id>, separate from the parent's actor and never a process: Agent-page actor; tests pin that derivation and the schema byte bound. No managed-account/action grants are copied or inserted.
5. Verify the joined rows through a new private resolve_claimed_child_lineage validator which additionally requires a non-forgeable, borrow-only claim proof produced inside this transaction from the original caller/frozen capsule. It checks every shared native axis, root parent liveness, depth one, no client identity, exact reservation/freeze/claim joins and deadline. Generic resolve_lineage stays job-denying. Do not merely remove source_kind=job/child_job_id checks or allow a row to supply its own proof.
6. Commit definitively; recheck original publication/store/evidence/deadline outside storage locks before exposing OwnedChildRun. Uncertainty produces no owner and cannot be retried into one.

runs.mode currently supports attended/ambient only. Use the existing attended pre-launch bookkeeping class, as begin_attended and begin_client_session already open rows before a process/model invocation; this is app-owned awake work, not an ambient scheduler lease. The mode must never be used to grant child attendance: future MCP asks.kind remains Unattended, so mail and parent approval authority are not inherited. Keep usage_state pending until terminal classification and then unknown when no CLI usage was recorded; do not present stored zero counters as measured model usage. The claim's state and backend-unavailable disposition distinguish pre-launch admission from an actual process. Do not claim child configuration capture or an observed CLI executable exists. Set configuration_capture to required pending a future actual launch capture, and leave it unfulfilled when the closed backend refuses.

The native actor/session/run are actual admitted pre-launch identities, not proof of an installed CLI session or a process. The fixed closed consumer has no subject usable at account/action providers. The specialized validator's proof is scoped to child backend ownership; it does not authorize general ACT actions or managed-account access.

## Lifecycle and settlement

The actual claim states for this slice are claimed -> backend_unavailable | cancelled | expired | interrupted. No terminal state can be reopened. No child process state is asserted. The live opaque owner is the only holder that can consume claimed into a backend attempt; the current attempt always refuses. Later execution states must extend this same machine, not add another claim.

Closed backend refusal atomically marks the claim backend_unavailable, sets the run outcome failed and ended_at with usage unknown, closes native provenance consistently, and clears only reservation occupancy. Claim IDs, reservation IDs, request/contract digests, deadline and lifetime admission count remain immutable. Preserve the typed backend-unavailable reason in metadata, never as a false successful job result. For Stop, close claim cancelled/run cancelled; for deadline, expired/run elapsed_aborted; for abandoned claim, interrupted/run abandoned_usage_unknown. Native close_kind uses its existing finite vocabulary (completed for a settled backend refusal, stopped for Stop, and context_closed for interrupted authority); no fabricated observed process termination is recorded.

If final settlement cannot commit, leave the claim/run in their last definite state and return Unavailable. A consumed owner cannot be rebuilt to repeat the attempt. Restart terminalizes abandoned claimed jobs and matching run/native rows as interrupted before any future job start; it never resumes or repeats execution. Recovery uses the established retained native storage writer, never a caller supplied connection. It returns no authority and does not repair missing provenance with invented rows. Corrupt/mismatched joins fail closed and remain visible as unavailable for investigation.

Terminalization has a different authority requirement from claim/owner exposure. with_original_observation and the same-Arc/live-parent checks remain mandatory for creating or exposing OwnedChildRun, but cannot be the sole terminalization door. A private held-owner terminalizer uses the existing owned claim and validated retained storage to permit terminal updates only after Stop or vault switch, without reviving the original publication. The metadata-only restart terminalizer validates historical claim/reservation/freeze/run/native/parent/session joins, immutable ownership/store/vault/session identity, allowed close states and the abandonment cutoff. It permits known closed historical app sessions and appropriately advanced authority revisions after Stop/context closure; it does not require a live historical parent/publication, an open old app session, a current opening for the old vault or a recreated frozen Arc. It never creates, returns or reactivates a caller, owner, token, subject or grant. Missing or inconsistent history is Unavailable, not reconstructed authority.

The reservation scan must recognize actual claims without treating them as inert. Current retire_inert_occupancy visits every same-owner/vault/store/actual-parent-CLI-session reservation, including occupies_slot=0, and reserve_rows always calls it before counting. An unconditional rejection of all execution identities would permanently block the second reservation after the first real claim, even after settlement. Correct this in the existing bounded scan; do not add another admission subsystem or broadly skip rows with a claim ID or released occupancy.

Validate the complete session set (at most the shared lifetime maximum plus one sentinel) before updating any inert row. For each reservation, validate the existing intent/allocation/historical-parent links and classify it using exact claim-owned lifecycle joins:

- Validated inert reservation: no actual claim and no matching or colliding execution identity in runs/action_native_runs. Retain the existing terminal-parent/deadline retirement rules, including released-row validation. An orphan claim or unexplained run/native identity refuses; absence cannot be inferred from a failed lookup.
- Exact claimed lifecycle: exactly one genuine claim, its reserved child run and job-native provenance, matching slot/job/run/session, immutable request/freeze/contract/deadline and parent/attempt/owner/vault/store/app-session identities, with coherent claimed/run-running/native-open state and occupies_slot=1. Check for additional/colliding identities, not merely existence of one matching join. A stopped/ended historical parent does not invalidate otherwise coherent accounting or authorize execution: the actual claim remains occupying until its child terminalizer closes it. The inert scan does not change any claim/run/native row or this occupancy, including after expiry. This row counts normally so a second reservation can be admitted.
- Exact terminal lifecycle: the same complete immutable joins plus a supported terminal claim disposition, the matching run outcome/ended_at/usage state, coherent native closure and occupies_slot=0 already committed by the child terminalizer. Account for the row without rewriting it. Terminal-with-occupancy, claimed-without-occupancy, partial settlement, malformed fields, missing rows, incompatible closes and any extra execution collision are Unavailable.

Historical classification is metadata validation only and creates no owner or generic ACT authority. It can share the child terminalizer's historical join checker; it must not require a revived parent or frozen Arc. Keep generic job-lineage validation closed. On any corrupt row, the reservation's classified transaction rolls back the whole prospective inert cleanup/allocation. After classification, count every reservation toward the eight-admission lifetime allowance and sum actual occupies_slot for concurrency. Terminal claims remain counted forever. Only the child terminalizer releases actual-claim occupancy. Stop, failed backend, restart, retry and new parent attempts in the same actual CLI session never reset the allowance.

## Recovery registration and generic sweep exclusion

At the inspected opening sequence, lib.rs prepares retained native storage before agent::meter::recover_orphaned, then sessions::track and later native bind_opening. Invoke the metadata-only child terminalizer after successful retained storage preparation and before the generic attended sweep. Its historical validation does not depend on the later live opening bind or a still-open old app session. An unavailable retained store leaves child rows untouched and reports recovery unavailable; do not fall back to an ordinary reopened writer for child terminalization.

Independently and unconditionally exclude child-owned/protected rows from recover_orphaned_attended's selection and finalization, including when child recovery fails or its joins are corrupt. Running the child sweep first is not sufficient. The exclusion is conservative metadata routing, not an authority validator: it must not depend on a complete valid join that a corrupt row could escape. Protect run IDs referenced by an actual child claim, run IDs carrying job-native provenance, and existing runs occupying reserved child run identities whose claim/provenance may be missing or inconsistent. Such unexplained rows belong to child recovery's unavailable diagnosis, not partial generic finalization. Schema/query failure must fail the sweep closed rather than drop the exclusion. This does not authorize repairing or settling a corrupt child join.

The terminalizer atomically settles claim/run/native closure/occupancy; generic attended recovery cannot partially close just its run. Test the real opening registration, not merely direct helpers: successful child recovery before generic recovery; failed child recovery followed by the generic sweep; closed old app session after catchup; Stop/vault-switch historical settlement without live parent/Arc; and an ordinary unrelated attended orphan still recovered by the generic path. No private owner is reconstructed at any stage.

## Lock, liveness and race boundaries

Use one documented order for caller launch state, freeze state, original opening, retained publication entry, owner storage and SQLite. Never acquire a caller mutex from code already holding owner/storage/SQLite guards. The existing original-observation path's MCP and AgentState lookups remain outside those guards; no token mint, process call or backend wait happens inside them.

Phase A observes the original source and acquires the current same-Arc contract. Phase B performs the actual claim/run/native insert under the classified owner transaction. Phase C drops every database/storage guard and rechecks exact publication/source/store/evidence/deadline before producing the owned handle. Phase D consumes the owner into the fixed synchronous closed backend, then Phase E settles through the private held-owner terminalizer under validated retained storage. After Stop/vault switch, terminalization checks historical claim identity rather than requiring the now-dead original publication to become live. A postcommit failure must leave a real recoverable claim, not erase it or call it committed-successfully.

Existing opening/publication guards may protect the short, effect-free ownership transfer, but they cannot be advertised as a future token/process revocation barrier. Stop immediately after an observation is harmless here because the only consumer is effect-free. Before any later token or process is enabled, the same OwnedChildRun must be installed in a revocable child-runtime registration whose cancellation/dispatch transition is atomic with Stop. This is a required next-layer condition, not a claimed property of these tests.

Stop before claim prevents it. Stop or vault/owner retirement after claim either terminalizes through a valid owner or leaves a recoverable interrupted claim; it cannot yield usable backend authority. A completed backend refusal remains complete. Test all barriers before/after commit, owner creation, consume and settlement. Any injected wait counts against the original deadline. No wake worker, detached process or automatic restart exists.

## Causal RED and unchanged GREEN

Register a compiling refusal-only native entry and the fixture assertions first. The baseline must successfully publish the original toy parent, reserve and freeze through the accepted real native seams. It then fails assertions that an actual child claim/run/native row and one owned handoff exist, because the old boundary returns BackendIsolationUnverified without those facts. This is a missing lifecycle capability RED, not evidence baseline leaked authority. Compile failures, zero tests or failed native setup are not causal RED.

After implementation, the same tests must observe an actual committed child run/native claim, exactly one OwnedChildRun consumption, and backend_unavailable settlement with no token/config/process/provider effect. A test-only witness at the real closed consumer may record safe identity and Arc equality; it cannot construct an owner, select a permissive backend, bypass native authentication or replace policy. All generic job-lineage denials remain passing controls.

Required adversarial cases:

1. Healthy original caller: one actual claim/run/native row; exact reserved IDs and session, parent/vault/store/owner joins; identical frozen Arc; exactly one consumption; typed backend-unavailable terminal; no child token/process/config/account grant.
2. Same-caller replay and simultaneous starts: one durable actual run and one consumption. Distinct caller, copied IDs, matching digest, frozen view or historical row cannot take the owner. Lost caller cannot recover authority.
3. Changed request, wrong Arc, missing freeze, replaced publication, broader/changed parent, stopped/revoked parent, wrong native window, retired owner or swapped runtime file: refusal at actual owner seams; no partial claim/run/native join.
4. Definite rollback, lost commit acknowledgment, failure after claim commit before owner, after owner before consumer, after consume before terminal write, unwind and lock poison: no duplicate owner/consume and no phantom successful settlement.
5. Exact deadline at each phase, changed source/evidence, out-of-scope/mail evidence and parent authority drift: no new invocation or deadline reset. Read all caps from shared policy.
6. Stop/vault switch at each barrier: terminal cancellation/interruption or safely held recoverable row; no executable authority and no recreation after restart.
7. Generic ACT job lineage still rejects arbitrary job rows. The specialized validator rejects missing claim, mismatched slot/digests, sibling parent, child-of-child, mismatched owner/store/session/actor, injected client identity and added account grant. Its proof cannot be constructed outside the retained owner path.
8. Sequential admission progress through the actual original native seam: reserve/freeze/claim child one first; only then reserve child two while one remains claimed, and claim two. Do not pre-reserve both. A third reservation must return exactly Concurrency with no reservation/claim/run insertion. Consume and settle one through the fixed closed consumer, then retry that same original third caller/intention and admit its fresh reservation. This avoids spending a fresh intent merely to conceal a retry issue. Verify the second claim's occupancy is unchanged. Continue actual claim/closed-consumer/settlement cycles until eight reservations exist, settle remaining occupants, and refuse the ninth specifically as SessionAdmissions, not an arbitrary error. Repeat across a restarted/resumed actual parent CLI session using a newly published original native parent/caller; do not fake session authority with IDs. Retain exact immutable metadata, eight lifetime rows and zero terminal occupancy. Include mixed inert/claimed/terminal histories and unexplained or corrupt execution controls, including released corrupt rows, duplicate/colliding identities, missing claim/run/native/freeze joins, terminal occupancy still one and claimed occupancy zero. These corrupt histories must return Unavailable and roll back prospective cleanup/allocation.
9. Crash/restart recovery closes real child run/native/claim together, records unknown usage and never repeats work. Malformed/missing provenance is unavailable, not silently repaired. The actual opening path must invoke retained-storage child recovery at its defined stage, and the generic attended sweep must exclude child-owned/protected rows even when child recovery fails; asserting only child-first ordering is insufficient. Test failure followed by generic recovery with the child run still unchanged, while a separate ordinary attended orphan is finalized. Test historical terminalization after Stop/vault switch and after old app-session closure/catchup without live parent publication, old opening or recreated Arc. No metadata terminalizer returns authority.
10. Storage/surface audit: prompt/objective/evidence/credential/result canaries absent from new metadata. No false configuration, process, usage or successful child result. Parent fixture logs are identified as parent evidence. Public child start stays closed; M92 and foreground researcher behavior stays unchanged.

## Remaining independent acceptance

A passing slice proves real native child claim ownership, narrow ACT lineage and lifecycle with a closed backend. It does not prove scoped credential delivery, parent-token noninheritance, raw connector denial, shell/filesystem isolation, live decision suspension, output collection or actual child process cleanup.

Next, consume OwnedChildRun into a separate scoped MCP registration/token only after it is tied to this actual live claim/run, with no inherited parent secret. That layer must deny non-granted tools before ask_gate/ask_host, enforce scope and mail denial, revoke on Stop/deadline/owner retirement, and safely handle lost mint acknowledgment and failed publication. The existing generic job ID path remains prohibited.

Then an isolated disposable toy executable may exercise the real child launch adapter. Passing toy command/transport cases does not establish installed Claude Code isolation. Isolated real CLI login is unavailable/pending; do not inspect actual auth/configuration or Keychain to work around that. Installed CLI shell/filesystem bypass denial, independent config/credentials and required suspension remain live blockers. Public jobs stay BackendIsolationUnverified until all independent capability proofs pass. Durable result-body retention remains separately unapproved.
