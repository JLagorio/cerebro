# M99.8 native portable-backup coordinator — amendment v1

This is an implementation design for [M99](../plans/2026-10-23-m99-rust-services-and-storage.md), under the approved SQLite metadata/Markdown decision. [Current implementation status](../plans/2026-10-23-m93-m99-implementation-record.md) and [reproduced inactive-copy failures](../../acceptance/2026-10-24-workspace/portable-backup/nested-format-boundary/root-red/ROOT-CHECKPOINT.md) remain separate from proposed behavior.

Status: source-only design amendment. No implementation candidate, registered edit, command execution or runtime acceptance is contained in this packet. All names described as proposed are new private operations or wire contracts, not claims about existing APIs. Root executes and registers any later candidate.

## Product and prerequisite boundary

Keep Settings → Vault → Backups with Create backup…, Check a backup…, and Restore a separate copy…. Only an already-published selected SQLite/Markdown workspace can create a complete canonical backup. Check and Restore use a native-selected portable bundle and remain available with a legacy current vault or missing original source. Restore creates a new containing directory with Pages and Workspace data siblings, both inactive. Workspace data is part of this separate copy; it is not the installation's active app-data store and carries no live-sync promise.

The owner's selected SQLite metadata plus visible Markdown, React UI, existing portable limits, omissions, macOS live-source boundary and library validation remain authoritative. This design adds no migration, current-vault conversion, registration, activation, authority constructor, credentials, Keychain use, remote tool, durable job or durable history. Generic retained content stays generic in summaries.

P1 is a prerequisite before UI exposure: an inactive, preparing or unsupported marked subtree must not be consumed as legacy through its root, containing directory, a higher ancestor, an exact descendant path, a registered external root, scan, watcher or dispatch door. The separately authored deny-only P1 repair must establish this using the existing bounded scope/traversal mechanisms. A folder-name prohibition, a marker only on the new container, or an unbounded search of every ancestor's filesystem is insufficient. Current accepted library evidence concerns direct restored-root refusal; this amendment does not extend that evidence to nested/native paths.

P2 is this amendment's coordinator prerequisite: an output and an opening must be admitted against one serialized in-memory boundary. An overlapping opening cannot pass its first side effect or become published during a copy. A copy cannot begin inside the published, requested or already-entered opening scope. Unrelated switches remain allowed.

## What the source actually does

AuthorityContext currently holds ActiveRoot { generation, root }. begin_open clears root and advances generation before start_watcher obtains its static OPEN_LOCK. start_watcher then resolves, stops the old watcher, suspends or prepares services, performs recovery, starts a watcher and finally publishes. Legacy preparation can write and spawn background work before publish_open_with. Merely checking active_root at commit or final publication leaves a gap while root is None, and checking only at publication is too late.

publish_open_with already establishes ActiveRoot → observed identity → connector setup → listener order. with_legacy_opening uses an opaque context-bound ticket and explicitly forbids reverse entry from listener/native-owner locks. Keep these boundaries; do not hold ActiveRoot across dialogs, source snapshot/copy, waiting on OPEN_LOCK, blocking workers or UI saves.

shell::build_main_window creates the actual main window. M96 native_owner privately checks its nonzero native window and view identities, injected/current window agreement, registration Arc, live flag, config origin and allowed entry URL. Its main-thread observation happens before locks. Draft export instead supplies a useful token/expiry/clear precedent, not sufficient exact-window proof for this feature. Its 64-choice limit is not appropriate for portable manifests.

portable::create_backup owns selected_backup::Source, existing WorkspaceLock and pinned SQLite transaction, rooted directory descriptors, ledger lock, inventory, copying and final validation. restore_bundle validates input, creates fresh body/metadata roots, writes preparing first and publishes restored_inactive last. Root::create currently reopens the parent from a path; calling it after a coordinator-only identity check would leave a native-choice replacement gap. A small internal descriptor handoff is required, without a second copier or validator.

## Chosen bounded workflow

Use one workflow for the actual registered main-window incarnation. All three modes share it. The book is Idle, Choosing, Pending, Running or Terminal. A native chooser or heavy validator/copy occupies the single active slot before it is scheduled; there is no work queue. A second request gets Busy. A pending choice is replaced only by an explicit new action after release, never by an unrelated stale response.

A separate shared Rust-owned policy artifact declares pending lease 60 seconds, maximum pending workflows 1, maximum active chooser/validator/copy 1 and maximum retained terminal outcomes 1. The UI consumes the rule/returned expiry; it does not maintain a second authorization timer or limit. Existing path, manifest, entries, parts, metadata, attachment and total-byte caps are unchanged. Summary size is bounded by fixed category/omission enums and existing path/string bounds, not one row per file.

The 60-second lease starts when a successful choice becomes Pending after the dialog or check finishes. It applies only before a transition consumes that choice. Check → choose restore consumes the checked input choice, uses the same workflow during the dialog, and returns one new restore-review choice with a new lease. Cancelling that chooser releases its held input; checking again is explicit. Running work has no 60-second cancellation or resource release. A terminal result is one bounded summary/location/refusal record, replaced by the next explicit workflow or discarded when its window retires.

A Pending value holds only its opaque nonce, mode, exact window registration, expiry, display labels and bounded native descriptors/identity expectations. A checked input holds its root directory descriptor, identity, canonical spelling, validated manifest digest and summary. It does not retain VerifiedBackup, manifest bytes, all part records, a SQLite connection or a source WorkspaceLock. One transient Verified value exists only during Check or committed Restore under the active-slot bound, and is dropped before returning Pending. Directory descriptors have a small constant bound per mode; no file-part handles or per-record inventory survive a review dialog.

## Real-window ownership

Add a narrowly scoped backup window registration beside the existing native_owner::register call in shell::build_main_window. Its constructor is private to that actual shell registration path. It records an Arc incarnation, the real native window/view identity, main label, origin and live state. There is no constructor from renderer strings, labels, paths, numeric generations or a caller-selected identity.

Share/factor only the passive main-thread observation routine if doing so avoids duplication. Do not expose M96 AttendedWindowProof, RuntimeOwner, action bearer, storage preparation or Keychain machinery to backups. The backup verifier applies the same actual-window/current-window/origin/entry checks to its own registration and returns a private one-call window observation. Observation scheduling, waiting and dialog callbacks run with no book, ActiveRoot, listener, owner, workspace, ledger or SQLite lock held.

Every chooser, commit, cancel and status command receives the Tauri-injected WebviewWindow and authenticates this observation. A token from a different incarnation, recreated same label, disallowed entry URL or retired window refuses before taking a pending choice. The same live native window after a webview reload may read its one operation's state; it does not regain write authority from a display path.

On Destroyed, mark registration dead and release Pending choices. A chooser result arriving afterward is discarded. If a worker was already admitted, retirement neither releases its output reservation nor reports cancellation; the worker owns its lifetime until it settles or the process terminates. No next window inherits the registration or pending tokens.

## Proposed private native values and minimal handoffs

The following values are non-serializable and privately constructed. They are observations, owned filesystem choices or deny-only coordination, not constructors for selected workspace authority.

| Proposed value | Owner and allowed contents | Source boundary it extends |
| --- | --- | --- |
| BackupWindowObservation | Backup registration Arc plus verified current native observation for one command | shell::build_main_window; native_owner's passive observation pattern |
| SelectedBackupOpening | Context Arc, exact published opening incarnation, existing SelectedBinding expectation and bounded physical directory/database identity observations | AuthorityContext, using current resolve_with/selected_binding; analogous lifetime check to LegacyOpeningTicket |
| CheckedInputChoice | Held Root, original root identity/canonical location, manifest digest and bounded validated summary | portable::Verified/validate_bundle; no manifest retained |
| NewDirectoryChoice | Held native-chosen parent Root, original identity/canonical location and one validated absent leaf chosen by Rust | portable_io::Root/open_at/mkdir_at; consumed at mkdir, not converted back to unchecked path |
| AdmittedBackupRead | A consumed SelectedBackupOpening expectation after atomic commit admission; never a live selection or a store permit | Existing selected_backup::Source admission re-resolves and compares this expectation |
| OutputReservation | Unique private operation identity, retained deny-only footprint and lifetime holder | AuthorityContext's opening gate; one slot, never a registry/binding |
| RunningCopy | Active-slot owner, original operation/window labels, output reservation and all transient reader/descriptor resources | New local coordinator; drop ordering required below |

SelectedBackupOpening can only be captured from the exact already-published selected opening. A renderer vault string is at most a selector that must match that opening. It cannot manufacture this value. The current resolver must still succeed; a remembered binding or opening never substitutes for current selected authority. Capturing it must not open SQLite or hold a WorkspaceLock across a dialog.

At commit the gate compares the ticket's context/incarnation, current published root, selected binding and physical source/metadata identities. It also rechecks the original window registration is live: this gate admission is the boundary after which a window retirement cannot cancel owned work. A Running/preparing book entry alone is not admission; retirement before this boundary refuses without output. The source's database identity is obtained by passive metadata observation, not a second database FD kept through SQLite locks. Normal acknowledged edits may change content, data_version and metadata epoch between choose and commit; those are captured afresh by the existing Source reader. Replacing the database/root with a different physical object, even with matching workspace ID and valid contents, refuses.

After this commit check, move the original expectation into AdmittedBackupRead. Add a private Source::open_expected-style variant that uses the existing resolver, read_guard_readonly, PinnedConnection::open, constraints/facts/validate sequence, comparing the original binding and held-root/database identities as part of that sequence. Compare the database identity through the already-owned PinnedConnection; never open or close another database pathname FD under its POSIX locks. The ordinary library Source::open retains its existing API and shares this implementation. An unrelated switch after commit admission does not retarget the reader or require the source to remain selected; changed binding/identity still refuses.

For input validation, factor validate_bundle into the existing path wrapper plus a private validator accepting the held Root and optional expected manifest digest. A CheckedInputChoice must reach that validator directly. It rejects replacement of either the original root or manifest with a different otherwise-valid bundle. Restore always repeats complete part/schema/ledger validation; a prior summary/digest is not authorization to skip it.

For outputs, factor Root::create into a private create-at-held-parent primitive and retain the public path wrapper for existing callers/tests. NewDirectoryChoice is consumed by the primitive that does no-follow create-new mkdir relative to its held parent FD, opens the resulting child relative to that FD, compares the created identity and validates the original parent location. Reopening only the parent's path after checking it is insufficient. Restore creates its organizational container this way, then derives two create-new child choices from the held container Root. It never accepts Pages or Workspace data as caller-supplied arbitrary paths. Keep the existing portable copy, manifest, source validation, snapshot and marker-publication kernels shared by both entry routes.

## P2: opening state and output reservation

Retain the existing ActiveRoot mutex as the single admission gate. Extend its private state with a bounded set of denial footprints, while keeping published authority distinct from denial-only protection:

- Published/current opening: exact root, generation and physical scope identity. The public active root is absent while a new opening invalidates it, as today.
- Protected prior opening: the previous published scope remains protected while its watcher/services may still be active. For the minimal implementation, retain it until a replacement opening publishes successfully; do not assume watcher::stop alone joins all old work. After an unsuccessful open, retaining this one previous scope is a conservative refusal until another successful opening replaces it.
- Latest requested opening: one candidate and generation accepted before OPEN_LOCK. A newer request replaces only this slot.
- Entered opening: at most one candidate already inside OPEN_LOCK, protected through its preparation and cleanup. A newer request cannot erase it.
- One active output footprint: the native-held proposed container/bundle leaf and, after creation, its physical root identity. This is deny-only and never exposed as an active workspace.

Published and protected-prior are the same scope before a request; storage should not duplicate it. At most three opening scopes need comparison (protected previous, latest requested, entered), plus one output. There is no unbounded list of opening attempts, abandoned roots or jobs.

Replace the production zero-argument begin_open route with target-bearing request_open(candidate). Candidate is the existing native opening target after canonical/P1 admission, not selected authority minted from a root. Under ActiveRoot, request_open compares the target against the output footprint before advancing generation or invalidating the published opening. A denied overlap must leave the current published opening, watcher and agent admission unchanged. It returns an opaque OpeningAttempt with an internal generation accessor for the existing agents.begin_open call. The raw generation remains insufficient to enter or publish an arbitrary root.

After obtaining OPEN_LOCK, enter_open(attempt) rechecks latest incarnation, candidate identity, P1 classification and output intersection before the current resolve/stop/recover/connector/watcher work. It installs the entered scope under ActiveRoot. A superseded waiting request refuses without entering any opening side effect. Only after successful entry does start_watcher proceed with its existing preparation. Keep agent invalidation semantics: request admission and agents.begin_open precede waiting for OPEN_LOCK; tests must cover monotonic/stale generation behavior without taking an agent lock in reverse order.

publish_open_with(attempt, bind) rechecks the exact candidate, current generation, P1 boundary and output intersection, then performs the existing synchronous binding callback while holding ActiveRoot in its audited order. It promotes the candidate, replaces protected-prior and clears only its own requested/entered entries. A failure releases only the matching attempt after its native cleanup; it cannot clear a newer request or another live output. A failed in-progress opening must stop its just-started watcher/listener as existing error paths require before its entered protection is released. Existing pure test fixtures using begin_open/publish_open must migrate deliberately or use a test-only fixture helper; production must have no bypass to unguarded target-free publication.

Before any output directory is created, reserve_output performs one atomic gate transaction: verify the export source ticket if applicable; compare the held proposed output footprint with all protected opening scopes; re-run the existing selected/app-data external-write exclusion and original source/input separation; reject another output slot; then install the reservation and consume the admitted source expectation. Check/Restore do not need the original source still active, but they must perform these current-opening checks. For Restore, full input validation may complete under the single worker slot before reservation, since it writes nothing; no SQLite reader from that validation survives into reserve_output. Create reserves first, then opens its original selected Source outside the gate. Path/root observations are bounded and no SQLite/ledger lock is entered inside this gate.

This orders every race. If opening admission wins, the new candidate is in a protected requested/entered/published slot and the copy refuses before its first write. If output admission wins, request_open and enter_open refuse an intersecting scope before opening effects; publish rechecks as defense in depth. A request already entered before output admission is protected even when public active_root is None. An unrelated candidate passes and may complete while the copy continues from its original source.

## Footprints, first write and publication

Compare destructive intersections in both directions, not string equality: candidate/output may contain the other. Resolve native-chosen aliases and nonexistent tails with the existing bounded path semantics, preserve case/collision checks from the portable library, and refuse symlink/identity changes rather than following a replacement. Compare the complete output container for Restore, not only Pages, and the entire bundle root for Create. Include source bodies, source metadata, checked input and the installed selected workspace namespace in separation checks. Do not prohibit the common parent merely because an unrelated sibling lives there.

Before creation, the footprint is the held parent identity and one absent leaf plus canonical candidate location. Once mkdir succeeds, record the created directory identity in the same live footprint before any descendant content writes. Opening checks use canonical ancestor/descendant comparison and bounded physical ancestry/scope checks, so an alias or observed relocation cannot turn an overlapping request into an unrelated one. If a footprint's original identity/location cannot be reconciled, refuse the conflicting open/copy rather than treating it as absent. Do not scan the whole filesystem to find a moved directory. P1's bounded recursive admission must be applied to an opening/root traversal; exact-file doors retain their exact-path scope so unrelated mixed-root siblings remain usable.

The output holder must be passed into the first-write and final-publication paths, alongside held directory choices. It remains registered until the copy and all final checks/publication finish and all resources that may write are closed. It is not cleared by pending expiry, vault switching, UI unmount, window destruction, lost IPC acknowledgement or an error before the worker has unwound. At first mkdir and final manifest/marker publication, assert that this operation still owns its live lease and revalidate the descriptor/path anchors. Current-opening exclusion at those points follows from the continuously held gate reservation and mandatory opener checks; do not call ActiveRoot while holding SQLite to perform a fresh snapshot check.

P1 bounded traversal happens in the native admission/enter phase before opening side effects. Do not expand ActiveRoot into a long tree-scan lock: capture the bounded candidate/scope observation outside the mutex, then compare the current output footprint and revalidate relevant root/ancestor identities under it. A newly installed output is always compared at the gate, so a traversal result collected just before reservation cannot bypass it. The exact integration must preserve P1's own mutation-time path guards for later filesystem changes.

A small footprint mutex may protect its transition from absent leaf to created identity: opener order is ActiveRoot → footprint; the worker only takes footprint without ActiveRoot and releases it before any other lock. The worker never acquires ActiveRoot while holding footprint. Reserve/release only operate before acquiring and after dropping Source/SQLite/ledger resources. No callback from a library copy may take ActiveRoot in reverse order. Reservation removal after final cleanup is the only transition that permits a later overlapping open; after Restore, P1's persistent marker denial independently continues to refuse it.

This is coordination of Cerebro's admission and owned descriptor writes. It is not an OS-wide filesystem transaction or a promise to stop another process renaming files. Original path/identity changes remain typed refusal under the existing descriptor validations; no replacement tree is accepted or overwritten. A partial-output report distinguishes known original display location from a currently verified location. Do not claim an externally moved copy remains at its former spelling.

## Command and wire contract

Use generated Rust DTOs, added to workspace_service::tests::schema_bundle and the existing shared/workspace/contracts.v1.json → scripts/contracts/generate.ts → generated workspace TypeScript pipeline. Extend finite authority.v2 nativeCommands rows with the actual handlers. No command is left to unknown/default policy, and a global token command's policy row does not replace its private exact-window/choice checks. All desktop calls go through ipc.ts; demo fixtures return explicit preview outcomes.

| Proposed command | Renderer input | Native behavior/result |
| --- | --- | --- |
| workspace_backup_availability | expected vault selector | Current published selected/legacy/unavailable/platform result with bounded label; no persistent source reader |
| choose_workspace_backup | expected vault selector | Authenticate real window, capture selected opening, claim chooser slot, native existing-parent dialog, anchored fresh leaf; recheck and return review token or cancellation/refusal |
| check_workspace_backup | none | Authenticate, native bundle directory choice, one full bounded validation, return summary and compact checked-input token; no output |
| choose_workspace_restore | checked-input token | Authenticate and consume exact input choice, native existing-parent dialog, retain original input identity/digest and anchored fresh container; return restore review token |
| commit_workspace_backup | review token only | Consume matching Pending once, claim Running before scheduling, validate native admission and source handoff; return accepted operation identity or immediate typed refusal |
| commit_workspace_restore | review token only | Same bounded handoff, revalidate original input and reserve current output scopes; no source selection/registration |
| cancel_workspace_backup_choice | token only | Release only that exact window's matching Pending choice; Running returns already_started and is not cancelled |
| workspace_backup_operation | none | Exact native window reads its single bounded current or terminal operation, including origin labels; supports remount/reload without replay |

An accepted operation ID is issued from the chosen workflow before copy completion. Native Running state is retained even if its commit response is lost. A status read returns none, choosing, pending, running or terminal for this window; it never recreates expired choice authority. A duplicate commit cannot enqueue a second copy; return already_started/status or invalid_choice according to the retained exact operation, never execute again. No polling spawns work; an app-level owner can poll only while Running and mounted, using the existing IPC adapter without an additional persistent job service.

BackupSummary includes validated workspace ID, portable/schema version, canonical body count if supplied truthfully, part count, decimal-string byte totals, fixed category facts, omissions and validated_backup/restored_inactive state. It contains no raw manifest, per-part names or secret hashes. Counts use the manifest/database classifier's actual meaning. A retained count must not be relabeled as separate comments, originals or Trash counts unless a reviewed classifier truly establishes those categories.

Use typed tagged outcomes: cancelled, review, started, completed, refused and already_started where appropriate. Preserve AuthorityError and BackupErrorKind variants instead of reducing them to prose. Add coordinator errors for busy, invalid/expired/wrong-window choice, stale opening, output overlap, changed choice, destination unavailable and unknown outcome. A refusal carries output disposition: none_created; incomplete { display location, location verification state }; or completed_but_response_unavailable when native still knows completion. Distinguish a successful durable library publication with a failed later presentation read from an uncompleted copy. Do not invent partial_success for an invalid required part. UI actions catch and render these outcomes under CV-03, with a persistent local status and actionable draft links; no automatic write retry.

## Save ownership and presentation lifecycle

Create is reviewed first, then the app-level workflow owner captures its current presentation { vaultPath, getVaultOpening() } and awaits the existing flushOpenPages. This includes retained/unmounted owners, child draft preparation, body then field saves and fresh unresolved owners. If any outcome failed/blocked/pending, unresolvedOwnerIds remains nonempty, or a fresh unresolvedOpenPages check finds a new generation before invoking commit, remain blocked and preserve those owners. No body is serialized directly to the backup and no save acknowledgement is invented.

After every await, compare the original presentation opening and workflow operation identity. A switch or same-path reopen before native admission invalidates the pending export and requires a fresh choice. Recheck immediately after flush and make the final synchronous unresolved check before invoking commit without another asynchronous gap. The native SelectedBackupOpening check remains authoritative against a concurrent native opening; the frontend counter is only presentation scope.

This is a barrier for existing acknowledged saves, not an editor freeze. Edits arising after invocation continue through their existing owners and may be beyond the admitted coherent snapshot; the UI says the backup contains saved content, not every draft typed until completion. Source::open and its existing workspace lock/transaction define the snapshot; if the library detects a concurrent change it refuses. Do not add a Rust boolean that pretends to certify renderer drafts or a parallel save writer.

Own workflow state outside Settings component lifetime (a small app-level/store adapter). Pending Create reacts to opening changes and invalidates; checked input and pending Restore remain tied to their native input, not the current vault, and will use current native output guards at commit. Running is always bound to its original operation/source label. Switching away, remounting Settings, or an away/back same-path presentation change cannot relabel a completion as a backup of the new opening. A completed original-source operation may appear as a separate explicitly labeled result; it must not write current-vault success state blindly.

On remount/reload, query workspace_backup_operation after attaching to the live native window. If native still knows Running/Terminal, display that result. If the process restarted or its single outcome was discarded, show outcome unavailable and offer an explicit Check of the saved location; never retry automatically. Unknown is not cancelled, failed or succeeded.

Quit remains the existing shell contract: the guarded close/quit requests page saves and has a five-second deadline; forced OS quit paths can terminate without preparation. This slice does not extend that deadline or promise the copy survives exit. A still-running copy may leave an incomplete directory; retain it, never delete it automatically, and let explicit later Check reject incompleteness. No durable resume token/history is added. Runtime-state cleanup after window destruction must keep the worker/lease resources owned for as long as the process continues.

## Lock and resource order

| Phase | Allowed ownership/order | Prohibited |
| --- | --- | --- |
| Main-thread/window/dialog observation | No book, ActiveRoot, OPEN_LOCK, owner, listener, workspace, ledger or SQLite lock | Waiting for main thread under native/storage locks |
| Book transitions | Book mutex only; authenticate before taking another caller's token; take owned state and release | Filesystem work, ActiveRoot, dialogs, callbacks or waiting under book |
| Opening request | ActiveRoot → observed identity/footprint bounded checks; release, then existing agent begin; acquire OPEN_LOCK with no ActiveRoot held | ActiveRoot → OPEN_LOCK wait; reverse listener/native-owner → ActiveRoot |
| Opening entry/publication | OPEN_LOCK → ActiveRoot → existing observed/connector/listener order; no SQLite held at entry | Calling publication under SQLite/ledger or deferred binding after gate release |
| Commit admission | ActiveRoot → observed identity/footprint; compare original held identities and install lease; release | Entering source WorkspaceLock/SQLite or waiting for a worker inside gate |
| Copy/check | Existing portable Source/WorkspaceLock/pinned SQLite/ledger ordering; rooted descriptor operations; footprint-only short update | ActiveRoot/book/main-thread work while storage resources held; extra source database FD |
| Finish | Drop copy resources and close writers/SQLite/ledger, then release output under ActiveRoot; then terminal book update | Early lease release on timeout/error/unmount; ActiveRoot → book nesting |

Use an explicit outer scope/RAII guard for cleanup; field order alone must not accidentally release OutputReservation before Source or writer handles. Unwind/panic and failed scheduling require the same ownership proof. If native state is poisoned or original footprint cannot be checked, fail closed with typed unavailable; never fall back to path-only copying or unguarded legacy admission.
