## Risks the references expose

- **The implicit backup is lost.** Today properties, relations and grants ride git and iCloud inside YAML. After cutover they exist only in app-data. A lost Mac or wiped app-data leaves bodies with no metadata. Morrow and TD both treat app-private data as needing its own backup (A06).
- **Schema text drift bricks every store, and fixture tests cannot see it.** AFFiNE's migration-3 incident is the precedent (A01).
- **One outside edit blanks the workspace.** A VS Code edit, `git pull`, iCloud or Claude Code's own Edit trips `SourceChanged` or an unpaired body today. AFFiNE and Morrow isolate failures per doc (A03, A04).
- **Attribution is never recorded.** Selected writes skip `vault_writes`. History and page attribution read it (both `unsupported_selected` today, so they fail closed), and CV-48 will once agents run on selected workspaces. Outline's after-commit enqueue shows the crash gap a relay must close (A02).
- **Property history leaves Git.** Receipts hold hashes only; Outline keeps changesets (A14).
- **The tempting shortcut is the DB in the vault.** AFFiNE's disk-sync keeps a WAL DB in the synced folder. Only non-live exports belong there (owner decision 2).
- **A second process.** CV-21 path locks are in-process. The selected store's flock (`selected_store.rs:170-200`) covers selected writes; legacy writers have none. Morrow takes a single-instance lock (`M/electron/main.cts:98`) [read]. Check `open -n` before activation.
- **APFS folds case; `records.path UNIQUE` does not.** `check_pairing` compares paths exactly, so a Finder case-only rename refuses the whole workspace (A03).
- **Paging under background writes.** Snapshot-bound offsets go stale whenever an agent writes (A10).
- **Hidden backup failures.** AFFiNE only logs `trashWorkspace` failures. Snapshot and export failures must surface (A06, CV-05/06).

## Owner decisions

1. **Field identity (A13):** stable field IDs before the first real `workspace.db`, or name keys (simpler; CV-40 batches stay)?
2. **Snapshot placement (A06):** app-data rolling snapshots only? Or also a non-live, deterministic JSON metadata export inside the vault, so git and iCloud carry properties again? It would be restore-only, never read as authority. To ride git it must sit outside `.cerebro/` (ignored, `git/commit.rs:75`), exclude mail-derived values (CV-59), be skipped by the scan, and be read only by `restore_workspace`.
3. **Field-level history (A14):** should receipts keep previous/next values? For how long? Should mail-derived fields be excluded?
4. **CLI writers on selected workspaces (A04):** deny Claude Code's `file_write` tools until reconciliation exists, and Bash too, or accept Bash writes as outside edits? Agents keep the MCP doors once those are adopted.
5. **Webview state that travels (A08):** which `cerebro.*` keys move with a backup or migration (favorites, tree order, issue prefixes)? Re-keying goes through `src/app/pointers.ts` (CV-53).
6. **Unused attachments (N01):** a reviewed "unused → Trash" list, or missing-target reports only?
7. **Features that fail closed (A12):** which may stay unavailable on selected workspaces at activation?
