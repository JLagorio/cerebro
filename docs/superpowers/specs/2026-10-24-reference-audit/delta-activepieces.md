## Top findings

- **Every colour step has one job, in both themes, and a test enforces it.** Activepieces uses 5 scales of 12 steps. Step 11 is always the low-contrast text, step 10 always a mark that must reach 3:1, and so on. Every step is written out separately for dark. A generator raises or lowers steps 10 and 11 until they reach 3:1 and 4.5:1, and a drift test fails if the CSS stops matching the generator. Cerebro's dark block (`src/styles/tokens/colors.css:231+`) redefines only 4 of 10 cortex steps and 2 of 8 synapse steps, yet raw steps are used about 812 times. Two of those uses compute to **2.2:1 and 1.7:1 in dark** [calc] (APC-01/02). → **Amend M94.2; NEW:colour-contract.**
- **Activepieces' lint asks Tailwind itself whether each class exists, and fails any `var(--x)` that nothing defines.** Cerebro checks classes with regexes and has no check for undefined variables. This audit's scan found `--info-700`/`--info-50` (`src/knowledge/FacetChips.tsx:27`), which nothing defines, and an undefined `--danger` whose raw `#b42318` fallback therefore always paints (`src/workspace/RootMountDialog.tsx:65`). That is the same failure `colors.css:42-55` already records twice (APC-04). → **Adopt into M94.1.**
- **The empty-or-failed decision is a required prop.** `DataTable` will not compile without `isError` and `errorStateEntity`, which surfaced four tables that had no error state (decision 000032). Activepieces' hand-written surfaces have no such guard, and one of them shows a failed diff as "No changes to apply". In Cerebro, 32 files hand-roll `unavailable` unions (APC-05). → **Amend M94.8: a shared `Read<T>` plus a `ReadView` whose branches are required.**
- **Settings pages are built from named primitives:** Page → Header → Section → Panel → Row (`role=group`, `aria-describedby`) → sticky SaveBar. Cerebro's Settings rows do not link their hint text to the control (APC-07). → **Amend M94.2/M94.8.**
- **Builder honesty for M98:** a step marks its test result stale with "needs-test" once `lastUpdated > lastTest`. Test is disabled while saving, and the disabled control says why. Any version opens read-only in the same editor (APC-08/12/13). → **Amend M98.5/M98.9.**
- **One output schema drives both the Friendly/Raw result view and the mapping picker** (APC-10/11). → **Amend M96.6, M98.9.**
- **Don't import the weak half.** Activepieces' builder save queue halts on its first failure and drops every later edit. A loading button replaces its label with a spinner, its z-indexes are ad hoc, its 38 animated icons ignore reduced motion, it uses viewport-only breakpoints, and it has 4 e2e specs. Cerebro is already ahead on every one of these (see Avoid).

### APC-01/02: the colour contract

- **Activepieces' generator:** `brandColors.ramp({hex, scale})` → `nearestFamily({hue})` → `familyRamp`. Light steps come from shades `25…900`. Dark steps 1–8 sit on a fixed lightness ladder `14 17 20.5 24 27.5 31 38 47`, and dark 10–12 = shades 400/300/100. `readable(base[11], grounds+tint, 4.5)` and `readable(base[10], markGrounds, 3)` then adjust lightness in 0.5 steps. Step 9 is the seed hex itself, and `onSolid` is whichever of black or white measures higher. The CSS reads `--accent-3: var(--accent-light-3, <default>)`, so seeds override on `<html>`.
- **Its tests:** `status-scales.test.ts` reads both theme blocks and asserts every step equals `defaultRamp`. `brand-colors.test.ts` asserts the contrast floors for every seed and every swatch.
- **Proposed Cerebro version** (no generator): a role table `step → job` (text 4.5:1; marks, and borders that are a control's only boundary, 3:1) and `PAIRS: [ink, ground, floor][]` covering every ink-on-ground pairing components use (opt pills, avatars, link, AI ink, raw steps). `contrast.test.ts` iterates `PAIRS × {light, dark}` and also asserts that every raw step used in `src/` has a dark value, or is listed as theme-invariant with a reason. Expected first failures: synapse-600/700 in dark [calc]. A token migration follows only after owner review (`composition-sheet.md`: "No radius or color-token migration is part of this slice").

### APC-04: the lint rail

- **Activepieces' flow:** walk `src/**/*.ts(x)` → collect class tokens from the AST (`collectStrings`, `collectCvaConfig`, `follow`) → `design.candidatesToCss(candidates)`. A token is unknown when it generates nothing, is in no stylesheet's class set (`collectStylesheetClasses`) and is not allow-listed. The variables half: definers = every CSS `--x:` plus every TS `'--x'` literal; uses = every `var(--x`; unknown = uses − definers − runtime prefixes (`--tw-`, `--radix-`, `--shiki-`, `*-seed`, ramp overrides). Output is `file:line:col`.
- **Cerebro adaptation:** a vitest at `src/styles/variables.test.ts`. Definers also include `style={{['--x' as string]: …}}` and `setProperty('--x')`. Allow-list `--bn-*` and the dynamic prefixes (`--opt-`, `--swatch-`, `--canvas-`) with reasons. A fallback is **not** an exemption unless the variable is listed as a runtime hook (`--working-ink`). That rule is exactly what catches the `--danger,#b42318` case. The class half helps less, because Cerebro mostly uses `cb-*` CSS on a reset Tailwind. Run it on non-`cb-` tokens.

### APC-05: a required read state

- **Activepieces:** `DataTableProps{ isLoading; isError; errorStateEntity; onRetry?; emptyStateTextTitle; emptyStateTextDescription; emptyStateIcon; emptyStateAction? }`. Branches go loading → rows → `isError` → empty. Two gaps remain: rows that went stale after a failed refetch carry no signal, and hand-written lists have no guard.
- **Cerebro sketch:** `type Read<T> = {kind:'loading'} | {kind:'ready';data:T} | {kind:'empty'} | {kind:'not-recorded'} | {kind:'partial';data:T;missing:string} | {kind:'unavailable';reason:string}`. Then `ReadView<T>({read, ready, empty, notRecorded, partial, unavailable, retry?})`, with every render prop required and no defaults, rendering through `StateMessage`. Lab presets are built from the same union, so CV-44's five states are complete by type. Migrate the 32 hand-rolled unions only as M94.8 touches each surface.

### APC-12/13: draft status and versions in the editor

- **Activepieces:** `DraftStepStatus = 'invalid'|'testing'|'failed'|'needs-test'|'tested'|'untested'`, derived in the order above. `testDisabled = saving || !stepIsValid || isLoadingDynamicProperties`. A version is viewed in the same builder with `readonly` set.
- **Cerebro (M98):** `PreviewReport{ draftRevision, definitionDigest, clock, … }`. The editor compares `draftRevision` with the current draft and shows the preview as `current | stale`. An effect-free preview may run on the unsaved draft (M98.9 already says so), but a rehearsal (M98.6) and a Run need a saved, published revision. `restoreVersionAsDraft(versionHash, expectedDraftRevision)` is one human batch (CV-38/39), so Undo brings the replaced draft back.

### APC-19: agent references

- **Activepieces:** a live `agentId`; "Detach & customise"; deletion refused inside the `DELETE` statement. The decision page itself says a race after that snapshot can only be closed by the writer of the reference, at publish.
- **Cerebro options:**
  - **Live:** a workflow step stores the Agent page's stem link (CV-41), and the M97.3 run manifest records the hash of the agent bytes that actually ran.
  - **Pinned:** the published version stores the agent's content hash, and a run refuses a changed agent until someone republishes.
  - **Either way:** publish validates the reference under the agent page's path lock (CV-21), and a Trash or rename of a referenced agent is flagged before anything moves (CV-40/41).

## Avoid / doesn't transfer

- **A save queue that halts on the first failure.** `flow-state.ts:182-216` (`updateRequest`) catches the error, calls `flowUpdatesQueue.halt()`, and every later edit is dropped (`promise-queue.ts` `run()` returns while halted). `saving` stays true, and a sticky "Unsaved Changes… please refresh" toast appears (`features/flows/api/flows-api.tsx:34-50`), but refreshing discards those edits. M93.1/M93.2's retained generations are the right answer already.
- **A tables client/server mirror keyed by array index** (`features/tables/stores/store/ap-tables-server-state.ts`). Queued deletes shift the indices the later queued updates rely on. This conflicts with one-writer files and receipts.
- **A seed-colour or white-label runtime:** Cerebro has no tenants. Take the contract and the tests, not `brandSeed`. The one exception is if the owner wants a user-chosen accent (Owner questions).
- **A `keyboardShortcut` prop on Button that adds its own `document` keydown listener** (`components/ui/button.tsx`), and the builder's `useHandleKeyPressOnCanvas`. CV-47's single keymap is ahead.
- **Ad hoc z-index** (`z-50` ×38, `z-9999`, `z-55`, `z-51`…) [grep]. Use a depth scale (OUT-3).
- **38 hover-animated icons on `motion/react`, none of which honour reduced motion** [grep], plus per-word blur-in for streamed chat. That conflicts with VS12, and Cerebro's motion tokens and tests are ahead.
- **Viewport-only responsiveness** (`hooks/use-mobile.ts`; 2 container queries in the whole app) [grep]. Cerebro's pane container queries are ahead.
