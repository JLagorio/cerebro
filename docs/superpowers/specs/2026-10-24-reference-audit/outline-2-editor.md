# Outline editor (ProseMirror, Markdown fidelity, menus, comments, revisions) - reference audit 2026-10-24

> **Scope:** slice OUT2. Outline's ProseMirror editor: schema and Markdown grammar, JSON vs Markdown storage, suggestion/block menus, paste, mentions, embeds, tables, comment anchoring, revision diff, find/replace, version gating, large-document performance, tests. Judged against Cerebro's BlockNote editor, CV-24 carriers, title projection, comments sidecar (CV-31), History, mermaid, and M93/M94/M97/M99.
> **Read:** ~55 Outline files (`shared/editor/**`, `app/editor/**`, `server/editor`, `server/models/helpers/{DocumentHelper,ProsemirrorHelper}.tsx`, `server/collaboration/EditorVersionExtension.ts`, revision processors, comments API/store), ~35 Cerebro files (`src/editor/*`, `src/engine/{commentAnchor,proseDiff}.ts`, `src/git/*`, `src-tauri/src/vault/{comments,quote}.rs`, BlockNote 0.46.2 dist where Cerebro delegates), and the M93/M94/M97/M99 specs/plans plus the implementation record.
> **Licence:** Outline is BSL 1.1: **ideas only, no code copied**, so no Outline pattern below is "adopt"; every take is a re-implementation ("adapt"). Libraries Outline uses are separately licensed and can be taken from upstream, never from Outline's tree: `prosemirror-changeset` (MIT, already in Cerebro's `pnpm-lock.yaml` via `@tiptap/pm`), `prosemirror-recreate-steps` (Apache-2.0; Outline vendors a modified copy at `shared/editor/lib/prosemirror-recreate-transform/` with its own LICENSE/NOTICE), `markdown-it-container`, `es-toolkit` (MIT).

## Top findings

- **Cerebro serializes the entire page on every keystroke. Outline never does.** Outline's `onChange` hands over a lazy `value()` getter and serializes only when it saves. Cerebro's `scheduleEmit` runs `blocksToMarkdownNow` on each change, which means a JSON deep copy, BlockNote's HTML export, then rehype→remark→stringify. It does this to feed `owner.edit()`. A second per-update cost: `pageTitleProjection` rebuilds one node decoration for every top-level block on each view update. **M93.1/M93.6/M93.7:** measure keystroke latency on long pages, then keep only a generation number per keystroke and serialize at debounce, flush, unmount and retry.
- **Source landing needs a position map built from the parse/serialize pipeline, not a second grammar.** Outline's serializer emits `{pmFrom,pmTo,mdFrom,mdTo}` for each top-level block, then maps text→PM positions inside the block with atom-aware segments. Cerebro's `mapSourceRange` re-parses the body with its own small grammar. Any mark, `*`, `_`, backtick, `|`, `&`, CRLF, multi-line paragraph, directive or nested child gives "unsupported", so most real pages cannot land. **M97.2.**
- **Outline compares against a round trip of the original, which separates "the edit changed it" from "the normalizer changed it".** It uses this to merge agent Markdown patches into rich JSON. Cerebro has the opposite problem: a one-word rich edit re-normalizes the whole file (bullets, padding, escapes; "accepted" in `markdown.ts`). The same comparison would let a rich save keep the original bytes of blocks it did not change. **NEW phase beside M93.8; owner decision.**
- **Outline shows what JSON-first costs.** Its Markdown is "a lossy conversion… only for export". Comment marks, toggle ids, highlight colours, column widths and embeds all drop out, and `__x__` is repurposed as underline. Cerebro does the right inverse: CV-24 gives every offered block a carrier, `UNCARRIED_ACTIONS` withholds the rest, and M99 keeps Markdown bodies. **Confirm M99.5/M99.6.**
- **Comments: Cerebro's text anchors already beat Outline's.** Cerebro records which occurrence is meant and shows an explicit detached state. Outline takes the first prefix/suffix match. Three gaps remain: Cerebro can't anchor to non-text blocks (Outline anchors images by node-hash), comment reveal doesn't open folded toggles, and a failed agent quote gets no "closest text" hint. **NEW:comments, NEW:agent-tools.**
- **Toggle fold state is lost on every reopen and leaks storage.** BlockNote's default stores `toggle-${block.id}` in localStorage, and Cerebro's block ids are regenerated on every parse. Outline keeps a stable toggle id in a bounded LRU (500 entries) per viewer. **NEW:editor-polish (M94.3).**
- **Input details that IME and Markdown users hit.** Outline accepts a full-width `＠` mention trigger and opens menus during IME composition. It parses VS Code copies in markdown mode as Markdown, where Cerebro turns them into a code block. Its find is diacritic-insensitive and maps indices back to the original text. **M93.11/M94.9 IME cases; NEW:editor-paste/find.**

### Key flow A: lazy materialization and structural-change gating (OUT2-01/02)

- Outline: `EditorView.dispatchTransaction` → `handleChange({remote})` → `props.onChange(getter)`. The getter calls `serializer.serialize(view.state.doc)` only when it is invoked. Save reads `editorRef.view.state.doc.toJSON()`.
- Cerebro adaptation, no new writer:
  - Keystroke: `owner.edit(thunk)` bumps `generation` and records a materializer bound to the editor instance.
  - Materialize at the debounce emit, `flush()`, `prepareLeave()`, `retry()` and the existing unmount flush (`MarkdownEditor.tsx` unmount effect). REL-01's "exact latest text through presentation unmount" still holds because unmount materializes first.
  - Dirty stays generation-based (REL-01). No text is needed to know the page is dirty.
- `pageTitleProjection`: hold the `DecorationSet` in plugin state. On `isInlineTransaction` map it; rebuild only when a top-level block is added or removed, or the first H1 changes. Emit node decorations only for the title block, plus body blocks while the body is hidden.
- Measure first (M93.6): `keydown→next frame`, `serialize ms per change`, `decorations ms per update` on `document64KiB` and a 2,000-block page. Outline has no editor virtualization (grep: no `content-visibility` in `shared/editor`, `app/editor`). It keeps per-transaction work small instead, which backs REL-08's stance.

### Key flow B: pipeline-derived source map for M97.2 (OUT2-03)

- Outline, two levels. (1) `renderContent` pushes a `BlockMapEntry` per top-level child. (2) Within a textblock, `segments[] = {textFrom,textTo,pmFrom,pmTo,isAtom}` and `textToPmOffset`. When Markdown ≠ text (marks, atoms), find the quote in `blockNode.textContent` and refuse if an atom overlaps.
- Cerebro already has level 2: `readerText(doc)` gives `posAt`/`offsetsOf` with chips as whole atoms, and `commentAnchor.validMatches`/`resolveAnchor` handle uniqueness and context.
- Missing piece: level 1, from raw body bytes to the editor's top-level block. Candidates to spike against M97.2's construct matrix:
  - (a) Extend `blocksToMarkdownNow` to record top-level block boundaries through its existing placeholder/set-aside machinery. Accept the map only if the full output equals the raw body byte for byte (canonical file).
  - (b) Run remark-parse on the raw body (already a transitive BlockNote dep). Pair top-level mdast `position` spans with editor blocks by order and kind, folding `:::` containers the way `promoteContainers` does.
  - On any misalignment the result stays `unsupported`.
- Within the block, require one match (KNOW-02). Outline's `indexOf` takes the first match, which must not carry over. Open folded toggles before selecting (OUT2-12).

### Key flow C: untouched-block byte preservation on rich save (OUT2-04)

- Outline: `parsed = parse(modified)`, `roundTripped = parse(original)`. A child equal to its `roundTripped` counterpart means the edit did not touch it, so the original node is kept.
- Cerebro, inverse direction:
  - At load, keep raw body `B0` and the canonical form of each top-level block, `c_i`, with its raw span `r_i` (needs flow B's level-1 map).
  - At save, for each current block with the same BlockNote id (ids are stable within a session; `reconcile.ts` keeps them for untouched blocks) whose canonical text still equals `c_i`, emit `B0[r_i]` and the original separators.
  - Guard: `parse(spliced)` must equal `parse(canonical)` block for block. Otherwise write canonical, as today.
  - The writer, lock and receipt are unchanged (CV-21/CV-33). Only the body bytes chosen differ.
- Payoff: one-word edits produce one-block git diffs. Hand or agent formatting survives. Fewer surprise diffs in History.

### Key flow D: comment anchors beyond text (OUT2-10/11/12/13)

- Keep Cerebro's v1 text anchor.
- Add a sidecar v2 anchor kind `{block: {carrier: media|fence|sheet|board, identity, occurrence}}`. Identity is the media URL or the fence/source content hash, analogous to Outline's `getNodeHash` (type + sorted attrs). Resolve it detached/attached exactly like text anchors.
- The `NEWER` guard keeps old builds read-only.
- `reveal(id)` should run `openTogglesAround` before `scrollIntoView`.
- For agents, `quote.rs` "not in the body" could append the closest line within a bounded edit distance. Only after the scope guard passes, since `an_unreadable_path_is_refused_before_any_match` already covers that ordering.

## Avoid / doesn't transfer

- **Y.js multiplayer, Hocuspocus, `EditorVersionExtension` as a server gate.** These need a server and CRDT. Cerebro is single-user, files are truth, and there is one writer per file (CV-21).
- **JSON or CRDT state as body authority.** It forces the loss list in OUT2-05. M99 rightly keeps Markdown bodies.
- **Comment marks inside the document.** Creating or resolving a comment would write page bytes and add undo steps. CV-31 sidecar plus decorations is right; `commentSpike.test.ts` measured BlockNote's mark approach.
- **Draft anchors for comment-only users.** They exist for a multi-user permission model.
- **Embed registry with iframes.** Cerebro's CSP is `default-src 'self'` (`tauri.conf.json` L27); CV-16 and CV-61 make remote loads click-gated. Page cards already cover internal embeds.
- **Private dialect choices:** `__` as underline (breaks CommonMark bold), `@[label](mention://…)`, attachment size packed into link text, image `=WxH` in the title. Other editors misread all of these. Cerebro's Obsidian-compatible carriers (`> [!kind]`, `![name|300]`, `[[…]]`) port better.
- **First-match semantics** in Outline's patch API ("The first occurrence will be replaced"; test "should always patch the first occurrence") and in comment anchoring. These are weaker than `edit_note`'s refusal plus `occurrence`, and than KNOW-02.
- **SmartText input rules on by default.** Typed `"`, `->`, `...` silently become different bytes in a file that agents grep and git diffs. Opt-in at most.
- **Pele mermaid renderer and Font Awesome icon packs.** Cerebro's mermaid stack (structural editor, `(theme, code)` render cache in `src/mermaid/render.ts`) is already deeper.
