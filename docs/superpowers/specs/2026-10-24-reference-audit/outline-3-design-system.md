# Outline: design system and components - reference audit 2026-10-24

> **Scope:** Outline's tokens/theme, depth scale, breakpoints, primitives, menus, command bar, dialogs, toasts, tooltips, hover previews, list selection, loading/empty/error states, a11y, motion, tests. Judged against Cerebro `src/components/ui/*`, `src/styles/tokens/*`, the keymap/catalog, the state lab, M94 and `plans/2026-10-22-ui-refresh-review/02-visual-system.md`.
> **Files read:** ~80 Outline (`shared/styles/*`, `app/components/primitives/*`, `app/components/{Menu,CommandBar,HoverPreview,List,…}`, `app/actions/*`, `app/hooks/*`, `app/stores/{DialogsStore,UiStore}.ts`), ~45 Cerebro.
> **Licence:** Outline is BSL 1.1 (`docs/examples/outline-main/LICENSE`): ideas only, no code. So every positive verdict below is **adapt** (rebuild the idea in Cerebro code); none is adopt. No third-party library is recommended for adoption.
> **Alias:** `O/` = `docs/examples/outline-main/`. **Basis:** [read] I read the code · [names] inferred from file/dir names · [docs] README/docs. Cerebro claims are [read] or grep counts, and none has been checked at runtime.

## Top findings

- **Cerebro has no React error boundary.** Grep finds no `componentDidCatch` or `getDerivedStateFromError` in `src/`, and `src/main.tsx` calls `createRoot` with no error hooks. Outline wraps 11 seams (`O/app/components/ErrorBoundary.tsx`). Today one bad sidebar section, rail card or hover card can blank the whole window. It also unmounts sheet, CodeOverlay and field buffers before M93.2's `prepareLeave` runs. → **Add M93.12, plus a consumer in M94.8.**
- **One action definition, many surfaces.** Outline writes each action once (name, icon, visible, disabled, dangerous, shortcut, perform). Dropdowns, context menus, the mobile drawer, the command bar, buttons and the bulk toolbar all draw from that one definition (`O/app/actions/index.ts`). Cerebro's catalog covers only keys, ⌘K and keycaps. Its menus are inline arrays in 10+ files, and the labels have drifted: "Rename" renames the file in `src/components/FileTree.tsx:603`, but "Rename…" rewrites the heading in `src/pages/DocPage.tsx:586`. → **Amend M94.5.**
- **`ContextMenu` doesn't follow the rules every other surface follows.** It has no `useLayer`, no key claim, sits at `z-50` (below Dialog at 1000 and Popover at 1050), uses a light-only literal shadow, and supports flat items only. Traced from source (not run): app-scope letter chords (`g …`, `c …`) still fire while it is open. In Outline a context menu is the same primitive as a dropdown with a different variant. → **M94.5.**
- **No depth scale.** Outline keeps one table, `O/shared/styles/depths.ts`. Cerebro has about 135 raw z-index uses with 15+ distinct values and no token. `src/components/ui/Popover.tsx:435` already records an ordering bug this caused. → **M94.2: depth tokens plus a lint rail.**
- **Toasts:** Outline's toasts are keyed, carry a tone and update in place (loading → success/error). Cerebro's `uiStore.toast(message)` only appends, with no tone, key, dedupe or cap, across 148 call sites. → **M94.8.**
- **Loading:** Outline delays its loading placeholder by 250ms and keeps the layout's shape while it loads. Cerebro shows loading text immediately at about 32 sites and has no skeleton. → **M94.8 / UX-10.**
- **Confirmed: Cerebro is ahead on several fronts. Don't port Outline components wholesale.** Outline's lists fall back to the empty state when a fetch fails (10 of 13 direct `PaginatedList` users). Its shortcut help is hand-typed. Its breakpoints are viewport-only. It has no component render tests. Cerebro's CV-05/CV-44, catalog-rendered shortcuts, pane-level container queries and per-primitive tests are better on each count.

### Key flows

**OUT3-01/02/09: action registry → presenters (Outline)**
- Definition: `Action = BaseAction & {variant:'action', perform(ctx), dangerous?}`. The other variants are `internal_link`, `external_link` and `action_with_children` (children may be a factory) (`O/app/types.ts`).
- Context: `ActionContextProvider value={{activeModels,isMenu,isButton}}` nests. `getActiveModels(Class)` checks local models first, then the parent context, then `ui.getActiveModels` (`O/app/hooks/useActionContext.tsx`).
- Menu: `DropdownMenu({action})`. While closed, `useComputed` returns `[]` and `hasVisibleActions` decides whether anything renders. When open, `actionToMenuItem` → `toMenuItems` → primitives (`O/app/components/Menu/*`).
- ⌘K: `useCommandBarActions(actions)` → `actionToKBar` flattens children with `parent` ids → `useRegisterActions(…, [ids, pathname])`.
- Bulk: `ModelSelectionActionToolbar({models, actions})`.
- Errors: `performAction` catches the rejection and calls `toast.error`.
- **Cerebro shape:**
  - Rows in `src/app/actions/*.actions.ts`, eager-globbed like the commands: `{id, label, icon, command?, danger?, appliesTo(target): {kind:'ready'}|{kind:'blocked',reason}|{kind:'hidden'}, run(target)}`.
  - `target = {entries, pane, surface:'row'|'page'|'selection'|'palette'}`.
  - Availability is pure, in `src/engine/actionAvailability.ts`: gated on capabilities (CV-08), the knowledge/ guard (CV-07) and agent-page rules (M55.12).
  - `run` calls only existing writers (`renameActions.ts`, `bulkActions.ts`) and follows CV-03.
  - `MenuItem` gains `command` (keycaps), and a blocked row draws disabled with its reason.
  - Rails: menu labels come only from the registry; one label maps to one action id.

**OUT3-06: render isolation (Cerebro shape)**
- `src/components/SectionBoundary.tsx`, a class component using `getDerivedStateFromError`.
  - It renders `StateMessage state="unavailable"` with Retry, which remounts the section by bumping its key.
  - It reports through `lib/diagnostics` without any vault path.
- Wrap each pane (`data-pane-index`), the page side-panel slot, every `data-section`, the assistant panel and each rail card, the Dialog body, HoverCard content and lab sections.
- Root: `createRoot(el,{onUncaughtError,onCaughtError})` reports to diagnostics. The root fallback offers "Reload window" only after reading `flushOpenPages()` (M93.2). Keep Outline's repeated-error window; drop the stale-chunk reload (packaged assets are local).
- Tests:
  - A throwing sidebar section leaves the editor pane and its `DocumentOwner` draft intact.
  - A crashed rail card leaves the transcript usable.
  - Rail: every pane and section host wraps a boundary.

**OUT3-03/04/05: overlay order**
- `Popover` gains an `anchorPoint` option (a virtual rect). `ContextMenu` then becomes `Popover role=menu` + `MenuSurface`, which brings a modal layer (so letters stand down), Escape ownership, focus restore, depth tokens and the ghost exit.
- `claims.ts` adds widget roles as a `typing` claim.
- Depth tokens such as `--z-sticky`, `--z-drawer`, `--z-dialog`, `--z-popover`, `--z-float` (tooltip, hover card, toast) live in `src/styles/tokens/` and map into Tailwind. A rail refuses raw z-index; local stacking uses `isolation:isolate`.
- Test: open a context menu, press `g` `p`: nothing navigates; Escape closes only the menu.

## Avoid / doesn't transfer

- **Lists where error rendering is optional.** If `PaginatedList` gets no `renderError`, a failed fetch falls through to `empty`. 10 of 13 direct users pass none; Notifications shows "You're all caught up." when its fetch fails (`O/app/components/PaginatedList.tsx`, `Notifications/Notifications.tsx`) [read]. This breaks CV-05; keep `StateMessage` and CV-44.
- **Hand-typed shortcut help.** `O/app/components/KeyboardShortcuts.tsx` lists 74 rows separately from where keys are bound, so the two drift. Cerebro renders its help from the catalog (M65.1b).
- **Progress bar as a boolean.** 18 `LoadingIndicator` mounts set and clear one boolean (`UiStore.enableProgressBar`/`disableProgressBar`), so the first to unmount hides the bar while others still load. If Cerebro adds a global indicator, use a counter.
- **Menus that don't return focus.** Menus pass `onCloseAutoFocus={preventDefault}` (`Menu/DropdownMenu.tsx`, `ContextMenu.tsx`), so keyboard users lose their place. Cerebro's `useFocusRestore` is better. M94.5's "opener vanished" fallback is still Cerebro's to build; Outline doesn't solve it.
- **Confirm button autofocused even when dangerous.** `ConfirmationDialog` autofocuses the submit button with `danger` set, so Enter confirms destruction. Cerebro's Trash plus Undo (CV-37/39) is the better pattern.
- **Runtime theming, mobile presenters, swapping libraries.**
  - styled-components `ThemeProvider` would be a second theme decider beside `data-theme`.
  - Drawers below 737px, pitch-black mobile dark and the touch `:active` hover don't apply to a desktop app with a 900×600 minimum.
  - Swapping Cerebro's primitives for Radix, vaul, kbar or sonner would discard `layers.ts`, the ghost exits and key claims, all already tested.
- **Stale-chunk reload.** No deploy can land between loads in a packaged Tauri app.
- **`corner-shape: superellipse`.** Chromium-only, so it has no effect in WKWebView.
- **WebMCP-style UI actions as agent tools** (OUT3-23). This would bypass manifest-derived reach and Rust dispatch (CV-28/29/32/46).
