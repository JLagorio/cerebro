# AFFiNE application, services and platforms — review completion, 2026-10-26

This completes the application-family comparison for the local `AFFiNE-canary` reference. BlockSuite/editor internals belong to the companion editor review. The useful transfers are narrower than feature parity: containment around independent views, explicit recovery identities, consistent list interactions, declared state ownership, and truthful progress/failure presentation. Cerebro should retain its existing workspace authority owners, creation and batch writers, personal CLI assistant, and desktop scope. Ordinary vault files and M99's selected workspace with canonical SQLite metadata are distinct authorities; this review does not propose reverting the selected design. AFFiNE's hosted collaboration, commercial administration, document database and provider runtime are different product boundaries.

This is a source review, not a runtime, security, accessibility, deployment or performance certification. No reference/application code was changed; no tests, builds, applications, providers or services were run. Recommendations below are candidates, not approved milestones. Earlier audit recommendations that named new milestone numbers are not authorization to implement them.

## Corrections to earlier comparisons

1. **Cerebro already applies page templates.** `C/src/app/applyPageTemplate.ts:1–101` flushes, waits for rescan, checks the vault, accepts only genuinely blank raw content, pins target/template hashes and submits one checked batch. AFFiNE's optional default page/journal template is additional behavior; “Cerebro has no templates” is wrong.
2. **Cerebro has backup and restoration implementation.** `C/src-tauri/src/workspace_service/selected_backup.rs:1–115,193–270` implements bounded selected-state snapshots; `workspace_migration/backup.rs:1–100` and `restore.rs:1–24` implement verified bundles and inactive restore. This is not proof of a public backup/restore/activation UI. The restore module explicitly excludes registration/activation/IPC. Any recommendation must extend the owning code rather than invent a second backup subsystem.
3. **Cerebro's managed credential bridge is no longer only a disabled test surface.** `C/src-tauri/src/credential_commands.rs:11–60` exposes production begin/poll/cancel commands. A late root reconciliation read `actions/native_account_commands.rs:256–298`: production now selects `NativeImport` on macOS and `Unsupported` elsewhere. `actions/native_credential_bundle.rs:32–47` constructs the native gh/identity/secret-store adapters under the original owner; `Unavailable` at `native_account_commands.rs:299–312` is smoke-only. This supersedes the earlier worker gate. `ManagedAccountSettings.tsx:307–310` still describes import as unavailable in that Settings surface; no live acquisition or provider check was run. Public commands, usable credential acquisition, provider execution and managed MCP routing are different acceptance boundaries.
4. **AFFiNE's TypeScript permission service is a wrapper.** `B/core/permission/service.ts:1–171` delegates to native `authorizePermissionV1`. `N/runtime/backend_runtime/permission/authorizer.rs:1–240` loads snapshots and runs checks inside relevant transactions, but the pure matrix is imported from external `affine_core` (`A/packages/backend/native/Cargo.toml:1–100`, version 0.0.8). The matrix itself was not available to review.
5. **Capabilities have build gates.** Both copilot tools and workspace MCP suppress create/update/meta-write tools outside dev/canary (`B/plugins/copilot/runtime/tool-runtime.ts:107–112`; `mcp/provider.ts:205–208`). Disk sync is Electron/canary and default-off (`F/modules/feature-flag/constant.ts:299–305`); mobile database editing is default-off at 306–313. Source presence is not stable release enablement.
6. **Not all “integration,” “theme,” or “tool” files implement what their names suggest.** Zotero is commented out (`F/modules/integration/constant.ts:1–63`); `section-edit.ts:1–52` generates replacement text rather than applying a document write; `A/packages/common/theme/README.md:1` says the theme package moved to `toeverything/design`. The local app theme bridge is only 22 lines.

## Architecture and authority contracts

### Application ownership and persistence

`F/modules/index.ts:1–139` registers common services. `WorkspaceRepo` pools normal workspace scopes, creates separate shared scopes, starts each engine, and disposes it through pool lifecycle (`F/modules/workspace/services/repo.ts:1–128`). Infra resolves cached services through scope/parent providers and invokes disposable instances (`I/framework/core/provider.ts:100–212`). This gives state a lifetime; it does not itself make state durable or authorize access. A service/entity/store split is useful terminology for review, but replacing Cerebro's pure engine, IPC adapters and stores with this framework would add migration cost without changing the relevant guarantees.

AFFiNE has at least four distinct state owners: document/workspace data, per-user workspace data, device/workspace preferences, and app-global state. The first two are explicit schemas: folders, custom property definitions, document properties and pinned collections versus favorites, settings and integration references (`F/modules/db/schema/schema.ts:15–85`). Cerebro's ordinary vault uses frontmatter/Type documents; selected-workspace metadata follows its separate M99 authority contract (`C/src-tauri/src/workspace_service/authority.rs:1–145` and the [authority decision](../2026-10-23-m99-workspace-authority-decision.md)). Its user preferences and grants already have different consequences despite sharing localStorage (`C/src/stores/uiStore.ts:608–658`). A future retention/export table must classify each, not copy all preferences or replay grants as harmless UI state.

Local engines connect doc/blob/sync/index/awareness stores and optional legacy/disk remotes (`F/modules/workspace-engine/impls/local.ts:400–539`). A native SQLite connection creates/migrates storage, supports read-only validation, full WAL checkpoint and `VACUUM INTO` (`L/nbstore/src/storage.rs:52–207`). A specific known migration checksum mismatch is repaired only when version, description and the historical whitespace checksum match; other mismatch errors propagate. This is evidence for a narrow historical repair, not permission to accept arbitrary drift.

Server composition depends on role (`B/app.module.ts:1–237`): API/frontend, sync/frontend, renderer, GraphQL, worker, self-host and GCP selections import different modules. Redis/cache/mutex/rate-limiter/metrics/transactional Prisma infrastructure sits beside native runtime, not beneath every possible role unconditionally. A GraphQL-generated type or frontend module cannot prove that a worker, provider, backend role or feature flag is present in a deployment.

## Remaining uncertainty and review boundary

The comparison covers every application module family and the requested user-facing feature families, with deeper fresh traces where earlier work stopped at names/wrappers. It does **not** claim a full semantic review of every source file or every operation in the repository. In particular: external `affine_core`, LLM/runtime/safe-fetch implementations and moved theme source are unavailable locally; many backend provider, renderer, updater, per-property editor and native media branches remain P/R; complete native IPC caller authentication for BYOK lease transport was not traced; the full financial reducer and calendar provider reconciliation were not reread; no OS runtime, real credential/provider, signing, screen reader, performance or crash-injection acceptance was performed.

The new source findings are still useful without those claims: transactional publish/comment authority, narrow migration repair, index checkpoint atomicity, share-import retry identity, native share/back implementations, native CI configuration, and current Cerebro backup/credential ownership are concrete bodies. Conversely, default-off flags, generated operations, commented integrations and wrapper-only methods remain visibly conditional. Future implementation should open only the relevant remaining branch, then verify it against the current owner rather than reopening this entire inventory or treating a mechanical census as semantic completion.
