# AFFiNE BlockSuite: editor, data views and canvas comparison

Review date: 2026-10-26. This is a source review and a set of **candidate decisions**, not an accepted milestone, an implementation plan, or a claim that the vendored application was run. Application and reference code were not changed. No dependency installation, service, provider request, or test execution was used.

The useful transfer is chiefly interaction design: explicit selection states, gesture boundaries, contextual commands, resource states, and measured rendering degradation. Replacing Cerebro's document owner, Markdown carriers, JSON Canvas model, or IronCalc engine with BlockSuite would change the product's storage and authority model. A larger feature count in a Yjs document is not evidence that Cerebro is missing the same feature in its own format.

### Architecture traces and failure boundaries

1. **Registration → schema → live model.** `A/affine/all/src/extensions/store.ts:1–72` assembles block, inline, graphics and foundation store providers; `view.ts:1–132` assembles their presentation providers and ordered widgets. `A/framework/store/src/schema/schema.ts:1–325` registers flavours, root/hub/content roles and parent/child constraints. `A/framework/store/src/model/block/sync-controller.ts:246–328` reads `sys:*` fields, rejects an unknown flavour, supplies a missing version from the installed schema, and writes missing default properties to the Y.Map during hydration. This is a live CRDT graph, not a read-only file decoder. The inspected path is not evidence of a complete schema migration protocol or future-version preservation. Cerebro's `src/editor/documentAdmission.ts:1–92` and `documentOwner.ts:1–230` instead retain one document payload, its generation and acknowledged writes, including pending/unknown/reconcile states. **Retain the Cerebro owner and no-write-on-open boundary.**

2. **Snapshot → conversion → mutation.** `A/framework/store/src/transformer/transformer.ts:250–328,422–697` validates the outer snapshot, runs middleware, converts drafts and inserts in batches. Ordinary conversion filters failed drafts; replacement asks for complete conversion, checks duplicate IDs and schema validity before clearing existing content. Clearing and the subsequent asynchronous insertion are separate steps in the inspected implementation: validation is not proof of rollback for every later failure. Errors commonly become console output plus `undefined`. Cerebro should require a complete proposed replacement or a visible loss report before its existing guarded write. `src/editor/markdown.ts:2120–2180` detects significant text loss/reordering and raw HTML; `src/editor/MarkdownEditor.tsx:830–860` checks the round-trip and `src/editor/NoteBodyEditor.tsx:457–480,2150–2190` locks rich editing until explicit adoption. This is useful but is not a general proof of byte fidelity.

3. **Clipboard → adapter priority → remapping → assets.** `A/affine/foundation/src/clipboard.ts:1–65` orders snapshot, Notion, HTML, image, text and attachment adapters. `A/framework/std/src/clipboard/clipboard.ts:1–323` embeds compressed private snapshot data in HTML, sanitizes HTML before extracting it, tries the private representation and falls back to public types. `A/affine/shared/src/adapters/middlewares/replace-id.ts:20–256` repairs database cells, page references, surface references, connector endpoints and group children when IDs change; it explicitly leaves linked block/element work as a TODO at line 107. `upload.ts:12–118` bounds concurrent uploads to five, aborts for removed views, hashes blobs, writes assets, then updates model properties. An aborted UI operation can still have performed asset work; the snippet is not transactional rollback. Cerebro's `src/whiteboard/clipboard.ts:1–122` writes before deleting for cut and executes one paste command; `src/sheet/clipboard.ts:1–42` refuses damaged private MIME and preserves quoted TSV. Retain these stronger failure contracts.

4. **Data view → source → typed property → mutation.** `A/affine/blocks/database/src/data-source.ts:1–185` reads database children and cells, injects external properties and derives read-only/mobile flags. `A/affine/data-view/src/property-presets/pure-index.ts:1–19` lists checkbox, date, image, multi-select, number, progress, select and text. The inspected preset directory and `affine/blocks/database` contain no `formula`/`Formula` implementation; external property injection means this is a bounded absence, not an assertion about all AFFiNE. `core/group-by/trait.ts:446–539` changes membership and ordering; calendar drop delegates to date mutations; table clipboard converts cells. These are record views, not a spreadsheet engine. Cerebro has **three separate systems**: saved record views (`src/engine/views.ts:1–210`), bounded number/date field arithmetic (`src/engine/formula.ts:1–155`), and page sheets calculated through IPC (`src/sheet/useSheetWorkbook.ts:1–118`). Preserve the distinction.

5. **Graphics tool → gesture → model → history.** Brush/shape/connector tools create and update graphics models; selection and capture boundaries are part of the interaction. `A/affine/gfx/brush/src/brush-tool.ts:1–200` detects actual pressure variation, batches points and separates drag history. `A/affine/gfx/group/src/command/group-api.ts:170–229` preserves child order during ungroup. `A/framework/store/src/extension/history/history-extension.ts:1–79` uses a Y.UndoManager tracking the local client. Cerebro's `src/engine/scene/history.ts:1–147` has deliberately different semantics: a step applies only while each item still matches its recorded pre/post side, reports skipped items and refuses to strand edges. Its retained save owner (`src/whiteboard/useCanvasFile.ts:1–170`) holds dirty scenes and drafts through a failure. Do not exchange this behavior for generic CRDT undo.

6. **Selection → awareness → rendering.** `A/framework/store/src/extension/selection/selection-extension.ts:1–185` saves selection in undo metadata, partitions awareness by editor/document identity and catches malformed remote selection. `A/affine/widgets/remote-selection/src/doc/doc-remote-selection.ts:1–150` renders passive overlays, subscribes to resize/selection/user state and has a missing-range fallback. `A/framework/sync/src/doc/engine.ts:1–280` loads the main store before starting shadows, exposes retry/sync states and waits for main pending pushes during graceful stop. This demonstrates editor collaboration machinery, not permission enforcement or a server persistence guarantee. Cerebro's external-file reconciliation is not real-time multiplayer; adding presence would need a separate product and authority design.

7. **Rendering → visibility → resource lifecycle.** `A/framework/std/src/gfx/grid.ts:280–376` searches spatial buckets, excludes hidden models and orders matches; `gfx/raf-coalescer.ts:1–76` coalesces to the newest payload with explicit flush/cancel. `A/affine/gfx/turbo-renderer/src/turbo-renderer.ts:290–431` switches between DOM and cached bitmaps, versions worker replies and closes stale bitmaps. `A/affine/blocks/surface/src/renderer/canvas-renderer.ts:63–188` names pixel/memory/layer metrics and device-specific degradation. These are candidate measurement and scheduling patterns, not evidence that the more complex renderer is faster for Cerebro's bounded JSON Canvas workload.

8. **UI command → carrier → owner.** `A/affine/widgets/toolbar/src/utils.ts:154–208` merges action groups and filters actions against current context; `keyboard-toolbar/src/config.ts:1–160` describes action/visibility/disabled contracts. That architecture is useful only if every command routes through its owner. Cerebro already intentionally omits underline, arbitrary text color/alignment and merged-cell actions that cannot survive its carriers (`src/editor/SelectionToolbar.tsx:87–99`). It already uses native labelled icon buttons, shared menu keyboard behavior and layered popover dismissal. Reuse those primitives rather than importing BlockSuite's Lit component layer.

## Feature matrix

“Retain” protects an existing Cerebro behavior; “adapt” is a candidate improvement through current owners; “defer” requires a new product/carrier decision; “reject” rejects the particular transfer, not the entire reference feature; “investigate” requires evidence before selection. Acceptance examples are prospective checks, not tests run in this review.

## Design-system and interaction contract for any adaptation

The reference shows why a feature cannot be copied as a screenshot. Selection, resource status, pointer gestures and menus each have owners and cleanup conditions. In Cerebro the following contract applies to every “adapt” row above:

| Component / state          | Contract grounded in current code                                                                                                                                                       | Concrete acceptance                                                                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Toolbar/icon action        | Use native `IconButton` with required accessible name, `aria-pressed`, native disabled and focus treatment (`src/components/ui/IconButton.tsx:27–88`).                                  | Space and Enter work; the active tool is announced; a disabled action cannot mutate via shortcut; no hover-only action.                                          |
| Menu and nested picker     | `MenuSurface` handles navigation, while `Popover` handles layer ownership/dismissal (`src/components/ui/Menu.tsx:1–170`, `Popover.tsx:81–155`).                                         | Editor selection survives opening its action menu; child Escape closes only child; focus returns to the correct pane/opener; IME owns confirmation.              |
| Format/action availability | Carriers gate offered controls (`src/editor/SelectionToolbar.tsx:87–99`).                                                                                                               | Every offered action is preserved by save/reopen and public export or names the loss before conversion. No “temporary” style masquerades as saved content.       |
| Numeric/mixed inspector    | Preserve draft, validation and explicit commit/discard; integer scene coordinates (`src/whiteboard/NumberField.tsx:24–118`).                                                            | Empty/mixed is not zero; invalid text survives blur/navigation as held draft; scrub cancellation restores original values; keyboard arrows use the same command. |
| Resource/content face      | Explicit loading/missing/unavailable/failure, with existing state styling (`src/sheet/useSheetWorkbook.ts:11–118`, `src/styles/surface-system.css:88–100`).                             | Failed read is not an empty state; retries do not flash stale successful content; count/size unknowns are words.                                                 |
| Pointer overlay            | Preview is passive; gesture owns cancellation and must release listeners/capture (`src/whiteboard/NumberField.tsx:44–83`, `keys.ts:137–168`).                                           | Escape, pointercancel, unmount and an external edit end the preview once; no global key suppression survives the gesture.                                        |
| Selection/history          | Commands return typed refusal and retained source/history remain authoritative (`src/engine/scene/model.ts:154–169`, `history.ts:74–147`).                                              | One user gesture is one undo step; changed external items are skipped visibly; a removed target does not cause a stale edit to overwrite another item.           |
| Density/theme/typography   | Use Cerebro's tokens/compositions, labelled controls and readable selection, not imported AFFiNE CSS (`src/styles/surface-system.css:1–100`, `src/components/ui/IconButton.tsx:10–19`). | Light/dark, large text, narrow pane and reduced motion keep all actions reachable; canvas overlays cannot occlude the focused field.                             |

## Decision priorities and remaining work

The highest-value candidates are a **carrier-specific clipboard/import loss matrix** (AE22–35), **shared keyboard/gesture regression matrix** (AE49,65,73–82), **explicit resource states** (AE10–15,33,36), and **measurement before rendering complexity** (AE50,70–72). These are improvements to existing owners and controls. They do not require wholesale adoption of BlockSuite.

Separate product decisions would be needed for shared document/canvas blocks, structural mindmaps, presentation frames, nested graphic groups, free-endpoint connectors, arbitrary active embeds, a remote template catalog and live multiplayer. The present file formats explain several deliberate absences. None is approved by this review.

The source assertions actually inspected include typed Markdown shortcuts (`A/integration-test/src/__tests__/main/editor-semantics.spec.ts:185–273`), imported relative-link resolution (`A/affine/all/src/__tests__/adapters/markdown.unit.spec.ts:537–591`), snap throttling/recovery and gesture-only canvas degradation (AE70/72). Current Cerebro assertions read include unknown JSON values/key order and format rejection (`src/engine/scene/jsonCanvas.test.ts:20–116`), no-write-on-open/failed-save retention (`src/whiteboard/useCanvasFile.test.tsx:130–238`) and source/value clipboard separation (`src/sheet/clipboard.test.ts:15–30`). These are evidence of intended behavior, **not passing results from this session**.

The family register closes the inventory and comparison taxonomy; it does **not close every leaf-file semantic review**. Important unresolved depth remains in full block keyboard/action configs, every schema/migration and adapter combination, virtualized edit focus, connector/mindmap algorithms, provider-specific embeds, complete renderer/worker lifecycle, remote collaboration authorization and actual desktop/mobile accessibility/performance. No source review alone proves VoiceOver, WebKit clipboard, pressure hardware, offline recovery, or device-specific memory behavior. These gaps must remain explicit rather than being converted into a claim that thousands of files were fully understood because an inventory or script read them.
