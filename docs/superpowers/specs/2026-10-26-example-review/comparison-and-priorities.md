# Cross-repository comparison and priorities

These are review recommendations, not new milestone assignments or approved implementation scope. Source details, exact paths, failure qualifications and acceptance examples live in the linked repository chapters. The [current baseline](cerebro-baseline.md) corrects stale absence claims before applying any comparison.

The strongest direction is to complete the existing reliability, authority and recovery journeys, then add a small set of distinctive editing and automation capabilities through those owners. The references are valuable both for effective interactions and for concrete failure patterns to avoid. Their cloud services, commercial permissions and CRDT storage do not constitute a drop-in architecture for Cerebro.

## Architecture and infrastructure decisions

| Concern                      | Evidence to study                                                                                                                                                     | Decision for Cerebro                                                                                           | Concrete completion criterion                                                                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| State ownership              | AFFiNE workspace scope/lifetime, document data versus user/device state; [application architecture](affine-application.md#architecture-and-authority-contracts).      | Retain current domain/native/UI separation; document the lifetime and export/recovery category of each state.  | A vault switch cannot leave an old asynchronous completion writing into the new vault.                                      |
| Source authority             | BlockSuite graph hydration, Markdown conversion, separate selected-workspace authority; [editor traces](affine-editor.md#architecture-traces-and-failure-boundaries). | Retain ordinary-vault and selected-workspace contracts; reject implicit migration on read.                     | Opening a future/unsupported document preserves bytes and gives an actionable refusal.                                      |
| Durable save acknowledgement | Retained Cerebro document/scene owners versus logged conversion or upload failures.                                                                                   | Finish existing recovery and native acceptance before adding another writer.                                   | A success label requires acknowledgement of the exact submitted generation; an uncertain write retains recovery.            |
| Local render containment     | AFFiNE route-container boundary; current Cerebro bounded search found no equivalent error boundary.                                                                   | Add a candidate for containing independent pane failures while preserving owners.                              | One crashed pane cannot unmount another pane's pending editor or the assistant.                                             |
| Import receipt and replay    | AFFiNE share-inbox attempt identity; Outline import partial completion; [application traces](affine-application.md), [Outline](outline.md).                           | Adapt a stable attempt/result identity and explicit partial-loss report.                                       | Retrying after a lost acknowledgement returns the prior result or a typed conflict, not duplicate documents.                |
| Export completeness          | BlockSuite database/surface Markdown losses and Outline missing-attachment behavior.                                                                                  | Distinguish portable backup, values export and rendered export.                                                | Missing attachments or omitted blocks are named before the result is described as complete.                                 |
| Backup ownership             | AFFiNE SQLite snapshot mechanisms; Cerebro pinned selected backup and inactive restore.                                                                               | Extend the existing native backup owner.                                                                       | Changed source/opening or replaced destination is refused; restore does not activate a workspace implicitly.                |
| Queue and concurrency bounds | n8n tool batching, child caps, large-result cleanup; [agent rows NAG-04–24](n8n-agent-runtime.md).                                                                    | Keep independent admission, work, output and cleanup bounds.                                                   | A cap on rendered text cannot be mistaken for a cap on events, child count, memory or external effects.                     |
| Cancellation                 | n8n pending-sibling cleanup and shared workspace startup.                                                                                                             | Model stop-requested, stopped and unresolved effects separately.                                               | Failed cleanup remains visible and recoverable after restart.                                                               |
| Retry                        | n8n narrow host classifications, interrupted tool/child state.                                                                                                        | Retry only under the owning action contract; never replay an uncertain external mutation because text stopped. | Lost remote response produces reconciliation, not a new action identity.                                                    |
| Leases                       | n8n memory task renewal allows the callback to continue after lease loss.                                                                                             | Require a write-time version/fence check for durable updates.                                                  | The old owner cannot commit after a new lease holder wins.                                                                  |
| Cleanup and retention        | n8n active checkpoint enumeration and self-healing reconciliation.                                                                                                    | Cleanup requires complete reference information and survives feature disablement.                              | Unavailable/over-cap enumeration postpones deletion rather than guessing which artifacts are unused.                        |
| Skill loading                | n8n registry filtering and active-skill rehydration.                                                                                                                  | Consider explicit skill version/provenance and dependency visibility within existing grants.                   | A changed/removed skill is explained; loading a skill cannot broaden allowed tools.                                         |
| MCP transport                | n8n single-flight initialization, narrow HTTP→SSE fallback and typed result errors.                                                                                   | Improve connection state and transport diagnostics through existing owners.                                    | Discovery failure is unavailable, not an empty catalog; invalid scope/filter config refuses.                                |
| Credentials                  | AFFiNE native provider routes, n8n managed connection lifecycle, Cerebro's newly wired macOS native import bundle, with live acceptance separate.                     | Finish one complete selected-account journey first.                                                            | Account/target/version stay bound through selection, import, approval, dispatch and recovery; secret material stays native. |
| Capability gates             | AFFiNE dev/canary write tools; n8n default-off repair service; Outline paid disabled AI setting.                                                                      | Show available, disabled, unavailable and unsupported distinctly.                                              | A catalog row never promises an effect that the enabled backend cannot perform.                                             |
| Diagnostics                  | Failure, omission and unknown-usage distinctions throughout the chapters.                                                                                             | Prefer bounded local diagnostic records with explicit source identity and redaction.                           | A diagnostic bundle helps reproduce failure without silently collecting credentials or document contents.                   |
| Evaluation                   | n8n expected-tool-name metric and LLM correctness judge.                                                                                                              | Use narrowly named quality metrics alongside deterministic authority/effect checks.                            | Extra unauthorized calls fail the outcome check even if every expected tool name appears.                                   |
| Distributed infrastructure   | AFFiNE server roles and hosted collaboration; Outline server/workers/storage.                                                                                         | Defer adopting cloud queues, multi-user auth, Redis or CRDT bodies without a matching product requirement.     | A local desktop feature has a justified lifecycle without requiring a hosted stack by default.                              |

## UI and design-system comparison

The target is a coherent set of component contracts. Counting buttons, CSS files or Storybook stories does not demonstrate accessibility or consistent composition. Retain Instrument Sans/IBM Plex Mono, shared cortex/synapse roles, both themes and the accepted shell geometry.

| Component/journey family                 | Reference lesson and source chapter                                                                                   | What to standardize                                                                                        | Acceptance examples                                                                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Buttons and icon actions                 | AFFiNE toolbars and BlockSuite compact link menu have different fallback behavior; [editor matrix](affine-editor.md). | Accessible name, disabled reason, pending behavior, keyboard action and fallback route.                    | The compact and full versions expose the same available action or explain why it is unavailable.                                             |
| Menus and contextual tools               | BlockSuite selection tools, view settings and slash/quick-search integration.                                         | Stable target identity, focus restoration, escape behavior and action availability.                        | A menu opened for one document cannot apply after navigation changes its owner.                                                              |
| Dialogs and drawers                      | Outline settings/import/share surfaces and Cerebro page/assistant geometry.                                           | Explicit opener, scoped shortcuts, pending/error retention and meaningful close.                           | A refused save keeps the dialog's data; dismissing a drawer restores the correct opener.                                                     |
| Page titles and metadata                 | AFFiNE rich title/block model versus Cerebro shared body owner.                                                       | Existing title roles, metadata portal and no second writer.                                                | Lazy editor readiness does not remount properties or discard a draft.                                                                        |
| List and grid rows                       | AFFiNE explorer selection, group ordering and Pages counterparts.                                                     | Identity-based selection, range selection, loading/empty/unavailable and consistent secondary actions.     | Reordering/filtering does not move selection to different records; missing rows are reported in bulk actions.                                |
| Database cells                           | BlockSuite type-aware editors, table clipboard and grouping.                                                          | Shared field grammar, drafts, correction status, focus and frozen-column behavior.                         | Rejected input retains the draft and readable status; scrolling does not hide the error permanently.                                         |
| Clipboard                                | BlockSuite cut-before-copy and lossy tab/newline paste contrasts.                                                     | Successful copy before destructive cut; versioned private format plus intentional public format.           | Clipboard denial leaves source intact; quoted newlines/tabs and formula/value distinction survive.                                           |
| Import/export review                     | Outline partial imports and AFFiNE lossy serializers.                                                                 | Per-item outcomes, loss report, retry identity and destination preview.                                    | “Completed” distinguishes created, skipped, failed and omitted; export names missing resources.                                              |
| Resource/attachment cards                | BlockSuite upload/error/oversize states and bounded upload workers.                                                   | Loading, unavailable, removed, uploaded, source ownership and retry.                                       | Removing a card during upload cannot resurrect it; storage failure cannot display an apparently durable attachment.                          |
| Search and source reveal                 | AFFiNE bounded title/body ranking, Outline search, Cerebro exact/relocated source locators.                           | Query identity, result provenance, source freshness and unavailable state.                                 | Stale query completion is ignored; ambiguous source relocation reports changed rather than jumping to a guessed match.                       |
| Conversation transcript                  | n8n tool batches and child suspensions; Cerebro ordered AI elements.                                                  | Ordered text/reasoning/tool events, stable child identity and explicit lifecycle.                          | One sibling's approval wait does not hide another sibling's completed effect.                                                                |
| Child/job cards                          | n8n bounded progress and paired resume/cancel capabilities.                                                           | Queued/running/waiting/failed/cancel-requested/completed, duration and absent usage.                       | A launch receipt is not a completion card; truncated progress is labeled.                                                                    |
| Proposal cards                           | n8n candidate repair, readiness downgrade and review/apply separation.                                                | Frozen input/version, diff/effect summary, exact approval and current applicability.                       | Changed target or missing credentials disables application and explains why.                                                                 |
| Connector rows                           | AFFiNE delegated/native routes and n8n transport/credential states.                                                   | Selected account, capability, connection health, configuration owner and reconnect.                        | “Connected” never means a live approved write is available merely because metadata exists.                                                   |
| Empty/error/pending states               | Explicit counterexamples throughout all chapters.                                                                     | A common state vocabulary with owner-specific recovery actions.                                            | A failed fetch cannot render “No items”; absent cost cannot render $0.                                                                       |
| Accessibility and responsive composition | Editor selection, virtual rows, drawing gestures and modal interactions.                                              | Keyboard alternatives, visible focus, text enlargement, reduced motion, high-contrast and native behavior. | A gesture has a reachable equivalent; zoom/narrow panes preserve content and actions. Source inspection alone does not pass this acceptance. |

## Priority order

| Priority  | Candidate                                                                                                          | Why it comes here                                                             | Boundary before expanding                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| First     | Complete M93 retained-save, native quit and scale acceptance; make failures legible.                               | New capabilities increase the number of concurrent owners and unsaved states. | No reference styling or architecture bypasses unresolved durability.                                 |
| First     | Complete one M96 selected-account read → reviewed write → lost-response recovery journey.                          | This proves the reusable contract needed by agents and workflows.             | More connector logos are not a substitute for an end-to-end effect boundary.                         |
| First     | Complete M95 conversation recovery and honest child lifecycle using the approved containment boundary.             | Users need to know what ran, what waited and what remains unresolved.         | Keep the independent native backend closed until its own acceptance is established.                  |
| First     | Complete M99 backup/restore and consumer authority closure under the selected design.                              | Storage transitions affect every source/effect comparison.                    | No implicit current-vault conversion or second metadata writer.                                      |
| Next      | Refine shared selection, menus, resource states, import/export reporting and source reveal.                        | These produce visible consistency without a new platform.                     | Reuse current DS, command scopes and writers.                                                        |
| Next      | Add provenance and lifecycle for durable artifacts and active skills where existing behavior needs it.             | This makes longer agent work reviewable and recoverable.                      | Retention, scope and version rules precede background cleanup.                                       |
| Next      | Deliver a narrow versioned workflow journey after the action contract.                                             | Workflow UI is valuable only when execution/recovery is dependable.           | Definition/publishing and execution enablement remain separate.                                      |
| Candidate | Math, stronger source editing, daily/journal templates, selected drawing gestures and cross-note sheet references. | These are tangible product choices beyond existing broad feature overlap.     | Each needs a carrier, loss, resource, permission and undo story. No blanket editor replacement.      |
| Candidate | Diagnosis agents that propose version-bound repairs.                                                               | n8n offers a concrete proposal/verification/review pattern.                   | No implicit permission escalation, automatic production application or unsupported “verified” label. |
| Defer     | Real-time multiplayer, public publishing, mobile/web parity, broad backend marketplace and always-on hosting.      | Each creates a distinct identity, service, privacy and operational product.   | Decide the product requirement and owner model separately; absence is not automatically a defect.    |

The granular feature breakdowns remain the primary review material. This table deliberately orders reusable contracts and concrete user journeys, rather than treating every reference capability as something Cerebro should copy.
