# Macro reference review — 2026-10-26

This continuation completes the **feature-family accounting**, not a full semantic
audit of every implementation file. Macro is useful chiefly for state ownership,
bounded and revision-aware operations, explicit partial outcomes, and composition
across a broad workspace. Its cloud account, collaboration, mail delivery and
specialized format editors are separate product decisions. None is automatically
missing Cerebro functionality or an accepted milestone.

The supplied snapshot is `docs/examples/macro-main/`. Below, **M/** abbreviates that
prefix, **F/** means `M/apps/web/src/features/`, **S/** means `M/services/`, and
**C/** means `M/crates/`. These are local source references, not upstream or deployed
product claims. Reference files are ignored study material. No application or
reference code changed; no tests, builds, services, provider calls or installations
were run for this review.

## Boundary traces and what they establish

**Word, shared state and durable acknowledgment.** The fresh path is original
DOCX download/cache → sync-existence check → seed/initialize → Loro manager plus
snapshot/WAL → explicit ready/error state → live transport. It establishes a real
collaborative editor ownership path beyond the earlier engine bridge. It does not
prove all Office formatting survives export or that the legacy save API is used
by the modern Word editor. The sync update path separately proves matching grant
and required edit access → bounded import on private fork → dependency/revision
check → persistence port → broadcast/publication → result. The concrete durable
object storage adapter and every socket operation are not fully read here.

**Database edit.** Registered `/ops` and conversion/history routes lead to typed
receipt-oriented services. The planner reads authorized schema, rejects foreign
tables and wrong base versions before materializing writes, then hands one plan
to `CellStore::apply_writes`. The fresh read stops at that port; the comment
promising one SQL transaction is corroborated by service structure but its SQL
implementation was not freshly inspected. On the UI side the fresh row-source
interface explicitly permits retained open records and stale rows with a refresh
error. That is a contract, not a completed HTTP-to-rendered-cell proof.

**AI editing.** Registered Hono worker routes, model-chain request schema,
generated-code execution adapter, operation application and effect reporting are
present. Before/after comparison is an XML node projection. Individual apply
failures can coexist with changed nodes. It would be wrong to describe this as an
all-or-nothing edit transaction or as byte-level canonical equality. Neither CORS
nor a documentToken field establishes successful authorization in every endpoint;
sync's separate authority boundary was actually read. No provider was contacted.

**Mail and media.** Email read/unread controls have explicit pending guards,
optimistic local state, error rollback and cache refetch. Previous/next guards
list identity and active pane across asynchronous pagination. Image adaptation
handles native cookie transport and blob disposal; it does not establish remote
image consent. Video fetches a version-bound signed URL and reports failures.
Transcript timing refuses unknown origins. These are concrete consumer paths;
mail transport, provider mutation retries, media codecs, call recording consent
and the complete sanitization pipeline remain outside this fresh trace.

**Search and operations.** Search-processing dispatch covers multiple source
classes, and per-worker processing bounds concurrency and elapsed futures. The
infrastructure queue declares redrive/retention and alarms; declarations are not
running observability. Exact binding of that queue to every processor and full
end-to-end idempotency remain unproven. Deletion source makes a useful negative
case: content-bearing traces and sync copies can fail deletion without failing the
whole worker. Cerebro must keep incomplete cleanup distinct from successful purge.

**Inspected assertions, not test results.**
`S/sync-service/src/domain/document/test.rs:23–69` asserts wrong-document/view-only
refusals, isolated stale-revision rejection and duplicate-delta retry after another
edit. `:222–273` asserts persist-before-broadcast, no notification after failed

repairing every downstream notification. AI effect tests at

## Design-system and architecture assessment

Macro's most useful frontend distinction is **pure core, source/adapter contract,
and composed UI**. The property namespace, database row source, project-description
adapter and agent roster keep these roles recognizable. The project description
retains its session through query refresh and remounts only on project identity or
explicit retry (`F/projects/project-description.tsx:42–65`). Cerebro's engine,
IPC, store and AI-element boundaries already serve the same purpose. Adopt
better-localized contracts where there is concrete duplication; do not replace
React/Zustand or the four IPC adapters because the reference uses Solid/context.

Accessibility evidence is source-level: named dialog title/description, live bulk
rename counts, labeled calendar sharing controls, scoped hotkeys and explicit
focus restoration. It is not a keyboard, screen-reader, color-contrast, touch or
pixel audit. The image block's global Command-C listener
(`F/block-image/component/Block.tsx:15–27`) is specifically not a pattern to copy
into Cerebro's central scoped keymap. Repeated document viewers should not each
install global accelerators. Existing Cerebro layers, Select, typography,
Instrument Sans/IBM Plex Mono and cortex/synapse tokens remain the design owners.

Macro's cloud service topology reflects multi-tenant sharing, hosted credentials,
mail/calendar transport, CRDT sockets, object storage and managed indexing. It is
not an incremental architecture recommendation for a local files-first app.
Current selected SQLite authority is already an explicit exception with a paired
body writer; runtime.db is not a license to move ordinary vault content or
epistemic history into another service. Use the reference to ask where ownership,
revision, resource bounds and recovery are explicit, then strengthen the existing
owner rather than add a parallel one.

The remaining registers preserve all feature families and broad backend families.
“Adapt” refers to the matrix's bounded behavior; “defer” means a separate product
or unproven path, not a finding that Cerebro is defective.
