# Morrow and ThoughtDesk: source review continuation

Review date: 2026-10-26. Documentation only. Recommendations below are candidates, not accepted milestones. No reference application, native shell, provider, benchmark, or test was run.

Morrow is the stronger reference for readable vault files, conservative external-edit handling, source editing and small connected writing features. ThoughtDesk provides a substantially broader database and academic-workspace interface, including intake forms, row actions, templates, math authoring and shortcut remapping. The useful transfer is usually an interaction or a carefully bounded capability. Neither app supplies an assistant architecture to replace Cerebro's existing one, and neither app's optimistic UI establishes that a write survived a failure or close.

## End-to-end traces and acceptance candidates

### A1. Keep failed work owned through navigation, lock and close

Morrow's `M/src/storage/saveQueue.ts:25–90,116–174` serializes writes, regards in-flight IDs as dirty, requeues failed IDs and retries with backoff. That is useful. Its callers weaken the guarantee: `M/src/storage/session.ts:78–103,298–301` ignores the boolean from `flush()` before lock, protection changes or close; lock then removes keys and in-memory bodies. `M/src/app/App.tsx:80–99` likewise does not branch on a failed flush. In `M/electron/preload.cts:14–18`, the close acknowledgment is sent in `finally`; `M/electron/main.cts:292–301,337–340` also has a five-second force-close path. A retrying queue does not make those close paths safe.

ThoughtDesk clears a pending autosave batch before IPC and only reports an error on rejection (`T/src/lib/autosave.ts:20–49`). `T/src/lib/editor/Editor.svelte:55–65` clears local dirty state and updates its saved-text marker before acknowledgment; teardown calls save (`:160–164`). The row queue similarly clears before a failing send (`T/src/lib/databases.svelte.ts:634–645`). `T/src/App.svelte:160–223` flushes three stores on hide/close, but its close-request callback does not prevent default close. A rejected native transaction may leave disk unchanged, yet the frontend has discarded its retry obligation.

**Decision:** retain C2/C3 and reject both failure patterns. Adapt the visible retry affordance in Morrow's `TopBar.tsx:52–91` only where the existing owner can retry safely. **Acceptance:** inject one body failure, one field failure and an uncertain selected-store acknowledgment; change panes, minimize, request quit and request lock. Dirty text and its exact target remain reachable; no unconditional ready-to-close message, dropped patch or “Saved” label occurs. A second edit during retry saves the latest draft without sending it to a different workspace. Explicit quit-anyway remains distinguishable from a successful flush. This is source-derived acceptance, not a reproduction.

### A2. Encryption must cover every disclosure and every retained plaintext carrier

Morrow's menu offers encryption for ordinary `kind: 'page'` records (`M/src/app/components/pageMenu.ts:66–88`), which includes child pages used as database rows. `setEncrypted` changes the flag while retaining page metadata (`M/src/core/commands.ts:166–188`). `protect` installs a key and schedules changes; `lock` drops bodies and keys but leaves `state.pages` metadata (`M/src/storage/session.ts:78–103`). The repository stores encrypted page payloads and removes history through later operations (`M/src/storage/vaultRepository.ts:233–295,524–560`). This is page protection, not whole-vault or attachment encryption.

Static export initially excludes encrypted pages (`M/src/core/site.ts:35–55`). However, a published database's `databaseHtml` independently asks `rowsOf` for its children and emits title and property values (`:341–355`); `M/src/core/database.ts:116–137` and `tree.ts:126–137` do not exclude encrypted children. **Conditional source result:** if a database contains an encrypted row whose metadata is already in memory after protection/unlock, database export can include that row's title/properties even though the encrypted page itself is excluded. This does not claim decryption of a never-unlocked ciphertext file, nor export of the encrypted row's complete body. It is a mismatched projection filter in the in-memory export path. `publishSite` produces a local ZIP (`M/src/app/operations.ts:438–465`), not a hosted public URL.

The crypto body uses PBKDF2/SHA-256 with 600,000 default iterations and AES-GCM (`M/src/core/crypto.ts:1–136`). The envelope accepts any numeric iteration count at least 100,000 without a finite integer upper bound; derivation is outside the decrypt catch. That is an input-budget/error-state acceptance issue, not a cryptographic certification. `EncryptDialog.tsx:23–30` reports the session result, which is not a durable-write acknowledgment.

**Decision:** defer encrypted pages and publication as independently specified capabilities; reject these incomplete boundaries. Cerebro C1/C2/C5/C11 are relevant authority/privacy/recovery owners, not evidence that Cerebro has the same export bug. **Acceptance:** publish a parent database containing an unlocked encrypted child, then lock it and export again; neither run emits private title, properties, links, filenames or body through any index, row, search or backlink projection. Also test never-unlocked ciphertext, a missing key, failed protect/lock write, history deletion failure, malicious KDF parameters and attachment references. State exactly which bytes remain plaintext and which recovery/backups are excluded.

### A3. “Unused” is a conclusion requiring complete readable reachability

Morrow's cleanup traces from `Dialogs.tsx:320–355` to `operations.ts:591–618`, collecting file IDs from live documents plus history before deletion. `doc.ts:119–126` recognizes image and file-attachment nodes, not every possible carrier such as page covers or canvas file nodes. Locked documents are absent from the readable document map. `vaultRepository.ts:493–519,588–603` can turn a failed history read/list into an empty result. Therefore a locked page, unrecognized reference carrier or unavailable history can make the proposed “unused” set incomplete. This is a conditional false-orphan risk; this review did not delete files or demonstrate a native loss.

ThoughtDesk's native orphan collector is a different pattern: prior whole-file evidence in `T/src-tauri/src/files.rs:98–122` preserves bytes when reference reads fail and only considers old files absent from library/content references. Its startup invocation is fresh evidence at `T/src-tauri/src/main.rs:89–93`. That rule is scoped to app-managed bytes, not arbitrary files a user placed in a Cerebro vault.

**Decision:** retain C11's visible unavailable state; reject cleanup from partial reachability. **Acceptance:** a cover, a canvas file node, an encrypted/locked document, a retained recovery copy and a temporarily unreadable history each protect referenced bytes. Unknown carriers or a failed scan yield “cannot establish unused,” never an empty reference set. Preview candidate deletions and separate app-owned temporary bytes from user-owned files.

### A4. Source preservation and import must survive unknown content and partial failure

Morrow's `pageFile.ts:17–80,110–130` preserves raw frontmatter and can avoid rewriting unchanged metadata. `load.ts:87–105,232–349` isolates unreadable/invalid pages and retains protected identities. Its Markdown converter preserves unrecognized HTML as `rawBlock` (`parse.ts:259–321`), while known tables, callouts, math, wikilinks, columns and media have explicit transformations. This is not universal losslessness: `serialize.ts:133–137` falls back to descendants for unknown structured nodes; unsupported atoms/attributes can disappear. `markdownToDoc` silently slices above its character limit (`parse.ts:155–157`), and the loader's differently named byte limit also compares JavaScript string length. `markdownToPage` separates a leading H1 (`:323–339`) and `pageToMarkdown` writes a heading (`serialize.ts:43–47`); Cerebro deliberately retains C4's single body/title writer.

The Notion/Markdown/CSV importer infers folders and database rows, skips some entries and reports the 1,000-row cap (`M/src/core/importer.ts:50–154`), but strips initial property-looking paragraphs (`:291–301`). `operations.ts:469–491` decompresses a ZIP before checking expanded entries; compressed input size is not an expansion budget. Attachments are put before page insertion (`:494–546`), so failure can leave a partial import. The UI's success follows in-memory insertion, not necessarily every later durable write.

ThoughtDesk's editor treats failed JSON parsing as legacy HTML and can resave it on mount (`T/src/lib/editor/Editor.svelte:42–50,142–145`). `T/src/lib/markdown.ts:50–73,95–156` reduces file blocks to names and links to titles; unknown atom nodes can disappear. `docx.ts:172–224,325–349` likewise flattens some structures and silently omits an image without alt text if loading fails. These are export projections, not backups.

**Decision:** retain C4/C8/C11, adapt explicit source inspection and format-specific loss reports, reject silent coercion or optimistic “imported everything.” **Acceptance:** include unknown nodes/marks, raw HTML, headings before/after other blocks, reference definitions, double/triple backticks, merged table cells, Notion-looking genuine prose, missing assets, malformed JSON, invalid calendar components and zip expansion bombs. Exact unsupported bytes remain recoverable. Preview alone writes nothing; partial results identify every admitted, skipped, preserved and failed item. A restore/export operation never substitutes for a complete backup contract.

### A5. Forms are a concrete new view, with false distinct from missing

ThoughtDesk registers `form` beside seven other view types (`T/src/lib/db/DatabaseView.svelte:146–156,412–429`), renders configurable fields (`FormView.svelte:1–586`) and submits through `databases.addRow`, which applies a default template then supplied cells (`databases.svelte.ts:866–911`). Failed `addRow` retains the form answers. However, `answered(false)` is false (`FormView.svelte:50`), and only answered values enter submitted cells (`:72`). A template default of `true` can therefore survive a person's explicit untick. Required-checkbox handling is also intentionally exempt at `:60`. The form's invalid path scrolls to an error but does not establish focus transfer (`:77`).

**Decision:** adapt as a distinct candidate on C6, not as a claim that ordinary record editing is absent. **Acceptance:** unset, false, zero, empty text, a deliberately cleared relation and a template default are separate values. Explicit false overrides true; the same admitted create operation carries the intended body/defaults/fields; duplicate submit is bounded; a failed submit keeps answers and focuses a named error; workspace change cannot submit to the replacement workspace. A form is local intake unless separately authorized as a published form.

### A6. Row actions and rules need explicit admission and durable configuration

`T/src/lib/db/ActionsEditor.svelte:1–300` authors set/add/open/url actions; `AutomationsPanel.svelte:35–54` creates a live automation before the user has finished configuring it. `databases.svelte.ts:1113–1173` separates immediate field changes from later actions, bounds automatic recursion for created rows, and gives touched manual fields precedence. That is useful deterministic behavior. It is not one atomic transaction covering changes, new rows and external navigation. Configuration uses separate 400 ms timers (`:1208–1249`) outside the row flush path. UI updates can be optimistic, and later actions run separately. Invalid numeric action text becoming zero (`ActionsEditor.svelte:211`) must not become a generalized coercion rule.

**Decision:** investigate a narrow command/rule capability through C6/C2/C3/C12; defer implementation scope. It would complement, not replace, existing agents/recipes. **Acceptance:** authoring starts inactive; cancel leaves no active half-rule; Done validates and acknowledges configuration. The close guard owns pending rule edits. Manual edits win deterministically, loops and total generated work are bounded, replay has an idempotency key, and a denied or failed later action has an explicit outcome. Opening an external URL is an independently visible effect. An agent using such a command still passes Cerebro's existing grants and approval path.

### A7. Search and suggestions should preserve selection without laundering failed reads

ThoughtDesk's palette coalesces searches to one in flight plus the latest query (`T/src/lib/components/SearchPalette.svelte:56–91`), combines native page hits with local courses/rows/assignments/events/files/tags (`:131–285`), and uses plain text highlight runs rather than injecting result HTML (`:97–105,357–360`). But it retains prior `hits` while a new query runs, and failure only toasts (`:74–75`); local groups can reflect the new query alongside old page hits. The same component has no separate loading or unavailable panel. Backlinks catches and hides errors (`T/src/lib/ui/Backlinks.svelte:14–25,43–61`).

Morrow's freshly read `SuggestionMenu.tsx:1–169` handles arrows/Ctrl-N/P, Tab/Enter, listbox selection and Escape. Its tree has a richer explicit keyboard path (`Sidebar.tsx:410–461`) than ThoughtDesk's `TreeItem.svelte:152–183`, whose own key handler is Enter and whose chevron/actions are removed from the tab order. This is a comparison of those component bodies; global assistive-technology behavior was not exercised.

**Decision:** adapt coalescing, grouped result descriptions and query-specific selection; retain C9/C10-style scoped navigation and unavailable distinctions. **Acceptance:** query A finishes after B is typed; no A row is presented as a B result. Failure preserves a clearly marked old result or shows unavailable, never “nothing matches.” Move/open beside, IME composition, nested dialog Escape and deleted selection have defined keyboard outcomes. Every tree operation has a keyboard path, not merely a `treeitem` role.

### A8. A component system is more than shared styles

ThoughtDesk has reusable menus, modals, popovers, sheets, tooltips and toasts, but the contracts vary. `Menu.svelte:19–75` handles arrows in a capture listener and closes before firing its action; it maintains visual selection without moving DOM focus to the selected item. `db/Popover.svelte:73–102` implements an innermost Escape stack and treats any `.popover`/`.menu` as an outside-click exception, but does not itself trap or restore focus, and watches resize rather than ancestor scroll. `Modal.svelte:1–85` likewise does not implement a full focus contract. `ui.svelte.ts:173–183` can replace an outstanding confirm resolver. `Tooltip.svelte:45–77` is pointer-triggered and keydown hides it; a tooltip role alone does not make icon-only controls named. Shared motion helpers honor reduced motion (`motion.ts:1–65`), but tooltip CSS has its own animation (`Tooltip.svelte:114–129`).

The number editor's invalid branch toasts then closes (`T/src/lib/db/CellEditor.svelte:101–111`), losing the displayed draft. Its overlay rect is captured once (`:68–69`), so scroll/zoom lifetime needs acceptance. `FileCard.svelte:28–37` has a non-tabbable primary card and hover-only action opacity; `TemplatesPanel.svelte:137` also hides action chrome on non-hover states. Morrow is not uniformly better: its tabs all enter the tab sequence (`TabBar.tsx:1–79`) and sidebar separator has pointer resize without a keyboard handler (`Sidebar.tsx:155–170,356–362`).

**Decision:** retain Cerebro's DS, C7 status, C9 scopes and `src/components/ui/Dialog.tsx:75–160` focus restoration/top-layer Escape/Tab trap. Adapt density and contextual presentation only. **Acceptance:** nested modal→popover→menu closes one layer; cancellation resolves the correct prompt exactly once; invalid edits stay available; moving/scaling an anchor keeps feedback attached or intentionally hides it; focused actions become visible; icon controls have names without relying on tooltips; reduced motion includes direct CSS animations. These are candidate checks, not an accessibility conformance result.

### A9. Academic workflows are an optional domain pack, not Knowledge verification

ThoughtDesk's assignments, courses, weighted grades, repeated class events, notes per occurrence, flashcards and quick capture form a coherent academic domain. Fresh sheet reads reveal important lifetime differences: `AssignmentSheet.svelte:95–109` closes before awaiting create, and close auto-creates a titled draft; `EventSheet.svelte:126–136` does likewise. A failed create has no still-mounted draft in that path. The event sheet serializes first detachment and queues changes (`:79–104`), but clears queued edits when detachment returns no copy. The study sheet records a local history step, awaits `cards.answer`, then advances (`StudySheet.svelte:63–98`); `cards.svelte.ts:88–101` catches a failed save yet returns the new review. A completed study session can therefore describe local progress not durably recorded progress. Its global key listener is not scoped to the innermost modal (`StudySheet.svelte:115–151`).

**Decision:** defer a reusable academic starter pack; retain C10's distinct concept verification and C8's explicit user-owned templates. **Acceptance:** create failure retains the assignment/event draft, close semantics are stated, detached occurrence changes survive a failed copy, review failure keeps the card retryable, undo acknowledges restoration, and due counts agree with the session's fresh-card cap. A study grade never writes a human verification stamp or changes evidence/recheck policy. Notes for an occurrence have stable identity across import/update and daylight-saving changes.

### A10. Platform, privacy and sync claims need narrow words

ThoughtDesk's full native registration (`T/src-tauri/src/main.rs:1–168`) contains local data, files, reminders, exports, capture and database/sync hooks, not a model/provider/chat service. `sync.rs:1–12` explicitly calls its hybrid-clock/outbox mechanism groundwork with no server. It is not shipped peer synchronization. Native startup uses one default data directory, with a custom-directory override permitting another instance (`main.rs:24–45`); a second instance against the same custom path is not prevented there. The checked configuration targets Windows NSIS and includes Windows-specific WebView switches (`tauri.conf.json:14–49`); source presence is not a demonstrated macOS/mobile port. Prior `memory.rs` and `pdf.rs` bodies establish Windows-specific implementations and unsupported/no-op branches elsewhere.

Its CSP permits HTTPS images (`tauri.conf.json:30`) and `export-images.ts:11–37` assigns an arbitrary source to a browser image before rasterizing. Local-first storage is therefore not a proof of no network traffic. Morrow has an explicit no-AI product statement (`Dialogs.tsx:313` and prior README) and no AI entry in the fully read action registry, but its Settings wording “never sends anything anywhere” is too broad beside opt-in LAN synchronization. Morrow's sync checks peer vault identity, plans a three-way change, then can skip failed deletes/copies/writes and still return `ok: true` (`M/src/app/sync.ts:30–104`). `SyncSettings.tsx:36–45` can report “up to date” with zero received despite such skips. Its single shared running promise can also answer a second peer request with the first peer's result (`sync.ts:19–24`).

**Decision:** retain C1/C5/C12 boundaries; defer adopting either transport. **Acceptance:** “synced” names the peer and every completed/skipped/conflicted item; partial changes do not return an all-success summary. Separate remote-image loading, remote publication, native file access, notifications and sync permissions. Verify every supported platform independently before claiming parity. Browser mocks do not prove native durability, file identity, close ordering, notifications, print output or encrypted transport.

### A11. Export, backup, history and recovery are four different products

ThoughtDesk's DOCX writer provides editable Word headings/lists/tables, image rasterization and MathML→OMML equations (`T/src/lib/docx.ts:1–465`, prior `math/omml.ts:1–152`). Its loss modes include flattened toggles/links/file cards, heading levels reduced to three, missing image omission, and no general unknown-atom preservation. `zip.ts:27–88` is an in-memory stored ZIP writer; it is not a streaming/bounded archive engine. Export success must include a loss report and memory budget.

Morrow's snapshots (`session.ts:275–285`) keep a current snapshot before a restore, but read failures can look empty as noted above. History cache and protection flags can be updated before their corresponding disk operations complete (`vaultRepository.ts:233–295,493–573`). JSON backup excludes encrypted pages/bodies (`core/portability.ts:40–63`); automatic backup does not imply an encrypted whole-vault recovery system. Attachments, source exports, per-page history and app-data backups have different inclusion policies. C11 already exposes a bounded, opt-in ordinary-body recovery surface with explicit exclusions. Selected backup/native kernel work must be assessed at its actual activation door; no broad backup parity claim is made here.

**Decision:** adapt export affordances and version comparison; retain explicit recovery scope; defer DOCX/publication/encryption expansion. **Acceptance:** restore refuses a changed target and reports unavailable history distinctly; failed history append/clear is retryable; backup inventories list every excluded class. Export of math, table spans, unknown blocks, remote/missing images and very large files yields an explicit loss/size result before a success label. An exported projection is never described as a restorable complete backup.
