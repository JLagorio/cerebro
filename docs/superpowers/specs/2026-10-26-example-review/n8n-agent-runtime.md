# n8n: agent runtime, delegation, memory, skills and workspaces

This review covers the distinct `packages/@n8n/agents` SDK and its native n8n host adapters, beyond the workflow-node catalog reviewed on October 24. It is a source review of the supplied snapshot. Provider calls, sandboxes, reference tests and the n8n application were not executed. SDK support, host wiring, deployment enablement and safe operation are separate claims.

The most useful transfers are explicit child lifecycle states, suspension ownership, bounded result readers, skill-version reconciliation and visible background work. Cerebro should retain its native authority, read-only delegation policy and knowledge verification rules. Neither an in-process child context nor a subdirectory constitutes a proven isolation boundary.

## Current Cerebro baseline

The current source is substantially ahead of the prior audit's native reservation checkpoint. `src-tauri/src/actions/native_delegation_origin.rs:35` now prepares an intent against the original owner, and `:74` reserves a native child. `native_child_claim.rs:77` creates an owned claim with original publication, frozen evidence, deadline and durable lineage checks; `:192` explicitly preserves recovery obligations after a definite commit. These are real implementations.

They remain behind the `native-read-smoke` gate on `native_owner.rs`'s `native_delegation_origin` registration (latest reviewed at 1470–1473). The only consuming backend in `native_child_claim.rs:305` counts a no-effect consumption; `:355` records `BackendUnavailable`. This is not a production child runner or measured process isolation. Existing CLI delegation is separately implemented and bounded by `shared/policy/subagents.v1.json:4`: two concurrent children, eight admissions per session, depth one, foreground, no built-in agent types. `supervised-jobs.v1.json:9` adds the candidate native read-only, awake-only, elapsed-time, input and result limits.

Cerebro already has an explicit answer-to-page path: `src/agent/artifacts.ts:26` saves a frozen answer to a new ordinary page through one create-only batch, with current-vault, content hash, destination, knowledge-path and size checks. A generic artifact preview must not replace those guarantees or imply verified evidence. Existing transcript children, AI elements and conversation rail remain the presentation owners.

## End-to-end traces that matter

### Foreground child with a question

The host delegate tool chooses a source and forwards parent identity/budget/sandbox context. The runner owns the child implementation. SDK delegation emits started/progress/completed events tied to a parent tool call. A suspended child returns a continuation; the parent tool suspends with its schema. On resume, continuation parsing checks selected child/task path; the host validates the resumed source and uses a specific resume runner. Cancel is configured as a paired capability. Reference: CLI `sub-agents/delegate-sub-agent-tool.ts:45–169`; SDK `delegate-sub-agent-runner.ts:90–364`.

The generic helper is not an authority issuer. It cannot establish that a durable ID still represents an authorized parent or that a background child is contained. Cerebro's original-owner/frozen-grant checks are stronger requirements and remain prerequisites to opening its backend.

### Tool batch during approval and cancellation

Inputs normalize first; provider-executed calls are counted without being repeated. Ordinary and foreground-delegation calls form different batches. Every call in a batch reaches the runner concurrently, so some siblings may finish before another suspends. Later batches become unexecuted pending items. Resume distinguishes suspended versus never-started work; a cancelled resumed call cancels its pending siblings, preserving ones whose cleanup failed. Abort takes a separate best-effort cleanup path. Reference: `runtime/tools/tool-call-executor.ts:129–515` and `tool-call-runner.ts:96–238`.

This supplies concrete acceptance cases for a multi-tool UI: waiting is not running; canceling one intent is not proof that prior siblings were undone; failed cleanup remains uncertain. The older workflow AgentTool examined in the first audit is a different implementation and must not be generalized to this SDK.

### Large tool result and its next session

The runner protects configured untrusted results before model-size handling. Large text is serialized and either stored under hashed run/tool names or visibly truncated. A read instruction points to the complete result. The host later enumerates active sandbox checkpoints before cleanup; enumeration overflow skips deletion. The SDK cleanup caps work and can silently leave stale files on a read/stat error. Reference: `runtime/tools/untrusted-tool-output.ts`, `runtime/tools/tool-result-guard.ts`, `workspace/tool-result-storage.ts`, CLI `agent-workspace.service.ts:103`.

For Cerebro, adopt the bounded read/provenance contract, not a globally accessible path. Distinguish expired artifact, denied artifact and storage unavailable. Retaining a transcript reference does not automatically retain its bytes; backup and deletion must include explicit reference closure.

### Skill activation through compaction

The current registered source loads a skill. Its active ID and activating tool-call stamp are persisted. On later runs the source is reloaded, old result bodies collapse, and current instructions attach to a usable visible tool result. If compaction or failure removes that anchor, a recovery block carries the skill. Serialized saves prevent an older activation snapshot overwriting a newer set. Reference: `runtime/skills/active-skills.ts:50–295`.

This is strong continuity behavior, but deliberately adopts current skill versions. A reproducible task needs the exact chosen version and explicit policy about updates. Cache behavior is a performance consideration after authority, provenance and comprehensibility.

Cerebro's current closed native child backend, existing CLI research delegation and governed proposal channel are distinct states; none should be renamed “self-healing” merely because this reference contains such a service.

## Concrete acceptance candidates

1. A child emits one oversized text delta: truncate at the shared progress bound, retain its final-result availability separately, and show that progress is incomplete.
2. A child fails before producing text: render failed, preserve absent usage, and never substitute its input prompt as a claimed answer. The generic result helper's text extraction does not independently check message role; the inspected inline producer uses response deltas. Other producers require their own contract review before reporting a bug.
3. Two sibling calls begin, one later asks for approval: show the completed sibling honestly; declining the question must not claim the first effect was undone.
4. A resumed question targets a different configured child, edited tool input, stale grant or expired parent: refuse without minting a replacement owner.
5. A child stops while a suspension cleanup request fails: retain an unresolved/needs-reconciliation state, not a fabricated terminal success.
6. A model/tool stream is quiet, a provider sends keepalives, and a tool may already have acted: do not auto-replay the whole turn.
7. Artifact storage fails: distinguish explicit truncation from complete evidence; disable a “read full” link that has no committed bytes.
8. Checkpoint enumeration is unavailable or over cap: do not garbage-collect potentially referenced artifacts.
9. A shell command changes directory or follows a link: prove the actual backend containment; a relative-path wrapper is insufficient evidence.
10. Memory lease renewal loses ownership while inference continues: the eventual write must fail its version/fence check.
11. A skill is removed, renamed or changed between turns: rehydrate only currently allowed content and explain which version governed any previously reviewed action.
12. A skill dependency is unavailable or forbidden: loading the skill must not widen the grant to satisfy it.
13. A tool-presence eval sees all expected names plus an unauthorized write: the presence metric may pass, but safety/outcome evaluation must fail.
14. A child has unknown cost and another crosses the known cap concurrently: show unknown accounting and the applicable admission limit; do not promise a hard budget guarantee from post-call totals.

## Review limits and disposition

Fresh source reads are recorded by path, SHA-256 and inspected ranges in the local `root/read-ledger.jsonl`. This chapter does not certify every SDK file or every host path. Vector-store providers, full observation/episodic algorithms, the complete checkpoint store, sandbox provider internals, background job runner and evaluation UI need their own end-to-end/runtime verification before implementation choices rely on them. The whole-repository body census remains a mechanical screening layer, not semantic proof.

Use these mechanisms to refine existing M95/M96/M97 work and to consider a small number of later capabilities. A new agent framework, cloud sandbox, vector database or model billing stack is not justified merely by finding it in n8n.
