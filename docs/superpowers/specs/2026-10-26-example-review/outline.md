# Outline: feature-family comparison and continuation review

Review date: 2026-10-26. Reference: `docs/examples/outline-main/`. This is a
documentation-only comparison, not an implementation plan or approval to add features.
The strongest transfers are explicit completion and loss reports, history comparisons,
small editor interaction improvements, reusable action presentation, and failure isolation.
Outline's hosted team authority, database/Yjs document truth, public sharing, automatic
notifications and remote content fetching do not replace Cerebro's workspace authority.
Cerebro now has both legacy vault paths and the selected workspace's native editor,
canonical metadata SQLite store and paired body writer; this comparison preserves that
separation rather than claiming all current state is file-only.

## Decisions that should survive implementation planning

1. Preserve Cerebro's current save/recovery owner, selected native metadata/body pairing,
   legacy source truth, guarded write receipts, shared policy tables, readable-source
   bounds and single-person authority. No source comparison justifies replacing those
   contracts with Outline's hosted database/Yjs/cache model.
2. Treat completion as a set of facts: conversion, item write, attachment acquisition,
   export archive, delivery and notification can succeed or fail independently. The observed
   empty-export-object, skipped-import-output, logged-enqueue and swallowed-storage cases
   are explicit reasons to require a loss/outcome report, not desirable behavior to copy.
3. Highest-value incremental candidates are bounded history endpoints, optional-surface
   error boundaries that preserve drafts, action-state presentation shared with the existing
   catalog, source-aware import/export reports, and measured lazy serialization. Each still
   needs a scoped proposal and the acceptance examples above.
4. Rich previews, public shares, team authentication, collaborative editing, presentation,
   outbound webhook/Slack and marketplace widgets are separate product choices. Their
   source presence does not create a Cerebro requirement.
5. The review establishes implementation only where a body was traced. Disabled AI
   answers, enterprise-only wiring, third-party widgets, provider credentials and every
   unexecuted test remain explicitly gated or unverified.
