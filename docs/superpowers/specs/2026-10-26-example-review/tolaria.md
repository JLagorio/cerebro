# Tolaria — completed family comparison, with bounded source depth

Reviewed 2026-10-26 against the local `docs/examples/tolaria-main` snapshot. This is documentation and source review only. No reference or Cerebro application tests, builds, services, provider calls, installs, credentials, or native interactions were run. Recommendations below are candidates, not accepted milestones or permission to enable a backend.

Tolaria is a particularly useful reference because it shares React, Tauri, BlockNote and IronCalc with Cerebro. Its strongest contributions are precise interaction and failure cases: source/rich handoff, composition, selection, sheet focus, dependency resolution, native windows, and backend-specific capability differences. It does not justify replacing Cerebro's retained document owners, guarded native writers, portable canvas format, shared policy, or conversation/run authority.

## Closed source traces and failure reasoning

1. **Paste to carried page:** `Editor.tsx:284–312` registers paste and selection extensions; `richEditorPaste.ts:88–100,174–189` chooses clipboard route and starts remote import; `remoteImagePaste.ts:124–141` returns partial counts; completion updates matching image blocks only after the page-path check. Selection clipboard separately prioritizes JSON→BlockNote HTML→HTML→Markdown (`richEditorBlockSelectionClipboard.ts:94–104`). This closes registration/dispatch/result at source level but leaves native download policy and all block-schema validation outside the read. The adaptation is precise intent and partial-result handling under C1/C2, with CV-61 preserved.
2. **Sheet dependency to result:** `useSheetExternalFormulaResolution.ts:191–238` resolves/prefetches entries and subscribes only to dependency paths; `:260–306` gates an asynchronous native result by cancelled flag/signature; worker `sheetExternalFormulaWorker.ts:129–161` passes source/link inputs and degrades to unavailable on exception; `:339–407` selects JS fallback and initial readiness. Input references, display formula and evaluation result are different values. Scope, source version and missing/error semantics must be held by the owner before this is safe cross-note arithmetic.
3. **Canvas input to page source:** `editorSchema.tsx:386–428` passes snapshot props and writes callback results to a block; `TldrawWhiteboard.tsx:567–611` loads or falls to an empty store and debounces user-document publication. `editorContentFlushRegistration.ts:33–55` exposes rich/sheet flush, with no board snapshot callback in that file. A bounded search of `T/src` for `flush.*tldraw`, `tldraw.*flush`, `getSnapshot` and `TldrawWhiteboard` found no additional dedicated tldraw flush route. This does not prove all outer lifecycle behavior; it establishes why Cerebro should keep C3 and demand a close-before-debounce native case rather than assume parity.
4. **MCP request to disk:** websocket verification checks local origin/address, dispatcher selects shared service, service resolves active root, JS `updateNote` canonicalizes target→optional mtime check→temp write/rename→mtime result; append has a different direct append path. These are real checks but not C5 actor/run authority or C2 compare-and-write locking. Atomic rename alone does not authorize a write or prove power-loss durability.
5. **CLI output to cancellation:** shared runtime spawns, optionally writes prompt stdin, registers child, reads stdout, drains stderr, waits, then emits error/Done. Stream registry removes only the matching child pointer; abort kills direct child, and `wait`/abort share mutex. There is no durable recovery claim from these bodies. Pipe pressure and wait/kill ordering are acceptance risks inferred from source, not demonstrated failures.
6. **Session UI to storage:** updates replace one entry in a whole map→publish/broadcast→250ms native write; errors are ignored; native read failure becomes `{}`; initial hydration ignores itself if local version changed. Restart clears working flags rather than reconciling native jobs. This is a view snapshot store, not a durable execution engine or proof that effects stopped.
7. **Telemetry setting to transport:** loaded settings with explicit true and ID initialize frontend SDK; analytics import is awaited then initialized, native Sentry independently rereads settings and requires embedded DSN. Actual gates exist. Redaction breadth and revocation during import remain separate, unproven properties; reproducing known failures with bounded local diagnostics is the transferable part.
