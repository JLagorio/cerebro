# Activepieces and n8n: workflows, connectors and operations

Review date: 2026-10-26. This is a source review of the supplied checkouts, not a claim about today's upstream releases or deployed services. Recommendations are candidates for Cerebro; they do not authorize implementation. The n8n instance-AI agent SDK, self-healing and agent runtime have a separate [review](n8n-agent-runtime.md).

The strongest transfers are explicit save/publication states, typed mapping diagnostics, honest connection availability, bounded recovery and dependency lifecycle reporting. The weakest transfers are a general script expression language, downloading executable connector packages into the desktop app, server-style tenancy, and queue acknowledgements presented as proof of completed work. Cerebro already owns durable agent admission and dispatch; it should build workflow execution beside those owners rather than replacing them with a cloud workflow stack.

## Evidence and current-state correction

This continuation inspected **67 distinct files / 9,774 unique lines**: Activepieces 27 files (15 full, 12 targeted; 3,843 lines), n8n 24 (7 full, 17 targeted; 3,669 lines), current Cerebro 16 (8 full, 8 targeted; 2,262 lines). “Full” means every line was actually displayed and analyzed, including unions of ranges at the same hash. Targeted files retain unreviewed bodies. Exact ranges, hashes, a readable coverage register and anchor validation are local in `/tmp/cerebro-example-review-2026-10-26/workflows/`; they are not fresh-checkout dependencies.

The October 24 expanded inventory and beyond-M99 workflow packet remain prior evidence. The latter recorded 52 decisions and nine traces across Cerebro, Activepieces, n8n and Macro; its Macro work is outside this chapter. Rows marked **P** below rely on that earlier body review, not a claim of new inspection. **F** means fresh body evidence, **R** registration/declaration evidence, and **I** structural inventory only. An F entry is bounded to its cited ranges, not the entire family.

The complete mechanical census covered Activepieces' 31,127 paths / 30,880 text bodies and n8n's 32,113 paths / 30,263 text bodies, with no reference-body hash changes against the prior inventory. Those machine reads are **not semantic review**. The chapter accounts for the product/module families, but does not certify every adapter, credential type, enterprise feature or line of these large repositories.

Current Cerebro differs from the prior packet in important ways:

- The [workflow definition owner][c-def] now implements bounded graph validation, semantic hashes, schema digests and typed literal/input/output/object/array mappings. Outputs must precede their consumer and normally dominate it; `exists` may inspect an earlier optional output. This is implemented validation, not a running workflow service.
- [Workflow module wiring][c-wf] still states that the definition boundary precedes native service wiring. The concurrently added [file-store module][c-files] advanced during this review and was reread fully: it now implements Unix directory/file identity checks, locked draft etags, immutable version installation, revision-checked publication pointers and `CommitUncertain` after the rename boundary (60–370). Non-Unix opening refuses as unsupported. These are substantive persistence bodies, not an activated workflow service or executed acceptance proof. No workflow invocation was found in the bounded `src/lib/ipc.ts`, `src/engine/destinations.ts`, `src-tauri/src/lib.rs` search at review time.
- Native managed-connection, acquisition poll/cancel, action-catalog and definition commands are [registered][c-commands]. Late root reconciliation found that the ordinary acquisition entry now selects macOS [NativeImport][c-acquire] (Unsupported elsewhere), and [native secret adapters][c-connections] are included by macOS build conditions. `actions/native_credential_bundle.rs:32–47` wires native gh, authenticated identity and the platform secret store. The earlier unavailable branch is now smoke-only. Action service/approval/recovery modules remain [test gated][c-actions]. A command contract, fixed native harness, installed account, successful credential use and enabled external action are separate facts.
- [The compiled action catalog][c-catalog] explicitly provides definitions only, without provider discovery, account grants or an executor. Existing [CLI connector configuration][c-connector] and [Settings][c-settings] are a different system: vault-local MCP entries, machine-local exact-spec approvals, CLI-owned sign-in and observed run status. Do not call managed native accounts a replacement already shipped.

## Runtime traces and failure distinctions

### Authoring to publication

AP's builder updates the local flow immediately, notifies operation listeners, sets saving, then submits an operation through an ordered/debounced queue. On success it adopts server version/state without blindly replacing newer local changes; on failure the visible owner only logs and halts the queue. The header distinguishes current published version, draft and enabled status. The read-only draft button labels edit versus view based on permission. This trace reaches the API call and frontend state, not the complete server mutation transaction. [AP save][ap-save] (159–259), [queue][ap-queue] (3–27), [status][ap-status] (9–25).

n8n's save path checks branch-read-only state, serializes saves, captures a dirty counter, sends version/checksum and refuses to save a serialized workflow whose ID differs from the active target. It handles HTTP 409 through a visible overwrite choice and does not clear edits made during the request. Its publication UI then independently considers version change, triggers, blocking validation and partial/failed publication. A saved draft, an accepted publication and a successfully registered trigger are therefore different checkpoints. The UI trace does not establish server-wide atomic publish/activation. [N save][n-save] (419–566), [conflict][n-conflict] (219–278), [publish][n-publish] (46–106).

For Cerebro the useful result is a narrow draft/validate/publish/activate state model over immutable bytes, with the existing page frame and inspector. A graph canvas is an optional view of that model. The current native file store now checks draft etags and publication revisions under its lock, preserves immutable version files and names post-rename uncertainty; retain this owner rather than recommending another competing writer. These bodies were read, not run, and do not supply activation authority. [C file store][c-files] (258–343).

### Credential authoring to execution

AP validates the selected piece version and projects, resolves secret references for validation, encrypts the connection value, records account metadata and returns a nonsensitive view. An engine-principal route derives scope from the principal and obtains the connection. Refresh serializes on platform/external ID and rechecks the stored value. The engine distinguishes 404, loading/fetch, expired and optional piece mismatch before handing the value to the piece. The binding flag defaults false, so the documented mechanism is conditional. The ordinary refresh error branch can return old credentials after a non-auth exception; it is not a universal fail-closed or “credentials valid” result. [AP connection][ap-connection] (35–118), [worker][ap-connection-worker] (10–41), [refresh][ap-refresh] (155–267), [resolver][ap-connection-resolver] (8–60), [default][ap-defaults] (64).

n8n's instance broker separates registered credential use, assignment metadata and secret resolution. This is useful authority decomposition, but it is not by itself proof of every caller's authorization. Its OAuth callback resolves a server-held attempt, checks the appropriate identity/browser branches, consumes cached CSRF state, applies PKCE and merges token data so an omitted refresh token is retained. The displayed `get` followed by `delete` is sequential, not visibly atomic; concurrent consume behavior requires independent proof. Browser completion channels are notification mechanisms, while the native/server record must remain truth. [N broker][n-broker] (35–100), [server state][n-oauth-state] (497–656), [token callback][n-oauth-token] (78–156).

Cerebro has two deliberately separate boundaries: existing CLI MCP configuration and new native managed-account metadata/acquisition contracts. Native production acquisition changed during this audit to an owned macOS import bundle; live acquisition and provider effects remain unexecuted acceptance, and the inspected Settings surface still says import is unavailable there. Borrowing AP's token store or n8n's instance credential service wholesale would erase that separation and bypass the existing native ownership boundary.

### Discovery to installed dependency

AP's catalog filters visible pieces/components and exact versions; custom deletion checks actual flow references after a candidate text search. n8n's authenticated controller requires distinct global install/list/uninstall/update scopes. Its lifecycle rejects environment-managed changes, derives a vetted version/checksum from server configuration, rejects banned packages, and calls a serialized installation owner. That owner backs up existing files, downloads, checks node API compatibility before import, loads code, then persists package metadata. Precommit failures restore files/loaders/ledger; after DB commit it treats the new package as authoritative. Peer notification is asynchronous and a failure logs a warning rather than rolling back committed files. [AP metadata][ap-pieces] (34–78), [deletion][ap-piece-delete] (194–246), [N controller][n-package-controller] (13–48), [lifecycle][n-install] (62–94, 134–252), [install][n-install-body] (509–649).

The [rollback assertions][n-install-test] (163–208) inspect real temporary filesystem markers and ledger restoration with mocked download/loader behavior. They were read, not run. They support intended rollback coverage, not successful package installation here. A healthy catalog is not a healthy installed adapter, and a loaded adapter is not a usable account or safe external action.

### Trigger delivery to run admission

AP resolves a flow and version, memoizes the one-shot request stream, answers provider handshakes before checking disabled state, enforces payload size, offloads the payload and awaits queue add before async HTTP 200. The webhook worker then resolves the flow again: missing/disabled work may complete queue processing without a run. It separately captures test samples and executes the real trigger hook; empty output, user failure, internal failure and sandbox timeout have different logs/trigger records. Polling also records failure and tries on a later cycle without claiming a workflow ran. [AP ingress][ap-webhook] (71–176, 208–243), [worker][ap-hook] (31–175), [poll][ap-poll] (20–87).

This exposes three evidence boundaries: transport accepted, trigger evaluated, and workflow run admitted. The 30-second dedupe counter is another independent mechanism; a crash between increment and expiry or a later redelivery is not covered by a universal exactly-once claim. For a desktop app, closed-session observation, sleep catch-up and failed local admission need explicit coverage reporting before internet-facing webhook hosting is even considered. Cerebro's current memory buffer has a cap and drops oldest offers beyond it; durable admitted wakes are a separate table and are not shown being dropped. [AP dedupe][ap-dedupe] (15–48), [C observation][c-runner] (277–355), [C admission][c-wakes] (377–460).

### Wait, child completion and restart

n8n's waiting webhook differentiates opaque resume tokens from HMAC-protected approval query parameters, strips the token before downstream processing, refuses a suspended-at-node-boundary execution and handles already-complete approval links differently from ordinary finished waits. The old tokenless compatibility path is explicit. This is valuable evidence of wait-kind distinctions, not proof every historical wait is authenticated. [N waiting webhook][n-wait-hook] (220–232, 274–359).

Its wait tracker reloads stored workflow/run state, restores acting identity and calls the runner with an expected waiting status. A child completion first patches the exact parent's wait, then claims resume; a patch that did not apply does not run the parent using its own input as if it were a child result. A sweep handles completion before the parent parked and avoids overlapping itself. Missing child rows produce warnings, not fabricated results. The sweep shown does not itself expose a persisted cursor or page budget, so AP's previously reviewed bounded deadline sweep is a better maintenance model for large backlogs. [N wait tracker][n-wait] (145–375); P: AP [deadline sweep][prior-ap-sweep] and [barrier][prior-ap-barrier] in the prior packet.

### Recovery, retention and audit

n8n recovery reconstructs missing per-node task entries from event logs. A “finished” event produces artificial task data; lack of a finish event produces a crashed node. Status claims prevent a recovery detector from overwriting a later state, and stale wait information is cleared. This helps explain incomplete runs but cannot recover real output or classify an external effect with certainty. [N recovery][n-recovery] (154–246).

Retention is another owner: soft-delete selects candidates; hard-delete drains ordered batches, tries rows individually if a batch fails, records failed IDs, yields between batches and honors cancellation/deadline. Its cursor advances past failed rows within the run; later maintenance may revisit them. AP's audit log is separately asynchronous, so an activity viewer cannot promise every completed operation appears merely because `auditLogRepo.save` exists. Cerebro should keep authority/effect identity and causal evidence transactionally durable, with optional diagnostic/history payloads governed by an explicit retention policy. [N pruning][n-prune] (33–105), [task][n-prune-task] (21–40), [AP audit][ap-audit] (15–64).

## UX and design-system adaptation

Use Cerebro's page frame, existing toolbar actions, contextual sidebar, Instrument Sans/IBM Plex Mono and cortex/synapse roles. A workflow page can expose its definition as an ordered, keyboard-accessible step list with a focused mapping inspector and a secondary graph view. The reference canvas, custom select styling and global document shortcuts are not a reason to replace the existing design system. The [C key root][c-keys] already handles IME, nested scopes, parked panes, editor claims and modal ownership. Every future inspector selection uses Cerebro's Select/Dropdown, and run/approval content composes the existing AI Elements through surface adapters.

Make status words describe evidence: draft unsaved, saved, published, activation partial, trigger unavailable, queued, waiting for input, safely suspended, effect unknown, complete with output retained, complete with output purged. Avoid a single green “connected” or “success” icon spanning all of these. Existing [connectorRow][c-row] is a good local model: configuration/approval precedes observed state; a failed read is not an unobserved connector; timestamp belongs only to an observation. Keep detailed secret approval material in Settings rather than expanding it into every run row.

The references suggest concrete accessibility work but do not establish accessible shipped behavior. Acceptance must include keyboard-only step insertion/reordering, label and error association, non-color state text, focus return after dialogs/drawers, a usable narrow inspector without drag gestures, large output virtualization that retains the selected item, and native WKWebView tests. Copying n8n's popup strategy into Tauri is not native acceptance: default-browser handoff, deep-link return, cancellation and stale attempt identity require their own proof. Reduced motion must preserve final geometry and all status transitions. Failure, loading, empty, not-recorded and partial states belong in Cerebro's five-state lab presets before calling a new read surface complete.

## Recommended order and failure-driven acceptance

1. **Retain and finish the native definition/account/effect boundaries already underway.** Confirm the current implementation state separately from this snapshot. No workflow or connector parity claim should precede actual production wiring, native authority, secret isolation and provider outcome proof.
2. **Add the reviewable authoring/diagnostic layer.** WC-01–11: saved versus published state, semantic diff, schema-first mappings, sample provenance and explicit conflict/error recovery. This is useful even before a graph canvas. Test concurrent outside edits, edits during save, incompatible interpreter/schema and unavailable sample reads.
3. **Make connection/dependency state honest.** WC-12–20: compiled definition versus installed capability, exact account binding, observed health and explicit acquisition lifecycle. Test changed connector fingerprints, revoked accounts, stale refresh completion, popup timeout/cancel, one winning concurrent callback and failed status reads. Keep the existing CLI sign-in path distinct.
4. **Make event/wait recovery durable and bounded.** WC-21–30: durable observation/admission identities, wait generation, completion-before-park reconciliation, effect-certainty retry and stop semantics. Crash at each identity/commit boundary; race two windows and stale finalizers; complete a child before/during/after parking; stop an uncooperative effect; sleep over schedules. A user can see what is waiting and why without retrying an effect to make a card reappear.
5. **Add maintenance and safe portability.** WC-31–37: policy revision checks, redaction/completeness, causal audit, byte/row/time retention budgets and disabled allowlisted imports. Fail history storage after real work, fail one deletion among many, revoke access while data is cached, export nested numeric/string/expression secret examples, and ensure parked continuations retain the evidence they require.

Distributed workers, parallel graphs, general code nodes, public forms/webhooks, a connector marketplace, multi-tenant administration and managed cloud AI are deferred product choices. Their infrastructure, permissions and operational burdens are substantial and independent. None is implied by the existence of source or by the integration counts above.
